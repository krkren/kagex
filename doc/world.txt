Title: Kirikiri/KAGEX World Extension Functions

Author: Wamsoft L.P. Tsuyoshi Watanabe



● KAGEX World Extension Functions Overview



By loading `world.ks` as a plugin into KAGEX, you can use the special "World Functions".



In the World Extension, elements that make up the game are considered "Objects,"
and the scripting style involves performing operations on these objects.



Environment : Control of the entire system and camera.
Stage       : A dedicated object for controlling the location and the "Background Image" associated with it.
Event       : A dedicated object for controlling "Event Images" (CGs).
Character   : An object for controlling "Character Images" (standing sprites), voices, etc.
Layer       : An object for controlling "Layer Images" as screen effect materials.



All objects share the following characteristics:



(1) KAG "Attribute" names are considered commands.
(2) KAG "Attribute Values" are considered parameters for those commands.



● Regarding Major Specification Changes



・`hide` type commands have been abolished. Please use `all` type commands + `hide` instead.
・`clear` command has been abolished. Please use `all` type commands + `hide` instead.
・`newchar`/`delchar`, `newlayer`/`dellayer` commands remain but are deprecated.
  Please use `char` / `layer` for creation, and use the `delete` command of the respective object for deletion.



● Installation Method



It is installed automatically by default. If you do not use it,
please set `global.worldEnabled` to `false` in `startup.tjs` or similar.



● Extended Tags



◇ Extension of Basic Processing



KAGEX tag processing is extended as follows:



・The `ENV` tag becomes a command for the "Environment".
・The `STAGE` or `BG` tag becomes a command for the "Stage".
・The `EVENT` or `EV` tag becomes a command for the "Event".
・The `CHAR` tag, combined with the `name` option, becomes a command for a "Character".
・The `LAYER` tag, combined with the `name` option, becomes a command for a "Layer".
・If there is a location specification, time specification, or action specification command matching the tag name,
　it becomes a command for the "Stage".
・If a character matching the tag name exists, it becomes a command for that character.
・If a layer matching the tag name exists, it becomes a command for that layer.
・"Environment" commands matching the tag name function as is.
・Name processing functions are processed in synchronization with character voices.



・The `BGM` tag becomes a command for the "BGM Object".



  ※ Specifications starting with "bgm" are treated as filenames,
　   equivalent to `[BGM play=Name]`.



・The `SE` tag becomes a command for the "SE Object Group".



  ※ If you specify a name starting with "se", it is considered a specification
　   for the SE currently playing with that name.
　   If no SE is playing, it is treated as equivalent to `[SE play=Name]`.



・Release conditions for delayed execution (`delayrun`) are added.



　String specification also reacts to labels within voice files.
　If voice playback does not occur, the string specification forces execution at the beginning.
  Labels within voices function with their original names and also with aliases 
　`vl1`, `vl2`, `vl3`... in order of appearance.
  Additionally, the virtual label `vlstop` is processed when the voice ends.



◇ Automatic Flag Processing



・When an image starting with "EV" is drawn on the Event or Stage,
　a value "cg_Name" is automatically registered in `sflags`.



・When BGM is played using the `BGM` tag,
　a value "bgm_Name" is automatically registered in `sflags`.



・When a character voice is played, a flag "voice_VoiceDefinitionName"
　is automatically registered in `sflags`.





・When an image is drawn on a layer,
　a value "cg_Name" is automatically registered in `sflags`.



・When a tile image is drawn on a layer,
　a value "tile_Name" is automatically registered in `sflags`.



・When a GFX type effect is displayed on a layer,
  a value "autoflagDefinitionName_Name" is automatically registered in `sflags`.



◇ Command Extensions



◆ begintrans / endtrans



Executes a transition for the entire screen.



・When `begintrans` is executed, the content of the front screen is copied to the back screen.
・From this point until the `endtrans` command is executed, all drawing for environment-related objects
　is performed on the back screen.
・When `endtrans` is executed, a transition for the entire screen is executed with the specified parameters.



Attributes of begintrans
    trans   Transition name specification (*Details described later)
    fade    Fade specification shortcut (*Details described later)
	nosync	Executes the global transition asynchronously



 ※ `ltbegin`/`ltend` are adjusted to function similarly.



◆ msgoff



Erases the message window.



Attributes
    trans   Transition name specification
    fade    Fade specification
    nofade  Suppress automatic fade



If neither `trans` nor `fade` is specified,
standard fade processing using opacity is performed instead of back/front screen transition.
※ The fade time in this case can be specified with `kag.messageeFadeTime`.



◆ msgon



Displays the message window.



Attributes
    trans   Transition name specification
    fade    Fade specification



Like `msgoff`, if neither `trans` nor `fade` is specified, standard fade processing is used.



◆ layer



Functions as a command for layer objects.
Can be used when you want to specify a layer name as a parameter in a macro, etc.
If a non-existent layer is specified, it is automatically created.



Attributes
    name    The identifier name of the layer.



◆ char



Functions as a command for environment character objects.
Can be used when you want to specify a character name as a parameter in a macro, etc.
If a non-existent name is specified, it is automatically created.



Attributes
    name        Specifies the character name.
    initname    Initialization name.



◆ allse



Executes the same command for all SEs.



◆ showvoiceinfo



◆ twait or *



Waits for a time from the start of the message display or for a label within a voice.
Basically used in combination with `delayrun` specification.



Attributes
	name	Voice label specification
	time	Wait time specification



If attributes are unspecified, it waits for automatic label specifications `vl1`, `vl2`, `vl3`, etc.,
in the order they appear in the text.



Example: Just insert `[*]` at the timing where the label appears in the text.



[Akari Surprise]
[Akari Startled delayrun=vl1]
[Akari Cry delayrun=vl2]
【Akari】Eh, [*] wha, [*] no way~

◇ All-type Commands



When you want to process image-type objects in a batch, you can use descriptions starting with `all~`.
These commands basically mean the same as listing the same command one by one for objects
displayed at that time.
In other words, if transitions or similar are synchronized, they are executed one by one in order.
If you want to make them all operate simultaneously:



a. Add `nosync` specification to make them all operate asynchronously.
b. Add `all` specification to perform a global transition.



Please do one of the above.



※ Default values when these are unspecified can be defined in `envinit.tjs`.
allnosync : Default is considered `nosync` specification.
allall    : Default is considered `all` specification.



Common Attributes
	poscond Limit the display position if the target is a character (specify the same as pos specification).
	vcond	Limit the display state of the target.
			true: Those currently displayed (Default)
			false: Those hidden
			all: All
	all		Executes while enclosing the whole operation in `begintrans`/`endtrans`.



※ Example
　Discard all hidden layers
  [alllayer delete vcond=false]



◆ allchar	Executes the same command for all displayed characters.
◆ alllayer	Executes the same command for all displayed layers.
◆ allfore	Executes the same command for all displayed characters/layers.
◆ allbase	Executes the same command for the event image/stage.
◆ allimage	Executes the same command for all displayed image objects.



● Omission of Description in World Extension



Various shorthand notations are valid in World Extension.



◇ Omission of Environment Attribute Specification



-------------------------
[stage stage=School]
-------------------------



This is the notation to set the stage to "School".
If the registered name does not conflict with other specifications, it can be omitted as follows:



-------------------------
[stage School]
-------------------------



◇ Omission of Environment Name



If the attribute value does not conflict with other tags, it can be further omitted as follows:



-------------------------
[School]
-------------------------



Since the tag "School" does not exist, it is replaced with a command for the stage
and executed, becoming equivalent to `[stage School]`.



◇ Character Specification



-------------------------
[Minase dress=Uniform pos=Middle]
-------------------------



Since neither the tag "Minase" nor a command for the environment exists,
it is processed as a command for the character "Minase".
※ The character must be registered in `envinit.tjs` in advance.



Layers created with `newlay` behave similarly.



◇ Omission of Character Attributes



-------------------------
[Minase Uniform Middle]
-------------------------



Like the environment, if the name does not overlap with others,
the parameter name specification can be omitted. The same applies to layers.



◇ Character Voice Playback



---------------------------------------------
【Tae/Voice】「Wake up... hey, wake up I said...」
---------------------------------------------



・Plays the default voice for character "Tae" at that point.
・Displays the name as "Voice" in the message window.
・Automatically displays the face column of the message window with "Tae's" current expression + pose.







    voice       Specifies the voice to play next.
　　　           Number:   Specifies the playback numeric counter.
        　　　   String:   Interrupts with a one-time playback.
            　　 ignore:   Ignores playback only once (treated as a string).



　  once        Interrupts for one-time playback using a number specification (treated as a string).
　  incvoice    Increments the numeric counter even when a string is specified.
    noincvoice  Does not increment the numeric counter (stronger specification than incvoice).



    clearvoice  Stops voice playback from the next time (returns to initial state).
    nextvoice   If specified, plays voice simultaneously with the next voice playback of another character.











◇ Writers' Shorthands (since 0.17.0)

Writers often number poses and faces in their scripts. envinit.tjs's "shorthands" turn a word
of a character's tag into a pose and a face:

---------------------------------------------
"shorthands" => [ %[ "pattern" => "^([0-9])([0-9][0-9][a-z]?)$", "pose" => "$1", "face" => "$2" ] ],
...
"ai" => %[ ...
    "poseCodes" => %[ "1" => "standard" ],
    "faceCodes" => %[ "01" => "happy", "02" => "angry", "03" => "sad" ],
---------------------------------------------

so [ai 102] is pose 1 (standard) and face 02 (angry). A word that is no attribute, pose, face or
command of the character is matched against each pattern (a regular expression; a character's
own "shorthands" come first); $1 to $9 take its groups, and the character's poseCodes and
faceCodes turn the result into a pose's and a face's name (without them it's used as it is). A
pose or face the character lacks is left out.

Positions can do more than place a character: in envinit.tjs's "positions", "front" => true
brings the character in front of the others at its level, and "back" => true puts it behind
them. The sample's far and near ([ai far], [ai near]) change the level and the order at once.

◇ Voice Files That Find Their Speaker (since 0.17.0)

Voice scripts are often written from the recording script, by file name:

---------------------------------------------
[vo ai000003]
I'll be right there.
[vo file="ai000004,pip000005"]
Together!
---------------------------------------------

[vo] plays those files on the next line, and works out whose they are from the characters'
voiceFile patterns in envinit.tjs ("ai%s%06d.ogg" is ai's, so ai000003 is ai's line; of two
patterns that fit, the one with more letters of its own): the line is theirs as if it began
with 【ai】 (several speak together; the first one's name shows, and nameAlias names them).
Compiled scenes do the same, and the scene compiler warns about a file no pattern fits.

◇ Voice Specification



If there is a description of 【Name】 at the beginning of the line, the voice is automatically played.



Basic Operation
　・If a number is specified, the voice follows the format and plays,
　　and the numeric counter is incremented.
　・If a string is specified, it plays taking priority over the numeric specification,
　　and the numeric counter is not changed.
　・String specification is valid only once.



◆ KAG Commands



    playvoice   Directly plays the specified voice.
                When specifying a voice name, it does not affect the voice count.
                When unspecified, it operates by referring to the internal count,
                and the count is incremented.
    
    waitvoice   Waits for the currently playing voice to finish.
                If set to `true` (default), cancellation by click is valid.
                If set to `false`, clicks are suppressed.



    stopvoice   Forcibly stops voice playback.



    bvoice      Specifies a voice to be loop-played in the background.
                Stops while other voices of the corresponding character are playing. When that voice stops,
                it resumes and loop plays. Stops if an empty string is specified.
	Auxiliary Parameter
	loop	Specifies looping.



    vol         The next line's voice at this volume, in % (vol=35 for a whisper), for that line
                only; with voice=, or on a tag of its own before the line (since 0.16.0).



    pan         The next line's voice put here, from -100 (left) to 100 (right), for that line
                only, rather than where its speaker stands (since 0.16.0).



Example: Play by specifying voice number
------------------------------------
[Tae voice=1000]
【Tae】Good morning
------------------------------------



Example: Play by specifying voice file
------------------------------------
[Tae voice="tae1000"]
【Tae】Good morning
------------------------------------



Example: Remove voice playback from next time
------------------------------------
[Tae clearvoice]
------------------------------------



Example: Handling a case where one voice is missing
------------------------------------
[Tae voice=1000 once]
【Tae】Good morning
------------------------------------



Example: Handling a case where one voice is replaced
------------------------------------
[Tae voice=1000 once incvoice]
【Tae】Good morning
------------------------------------



Example: Handling a case where silence is inserted (count continues)
------------------------------------
[Tae voice=ignore]
【Tae】......
------------------------------------



Example: Handling a case where voice is removed for one line (discard corresponding count)
------------------------------------
[Tae voice=ignore incvoice]
【Tae】......
------------------------------------



Example: A whispered line, from the right
------------------------------------
[Tae voice=1001 vol=35 pan=60]
【Tae】(whispering) Over here
------------------------------------



・In the environment initialization process, voices for all characters are initialized to "None".
・The actual file name format for number specification is defined in `envinit.tjs`.



※ About Wait Time during Voice Specification



When voice playback occurs,
the wait time at page wait during auto-play changes as follows:



Normal
　Waits for the specified time.
During Voice Playback
　Remaining voice time at the moment the wait started (calculated from voice length) + specified time wait.

Clicking cancels the wait and proceeds to the next conversation.



※ Takes That Say the Hero's Name

A line that says the hero's name can be recorded twice: with the default name, and without the
name. While the hero's names are still the defaults (kag.defaultName and defaultFamily: the
player hasn't named the hero, ● The Hero's Name in kagex.txt), a numbered voice plays the take
whose file name has an N where voiceFile's third %s is ("ai%s%06d%s.ogg": ai000012N.ogg), when
there is one; once the player names the hero, the plain take (ai000012.ogg), which doesn't say
it.

※ Auto Mode After a Voice (since 0.17.0)

In auto mode the World goes on kag.autoVoiceWait ms after the voices end (Config's "Pause After
a Voice"; the trigger env_voice_after), so a reply doesn't come on the heels of the line.

※ Voices That Fade Out When Cut (since 0.16.0)



A voice is cut when its line is clicked past (with KAG's voicecut), by the next voice, or by a
click during [waitvoice]. It then fades out over kag.voiceFadeTime ms (300) instead of stopping
in the middle of a syllable, on a track of its own, so the speaker's next voice starts at once on
the other. The game doesn't wait for the fade: the voice's stop is told as the fade begins (the
waits end, the BGM comes back up, the tags delayed to its end run). Skipping, auto mode and
loading still stop voices at once, and so does kag.voiceFadeOn = false. Both are the player's
(kept in the system variables); the sample's Config offers Stop (voicecut on, no fade), Fade
(voicecut on) and Keep (voicecut off: a voice plays on until the next one, which fades it out),
and the fade's length, on its second page.



※ Voices From Where the Speaker Stands (since 0.16.0)



With "voice3d" => true in envinit.tjs and the player's switch on (kag.voicePlacement), a
character on the stage is heard from where it stands, through the engine's 3D sound as a sound
placed with [se char=] is (● SE Object Functions, positional sound): one on the left a little from the left, one
further back further away, and the voice follows the character while it moves. A character off
the stage, or shown in the face window only, is heard from the middle, and so is every voice on
an engine without 3D sound. A line's pan= puts its voice there instead. The Character demo
(char.ks, "Voices") has Ai on the left and Pip on the right, and a whisper:


    [ai posleft]
    [pip posright]
    [pip voice=4 vol=35]
    【pip】(whispering) Is she always like this?



◇ Face Windows



The speaker's face shows by the message window (since 0.18.0 in the sample; the World could draw
one before, but nothing cut it from a sprite). A message window gets a face box with [position
faceleft= facetop= facewidth= faceheight=] (the sample's [initscene] in macro.ks), and envinit.tjs
names the level faces come from with "faceLevelName" (void: no faces). Then, with no face command
in the scenario:

  - each line's speaker shows their face in their sprite's pose, outfit and expression, but in
    its own colours: the time of day's lighting and the colour effects on the character or the
    scene ([env grayscale], a character's color= and the like) aren't applied to it, nor are
    the layer's zoom, turn or opacity ("faceApplyColor" => true lights it as the sprite is);
    it crossfades from the last speaker's over "faceFadeTime" ms;
  - narration (no name) has none, and neither has a line over an event CG (envinit's
    "faceOverEvent" => true keeps them);
  - a character on the stage (shown, disp BOTH) or in the face window only ([name facewin]: a
    voice on the phone, someone off stage) shows a face; one hidden doesn't;
  - the face goes with the message window, which it's part of, and a save or Back brings it back.

A character's "faceCrop" says which part of its sprite is its face:

    "faceCrop" => %[ "level" => "0", "left" => 90, "top" => 70, "width" => 360, "height" => 360 ],

level is one of envinit's level names; for a character from pictures left, top, width and height
are in that level's picture (Ai's ch_0_*), for a character drawn from layers in its canvas at that
level (Pip's pip_0.txt), and the part fills the face box, keeping its shape. Without faceCrop a
picture character draws its own face picture at faceLevelName (its pose's msgImage, or the image
pattern with LEVEL), and a layered one the face area its layers name (facezoom, facexoff and
faceyoff in charinit.csv). A Live2D or VRM character (since 0.22.0) takes faceCrop without a
level: left, top, width and height in its picture at 100% (the entry's "height" tall, as wide as
its aspect makes it), or fractions of the picture when every value is at most 1. The face is cut
from the picture the model has just drawn (one drawn then when it isn't on the stage), and while
it's the speaker the window is drawn again from each new picture (faceWindowFrameTime, 66 ms), so
its blinks and its mouth show there too. The sample's Vee and Hiyori have one.

    [env facewindow=off]      no faces in this scene, until facewindow=on or the next [env init]
                              (kept in saves and compiled scenes)

Config's Face Window (the faceWindow option, Options.tjs) turns them off for good: off, the face
goes at once; on, it comes with the next speaker. The sample keeps room for the face by giving the
message window a wider left margin (faceWindowMargin() in Override.tjs), and the Character demo's
"Faces" scene shows each case.

◇ Message Window Styles

Since 0.22.0 the message window can take another look for a scene, a flashback or another
character's point of view, and the player can tint each look a colour of their own. A style is
defined once (AfterInit.tjs, template/system/MessageStyles.tjs):

    KAGDefineMessageStyle("normal", %[ frame:"messagewindow", nameframe:"namebox" ]);
    KAGDefineMessageStyle("memory", %[ frame:"messagewindow_memory", nameframe:"namebox_memory",
        label:"Memories' Window" ]);

  frame        the message window's frame image (void: as [position] gave it)
  nameframe    the name box's frame image (void: as it is)
  tint         a colour laid over both frames by default (0xRRGGBB, -1: none); the frames'
               own transparency is kept
  tintOpacity  how strongly (0 to 255; 150)
  label        its name for the player (English, shown through tr()): a style with a label has
               a row on Config, where the player keeps it as drawn or picks a colour

"normal" is the game's own window: give it the frames [position] gives, so a scene can go back to
them. The scenario changes the style with a World command, so a save, Back and a compiled scene
keep it, and [env init] goes back to normal:

    [env msgstyle=memory]     the flashback's window
    [env msgstyle=normal]     (or msgstyle= with nothing) the game's own

The page on the screen takes the new frame at once, and is drawn again in it where its window
records the page (a game with more than one language, or a window that follows the opacity), so
a language switch or [env restore] doesn't bring the old frame back. Behind a global transition
([begintrans] ... [endtrans trans=...], [env restore trans=...]) the back page's window takes it
first and the other one when the pages are exchanged, so the window changes with the scene, in
the same transition (since 0.23.0). KAGMessageStyleLayer says
which message window the styles are for (0: message0). KAGDefineMessageStyleOptions() makes the
Config rows ("msgStyleTint:<style>": As Drawn, or Other… for the colour picker) and returns their
names, for a page's column. The sample's flashback in the Character demo puts a sepia window
between letterbox bars ([memory] and [memoryend] in macro.ks), and Config's third page has a row
for each of its two styles.



◇ Keeping a Scene



A scene can be put away and brought back exactly as it was (since 0.18.0), for a flashback, a
phone screen or a dream:

    [env keep]                    the stage and time, the characters (pose, outfit, face, place,
                                  level), the layers, the camera and the colour corrections
    [begintrans]                  the flashback's changes, drawn behind one transition:
    [pip hide][ai sad][memory]
    [env grayscale=true]
    [endtrans trans=normal]       ... into the memory
    ... the flashback ...
    [env restore trans=normal]    all of it back, while the music and looping sounds play on

With a transition (trans=, fade= or a transition's name in the tag), or inside [begintrans],
[env restore] is one transition from the screen as it is to the scene it brings back: the
flashback stays on the front page, its objects' pictures with it until the transition ends, while
the kept scene is drawn behind it (since 0.23.0; before, the screen went black at once and the
scene faded in from black). Without one it comes back at once.

[env keep=<name>] keeps a named copy, which [env restore=<name>] brings back as often as wanted
until [env drop=<name>]; plain keep and restore are a stack (the last kept comes back first).
With sound=true the copy has the music and sounds too, and restoring it plays them as they were.
The copies are part of the World's state: saves, Back and compiled scenes keep them. The Character
demo's "A Flashback" scene keeps the street, fades into a memory in grey and fades back.



◇ Layouts



Characters can make room for each other (since 0.18.0). envinit.tjs's "layouts" says where one to
four characters stand, left to right, and how long the others take to slide over:

    "layouts" => %[ "places" => [ [0], [-420, 420], [-660, 0, 660], [-780, -260, 260, 780] ],
                    "levels" => [ void, void, void, 0 ],   // optional: a level for each count
                    "time" => 400, "accel" => 0 ],

    [pip join]          Pip comes on at the right end (join=left: the left end; join=middle: the
                        middle), at its place, and everyone already on the stage slides to theirs
    [ai leave]          Ai leaves (as [ai hide]) and the others close the gap
    [env layout]        everyone on the stage to the places for their count
    [env makeroom=0]    those left of xpos 0 move left by half of room=, those right of it right
                        (room: the layout's distance between two)

time= on the tag overrides the layout's time. More than four spread over the four's width.
Characters keep their order (by xpos). These are World tags, so compiled scenes, saves, Back and
Replay get the places as any position. The Character demo's "Making Room" scene has Ai, Pip and a
second Ai join, cut in and leave.



◇ Emotion Function





● Characters Drawn from Layers



A character can be put together from layers each time it's shown, as a PSD is shown with some of
its layers turned on: a body, outfits ("dress"), variations of a pose such as arm positions
("diff") and faces. Its eyes blink by themselves, and its mouth moves with its voice. The sample's
Pip is one (anim.ks; its files are made by tools/assets/make_pip.py).



This is Wamsoft's "exstand" (template/system/KAGEnvCharacterEx.tjs, with psdlayer.tjs), which
world.tjs loads when there is a charinit.csv. A character listed in charinit.csv whose envinit.tjs
entry has no "poses" is drawn from layers; its entry holds the rest:



------------------------------------
"pip" => %[
    "nameAlias" => "Pip",
    "yoffset" => 0,             // its canvas's centre goes to the centre of the screen
    "voiceFile" => "pip%s%06d", // pip000001.ogg ...
    "voiceName" => "voice0"
    ],
------------------------------------



◇ charinit.csv



One line per pose, comma separated (a line starting with # is a comment):



    character,pose,files,xoffset,yoffset[,facezoom,facexoff,faceyoff,emoRev]



    files       Names the pose's files: <files>_info.txt, which says what its outfits,
                diffs and faces are, and its layers, <files>_<level>.txt or a PSD or CLIP
                STUDIO PAINT file, <files>_<level>.psd or .clip (below).
    xoffset     Where the character's anchor is, from the centre of the canvas, at 100%
    yoffset     (right and down are +). The World places the anchor where it places any
                character: xpos from the centre of the screen and yoffset (the character's
                or envinit.tjs's) below it. Pip's entry sets "yoffset" => 0, so the centre of
                its canvas is the centre of the screen, and it's drawn standing 172 pixels
                below that, on the message window.
    facezoom    For the face window (facewin): the face's size in %, and its offset.
    facexoff
    faceyoff
    emoRev      1: emotions show mirrored.



charlevel.csv can move a pose per level: character,pose,x0,y0,x1,y1,... (pixels at each level,
in the order of envinit.tjs's levels; pose * for every pose).



◇ The layers: <files>_<level>.txt



One file per World level, named after the level ("name" in envinit.tjs's levels: the sample's
<files>_1.txt, _0.txt and _2.txt are 60%, 100% and 150%), so each level is drawn at its own size.
A level without one uses the file of the next level after it in the list, or else of the one
before it ("searchSmallLevel" => false in envinit.tjs: never one before), scaled to fit; with none
at all, <files>.txt, scaled by each level's zoom.



It's psdlayer.tjs's text format, tab separated: a header line (starting with #), the canvas
size (four empty columns, then width and height), then a line per layer, the top layer first:



    layer_type  name  left  top  width  height  type  opacity  visible  layer_id  group_layer_id



    layer_type  0: a picture. 2: a group (a PSD's folder).
    left, top   Where the picture goes on the canvas, and its size.
    width
    height
    type        Its blend mode, as psdfile reports it: 13 is normal (drawn as ltAlpha).
    opacity     0 to 255.
    visible     1 (each pose turns its layers on and off itself).
    layer_id    A number; the picture is the image <files>_<level>_<layer_id> (.png, .tlg or
                any format the engine reads), cut to the layer's rectangle.
    group_layer_id  The layer_id of the group the layer is in, if any.



Layers with Background, Origin or Area in their names don't count for the size of the picture
(such as "Emotion Origin", which places emotions). Layers saved in pieces (psdlayer.tjs's split
images, .siz) need the layerExSubImage plugin, which the SDL engines don't have.



◇ The layers in a PSD or CLIP STUDIO PAINT file



A level's layers can also be the file they're drawn in: when there's no <files>_<level>.txt,
<files>_<level>.psd (Photoshop), then <files>_<level>.clip (CLIP STUDIO PAINT), the extension in
lower case (and <files>.psd or .clip without levels). A layer of the file is a layer above, a
folder a group, with the same names (a "/" in one is "_"), so Mouth/Open Mouth is the layer Open
Mouth in the folder Mouth; Background, Origin and Area layers work as above. A layer's picture is
what it draws with its mask, its blend mode and opacity are the file's, and layer_id is its ID
(a PSD layer saved without one is given one, as the psdfile plugin's assignAutoIds gives it).
Adjustment layers aren't used, nor are a PSD's text layers (rasterize them) or empty layers.
Folders hidden in the file are shown all the same (each pose turns its layers on and off itself).



The engine reads the file through the psdfile or clipfile plugin, which only the desktop engines
have, so the web, Android and iOS builds can't: kagex-release splits such a file into the
<files>_<level>.txt and pictures above, which every build reads (tools/release/README.md,
"Photoshop and CLIP STUDIO PAINT files"). The file then stays the artists' to edit, and a
release reads the layers it had when it was built. To see what a build makes of one,
kagex-release --cli split <file> <folder> writes it out; tools/assets/psdwrite.py goes the other
way, writing a layer structure and its pictures as a PSD with folders (psdfile writes PSDs, but
not their folders).



◇ <files>_info.txt



Tab separated; a line starting with # is a comment. A layer is named by its name alone, or by its
group and name (Mouth/Open Mouth); names match exactly, case and spaces included.



    common  <layer>                 Shown in every outfit.
    dress   <dress>  base  <layer>  Shown in that outfit.
    dress   <dress>  diff  <diff>  <layer>
                                    Shown with that diff, in that outfit. Every outfit needs at
                                    least one diff; more lines add layers to it.
    dress   <dress>  diffface  <diff>  <face>
                                    The face the diff starts with.
    face    <face>  base  <layer>   Part of that face (brows, blush ...).
    face    <face>  eye  <group>    The face's eyes: a group of three layers, "Open Eyes",
                                    "Half-closed Eyes" (or "Half-open Eyes") and "Closed Eyes".
                                    Those blink. With blinking off, the group's top layer shows.
    face    <face>  lip  <group>    The face's mouth: "Open Mouth", "Half-open Mouth" (or
                                    "Half-closed Mouth") and "Closed Mouth", and, for mouths by
                                    vowel (below), "Mouth A" ... "Mouth O". With lip-sync off,
                                    the group's top layer shows.
    face    <face>  eyeimage  <layer>
                                    Eyes that don't move (Pip's laugh has them drawn shut).
    face    <face>  lipimage  <layer>
                                    A mouth that doesn't move.
    face    <face>  noeye           No eyes; nolip: no mouth.
    add     <name>  <layer>         An extra layer, shown with add=<name> or <name>.
    rename  dress|diff|face  <new name>  <old name>



Without eye and lip lines, a face's eyes are the group named after its first base layer followed
by "・目", and its mouth "・口". In common, dress and diff lines, a layer name followed by $ and a TJS
expression (Glasses$f.glasses) shows only while the expression is true. The first outfit, its
first diff and the first face are where a character starts.



A face can also be made of parts from groups (brows, eyes and mouth chosen separately):
facegroup <prefix> defines a group of parts, fgname <part> <layer> [eye0|eye1|eye2|lip0|lip1|lip2]
adds a layer to the part whose name starts with that prefix (shown at that eye or mouth level only,
when given), and fgalias <name> <part> <part>... names a set of them. Such a face is given as
part:part:part, one per group, or by a part's or an alias's name, which changes that group only.
lipa, lipi, lipu, lipe and lipo show a layer while the voice says that vowel (mouths by vowel,
below), in place of the part's lip1 and lip2 layers.



◇ Blinking and lip-sync



A face whose eyes are a group of three blinks at random, a frame every eyeFlipTime ms (60). A
face whose mouth is a group of three moves with the character's voice (that of its 【name】
lines): every lipFlipTime ms (120), the mouth opens half above a level of lipSyncHalfLevel
(0.03) and wide above lipSyncOpenLevel (0.12), measured as the RMS of the voice
(WaveSoundBuffer.getSoundLevel). They're global variables in KAGEnvCharacterEyeLip.tjs (the
blinking and lip-sync these characters share with Live2D characters), so Override.tjs can
change them; eyeFlipFreq is the chance that a frame starts a blink.



Mouths by vowel: a mouth group can also have a layer for each vowel, "Mouth A", "Mouth I",
"Mouth U", "Mouth E" and "Mouth O" (or あ, い, う, え and お). While a voice with a lip track
(below) is loud enough to open the mouth, the layer for the vowel it says shows in place of the
half-open or open mouth, so the mouth makes the shapes of the words. A group can have only some
vowels: for one it hasn't, the half-open or open mouth shows as before. It can also have only
vowels and "Closed Mouth": its half-open and open mouth are then the "Mouth A" layer, or the
first vowel it has. lipVowelLayerNames in KAGEnvCharacterEyeLip.tjs holds the names. Pip's plain
face has them (Mouth/Mouth A ...).



Lip tracks: a voice's vowels come from its lip track, a text file beside it with its name and
.lip (ai000001.ogg's is ai000001.lip, which still applies once a release makes it .opus).
kagex-lipsync (tools/lipsync/README.md) makes them for the voices a game picks, from each voice
and the line the scripts give it: it aligns the line's sounds to the voice (PocketSphinx), a
Japanese line's sounds read from its text, kanji included (OpenJTalk). A voice without one opens
and shuts the mouth by its loudness alone, with nothing to prepare. Each line of a track is a
time in ms, a tab and the mouth from then on: a, i, u, e or o, n for the lips closed (m, b, p),
or - for any other sound; then, optionally, a tab and how open it is: 0 closed, 1 half, 2 wide
(without it, 2 for a vowel, 0 for n and 1 for -). # starts a comment:

    # the start of pip000009.lip: "Hi again! ..."
    0	-	0
    130	a	2
    200	i	2
    270	a	2
    ...

While the voice plays, the track moves the mouth, in place of the voice's level. Each
lipFlipTime, the mouth is what the track says halfway through that time, where the level would
be read: a vowel's layer on a face with mouths by vowel (the half-open or open mouth on others)
as open as the mark says, n closed, and - as open as it says, shaped like the vowel the time
holds longest. The track is timed from when the voice starts. lipSyncTracks (false) leaves them
unread. Pip's synthesized line (pip000009) has one, made by kagex-lipsync; its babble has none.



How well kagex-lipsync's tracks do was measured on synthesized lines in four Japanese and four
English voices, whose sounds' times are known, as the share of the time the face shows the mouth
the voice is making: the right vowel 86% (Japanese) and 87% (English) of the time both show a
vowel, against a best of 90% with the mouth changing every lipFlipTime (120 ms).



Without a track, a vowel can come from the engine's WaveSoundBuffer.getVowel instead
(lipEngineVowels = true), but it reads few voices right. It compares the voice's energy around
the first two formants of Japanese vowels as a man says them (a 800 and 1200 Hz, i 300 and 2300,
u 350 and 1200, e 500 and 1900, o 500 and 900), and most of a voice's energy is at its pitch and
its first few harmonics, so it mostly hears the pitch: a woman's voice, around 200 to 250 Hz,
reads as i, a higher one as o (UPSTREAM.md). It found the right vowel 22% of the time on the
Japanese voices above and 39% on the English ones.



◆ KAG Commands



    <dress>     Changes the outfit (also dress=<dress>).
    <diff>      Changes the diff (also diff=<diff>).
    <face>      Changes the face (also face=<face>).
    x<face>     Changes the face with the eyes closed: they close, the face changes, they
                open again (also xface=<face>).
    <animation> Plays an animation from charanim.csv (below).
    add         Shows the extra layer named in an add line, which also works as a command of
                its own (add= with nothing: none).
    addface     Shows a layer over the face (addface= with nothing: none).
    facediff    The diff the face window (facewin) uses.
    noconvdress Uses the outfit's name as given, not through envinit.tjs's dressNameMap.
    eyeopen     Holds the eyes open, no blinking.
    eyeclose    Holds them closed.
    eyeopento   Opens them through the half-closed frame, and waits for that.
    eyecloseto  Closes them the same way, and waits.
    eyeflip     eyeflip=3: blinks three times, waits, and holds them open.
    eyeflipon   Blinks at random again (after any of the above).
    eyeflipoff  No blinking: the eye group's top layer.
    lipopen, lipclose, lipopento, lipcloseto, lipflip, lipflipon, lipflipoff
                The same for the mouth; lipflipon makes it follow the voice again.
    fliptime    With the commands above: the time of each frame, in ms.



Example
------------------------------------
[pip xsurprised voice=3]
【pip】Oh! A new face!
[pip eyecloseto]
[pip beret smile]
------------------------------------



◇ charanim.csv



Animations, in steps: character,animation,command,time. A step runs a command (any of the
above, several separated by spaces: wave smile) and lasts its time in ms; wait just waits; loop
goes back to the step numbered in its time column (from 0). [pip waving] plays one, and waits
for it to end unless it loops. Changing the outfit, diff or face stops it.



------------------------------------
pip,waving,wave,280
pip,waving,rest,280
pip,waving,loop,0
------------------------------------





● Live2D Characters



A character can be a Live2D model, made with Live2D's Cubism Editor. Its poses are motions that
go on, its motions play once, its faces are the model's expressions or values for its
parameters, and it blinks and lip-syncs to its voice as a character drawn from layers does. The
Animated Character demo's Hiyori is one (anim.ks; Live2D Inc.'s sample model, which
tools/assets/make_hiyori.py fetches: Live2D's licence lets no one but Live2D hand out copies of
its sample models' files).



It takes the krkrlive2d plugin (Live2DDevice, Live2DModel, Live2DPlayer), which draws a model
with OpenGL ES into the character's layer (GFX_Live2D.tjs, KAGEnvCharacterLive2D.tjs), and the
plugin takes Live2D's Cubism Core. Live2D's licence lets a game ship the Core inside the game but
not in an engine handed to other developers, so kagex's engines don't have the plugin: a game
builds it with its own copy of the Cubism SDK (Building the plugin, below). Without the plugin,
OpenGL ES or the model's file, a Live2D character draws nothing and the log says why, once.
KAGLive2DCanDraw("hiyori") tells a script whether a model can be drawn (anim.ks says so when it
can't). A model can also play on a layer as it was made, without the World's poses and faces:
l2d on World layers (Layer Functions, below), [image flip=hiyori.l2d] on KAG layers (doc/kagex.txt;
the layer demo, layer.ks, shows Hiyori so).



The character's envinit.tjs entry has "live2d"; the rest is as for any character:



------------------------------------
"hiyori" => %[
    "nameAlias" => "Hiyori",
    "yoffset" => 300,                // her canvas's centre, below the screen's centre
    "voiceFile" => "hiyori%s%06d",
    "voiceName" => "voice0",
    "live2d" => %[
        "model" => "hiyori",             // hiyori.l2d
        "canvas" => [2976, 4175],        // the model's canvas
        "height" => 1650,                // the canvas's height on the screen at 100%
        "poses" => %[ "standard" => "Idle", "still" => ":Hiyori_m03" ],
        "defaultPose" => "standard",
        "motions" => %[ "tap" => "TapBody", "idle5" => "Idle:4", "m03" => ":Hiyori_m03" ],
        "faces" => %[
            "normal" => %[],
            "smile"  => %[ "ParamEyeLSmile" => 1, "ParamEyeRSmile" => 1 ],
            "wink"   => %[ "ParamEyeLOpen" => 0, "ParamEyeRSmile" => 1 ],
            "laugh"  => %[ "ParamEyeLOpen" => 0, "ParamEyeROpen" => 0, "ParamEyeLSmile" => 1, "ParamEyeRSmile" => 1 ],
            "angry"  => "exp_03",        // an expression of the model
            ],
        "defaultFace" => "normal",
        ],
    ],
------------------------------------



    model       The model's file, with or without .l2d: the folder Cubism Editor exports
                (model3.json, the .moc3, the textures, the motions ...) zipped with its contents
                at the top (model3.json not in a folder) and renamed .l2d, as krkrlive2d reads a
                model. The file is named as its model3.json is (Hiyori.model3.json in
                hiyori.l2d; the case doesn't matter): krkrlive2d reads <its name>.model3.json
                from it. Keep the motions in the export's motions folder: krkrlive2d finds a
                motion by its name there.
    canvas      The width and height of the model's canvas (Cubism Editor's Canvas settings),
                for its shape: the picture is drawn that shape, the canvas filling it. Without
                it the picture is square, which cuts a canvas wider than it's tall at the sides.
    height      The canvas's height on the screen at a World level of 100% (the screen's height
                without it). Each level draws the model at its own size (its zoom, or imgzoom),
                up to live2dMaxHeight (2048) pixels tall and enlarged beyond that.
    anchor      [x, y]: the point of the canvas the World places where it places a character,
                from the canvas's centre, at 100% (right and down are +; [0, 0] without it). A
                character is placed xpos from the screen's centre and yoffset below it.
    poses       Names, each for motions that go on while nothing else plays: "<group>" is a
                motion group of model3.json, one of its motions at random and then another;
                "<group>:<n>" its n-th (from 0), looping; "<group>:<name>" or ":<name>" the
                motion named so (motions/<name>.motion3.json), looping.
    defaultPose The pose it starts in.
    motions     Names, each for a motion played once, then the pose's again, given as for
                poses (a group: one of its motions).
    faces       Names, each for an expression of the model (its Name in model3.json), or for
                values of its parameters, by their IDs (ParamCheek) or display names. A
                dictionary can have both, the expression as "expression" => "<name>". The
                value of an eye parameter is how open the eyes are: 1 the model's open eyes, 0
                shut, more than 1 wider where the model goes that far; blinking closes them from
                there. The value of a mouth parameter is how open the mouth is without the
                voice, which opens it further. Values fade into the next face's over
                live2dFaceFade ms (300); an expression fades as the model says.
    defaultFace The face it starts with (none without it).
    eyes        The eye parameters blinking closes (["ParamEyeLOpen", "ParamEyeROpen"]).
    mouth       The mouth parameters the voice opens (["ParamMouthOpenY"]).
    mouthForm   The parameter the voice's vowels shape ("ParamMouthForm").
    vowels      The mouth for each vowel: %[ a:[open, form], ... ], how open (a share of the
                voice's level) and the mouth form added to the face's (live2dVowels: a [1, 0],
                i [0.45, 1], u [0.35, -0.8], e [0.6, 0.6], o [0.8, -0.6]).



◇ How it moves



While the character shows, the model is drawn again every live2dFrameTime ms (33: 30 times a
second), each frame read back from OpenGL into the character's layer, at the size the level
draws it.



The face is the World's, and the motions move the rest. The parameters any of its faces name,
its eyes' and its mouth's hold the face's values (a parameter's default where the face names
none), whatever the motion playing does with them: a model whose idle motions blink, smile and
talk (Hiyori's do) keeps the face the script gives it and its mouth shut while it isn't speaking,
and its head, body and hair go on moving. Every other parameter is the motions'. The plugin adds
a value to a parameter after the main motion, so a copy of the model without OpenGL plays the
same motions, moving on first each frame, and what's added is the face's value less what the
motion sets in that frame. An expression of the model goes on top, as the model says.



Its eyes and mouth go as a character drawn from layers' do (Blinking and lip-sync, above): the
eyes' level (open, half, closed) closes its eye parameters, the mouth's opens its mouth
parameters, each eased over live2dEyeSmooth and live2dMouthSmooth ms (40, 50) so the steps
become movement, and a lip track's vowels shape the mouth form. The model's own blinking is off:
the World blinks it, so the eye commands work as they do for every character.



Its pose and face are kept in a save, and a load starts the pose's motions again. A model is let
go when its character leaves the screen (the plugin deletes its OpenGL objects as it draws the
next frames, or with the window), and read again when it comes back; a model shown by several
characters is read once. While a skip shows nothing, the character keeps its last picture, and
a motion played once doesn't play. There's no face window (facewin) for a model. The settings
are global variables in KAGEnvCharacterLive2D.tjs, which Override.tjs can change:
live2dFrameTime, live2dMaxHeight, live2dMotionFade (how long a motion fades in and out, 500 ms;
0 for a very short fade),
live2dFaceFade, live2dEyeSmooth, live2dMouthSmooth and live2dVowels; and in GFX_Live2D.tjs
live2dFlipY, which turns the picture read back upside down, should an engine read it back the
other way up.

    <motion>    Plays a motion once, then the pose's again (also motion=<motion>). With

◇ Building the plugin



The plugin is wamsoft/krkrlive2d, with the Live2D driver wtnbgo/live2d (krkrz_dev has it,
src/plugins/krkrlive2d, but doesn't build it at engine 2.6.5). kagex builds it for you, and
tools/live2d/setup.py walks you through the steps below (python3 tools/live2d/setup.py):



1. Download the Cubism SDK for Native from Live2D's site
   (https://www.live2d.com/en/sdk/download/native/), agreeing to its licences: its Core is
   under the Live2D Proprietary Software License. The driver wants Core 06.00.0001 or newer.
2. Run, with git, CMake and a C++ compiler there:

       python3 tools/live2d/build.py --sdk <the SDK's zip, or the folder it unzips to>

   It fetches krkrlive2d, the driver, tp_stub and ncbind at the commits kagex is tested with,
   applies kagex's fixes to them (tools/live2d/patches; UPSTREAM.md), builds them with the SDK's
   Core and puts the plugin in plugin/: libkrkrlive2d.so on Linux, libkrkrlive2d.dylib on macOS,
   krkrlive2d.dll on Windows (--arch: the engine's, arm64 or x86_64 on macOS, Win32 or x64 on
   Windows). CI builds and tests it on all three (.github/workflows/live2d.yml). The driver's
   own CMake builds for Windows, Android and iOS, so on Linux and macOS it's built through
   tools/live2d/driver. Android's and iOS's engines have their plugins linked in, so there
   build.py --kit builds it with the engine, by the platform's kit; the web engine has it
   built in, over Live2D's Web Core, which the game adds (tools/live2d/README.md).
3. The framework links plugin/krkrlive2d.dll (the engine's name for the plugin on every
   platform) the first time a Live2D character is drawn.
4. Put each model's .l2d in the game's data, where its scripts find it (fgimage/, say).
5. For a release, put each platform's plugin in plugins/<platform>/ next to data/ (build.py
   --out plugins/linux, plugins/windows or plugins/macos): kagex-release copies a game's own
   plugins from there into that platform's packages (tools/release/README.md, "Your own
   plugins").



Releasing a game with it: Live2D's Publication License (its "Cubism SDK Release License") is for
a business with yearly sales of 10 million yen or more; individuals and smaller businesses
release without one, but check Live2D's terms as they stand; an "Expandable Application" (one
that can show any number of models, as an avatar or streaming app does) needs Live2D's approval
whoever makes it. The Core goes out inside the game only: the plugin goes into the game's
packages, never into anything handed to other developers, and the game's terms for its players
protect the Core as the licence says (its section 5.2.2).
A model is yours or one whose licence lets you ship it: Live2D's sample models, Hiyori among
them, are under its Free Material License, which lets individuals and small businesses use them
in their works, a game shipping them inside it, with "This content uses sample data owned and
copyrighted by Live2D Inc." shown; no one may hand out the model files themselves, as material.


● VRM Characters



A character can be a VRM avatar: a 3D model in the format VRoid Studio and other tools export
(.vrm, VRM 0.x or 1.0). Its poses are VRM animations (.vrma) that go on, its motions VRM
animations played once, its faces weights for its expressions, and it blinks and lip-syncs to its
voice as a character drawn from layers does. The Animated Character demo's Vee is one (anim.ks):
the sample's own avatar, built from shapes by tools/assets/make_vrm.py, which also makes her
VRM animations and the layer demo's glTF star.



It takes the krkrthreepp plugin (threepp, a C++ port of three.js, with VRM), which draws the
avatar with OpenGL ES into the character's layer (GFX_Three.tjs, KAGEnvCharacterVRM.tjs). Every
engine has it: Windows, Linux, macOS, the web, Android and iOS. Without the plugin, OpenGL ES or the model's file, a VRM character draws nothing
and the log says why, once. KAGVRMCanDraw("vee") tells a script whether an avatar can be drawn
(anim.ks says so when it can't). An avatar can also play on a layer, without the World's poses
and faces: 3d on World layers (Layer Functions, below), [image flip=vee.vrm] on KAG layers
(doc/kagex.txt; the layer demo, layer.ks, shows Vee so).



The character's envinit.tjs entry has "vrm"; the rest is as for any character:



------------------------------------
"vee" => %[
    "nameAlias" => "Vee",
    "yoffset" => 190,                // her picture's centre, below the screen's centre
    "voiceFile" => "vee%s%06d",
    "voiceName" => "voice0",
    "vrm" => %[
        "model" => "vee",                // vee.vrm
        "height" => 1340,                // the picture's height on the screen at 100%
        "aspect" => 0.62,                // its width for its height
        "frame" => [-0.03, 1.47],        // what it shows of her, bottom to top (metres)
        "poses" => %[ "standard" => "vee_idle", "think" => "vee_think" ],
        "defaultPose" => "standard",
        "motions" => %[ "wave" => "vee_wave", "nod" => "vee_nod" ],
        "faces" => %[
            "normal" => %[],
            "smile"  => %[ "happy" => 0.45 ],
            "laugh"  => %[ "happy" => 1 ],
            "blush"  => %[ "relaxed" => 0.5, "blush" => 1 ],   // blush: one of her own
            "sad"    => "sad",           // an expression at 1
            ],
        "defaultFace" => "normal",
        ],
    ],
------------------------------------



    model       The avatar's file, with or without .vrm.
    height      The picture's height on the screen at a World level of 100% (the screen's
                height without it). Each level draws the avatar at its own size (its zoom, or
                imgzoom), up to vrmMaxHeight (2048) pixels tall and enlarged beyond that.
    aspect      The picture's width for its height (0.6 without it).
    frame       [bottom, top]: what the picture shows of the avatar, in metres from the ground:
                a camera in front of it, far enough back to fit that much, fills the picture's
                height with it (from its feet to 0.3 above its head bone without it, where a
                VRoid's head ends; an avatar's hair can reach further).
    fov         The camera's field of view in degrees (vrmFov, 20: from far, as a picture is
                drawn).
    angle       The avatar's turn about its upright axis, in degrees (it faces the camera
                without it).
    look        Whether its eyes look at the camera (where it has eyes that turn). Default:
                true.
    anchor      [x, y]: the point of the picture the World places where it places a character,
                from the picture's centre, at 100% ([0, 0] without it).
    poses       Names, each for a VRM animation (.vrma, with or without the extension) that
                goes on, looping, while nothing else plays.
    defaultPose The pose it starts in.
    motions     Names, each for a VRM animation played once, then the pose's again.
    faces       Names, each for weights of the avatar's expressions: %[ name:weight ], or a
                name alone (weight 1). Names are the avatar's, or VRM 1.0's presets (happy,
                angry, sad, relaxed, surprised; aa, ih, ou, ee, oh; blink ...), which find a
                VRM 0.x avatar's own (joy, sorrow, fun; a, i, u, e, o; blink_l ...). An
                expression the face doesn't name is at 0, and weights fade into the next face's
                over vrmFaceFade ms (300).
    defaultFace The face it starts with (none without it).
    blink       The expression blinking sets ("blink").
    mouth       The expression the voice opens without a lip track's vowels ("aa").
    vowels      The expression for each vowel of a lip track: %[ a:"aa", i:"ih", ... ]
                (vrmVowels: VRM 1.0's aa, ih, ou, ee, oh).



◇ How it moves



While the character shows, the avatar is drawn again every vrmFrameTime ms (33: 30 times a
second), each frame read back from OpenGL into the character's layer, at the size the level
draws it. Its pose's VRM animation loops; a motion's plays once, fading in from wherever the
pose had it and back out into the pose's over vrmMotionFade ms (400). Its spring bones (hair,
clothes) swing as it moves, and are put at rest in its first pose.



Its eyes and mouth go as a character drawn from layers' do (Blinking and lip-sync, above): the
eyes' level (open, half, closed) sets its blink expression (a face's own blink holds: "blink"
=> 1 is eyes shut), and the voice opens its mouth, eased over vrmEyeSmooth and vrmMouthSmooth ms
(40, 50): with a lip track, each vowel's expression (vowels), else its mouth expression. A
face's mouth expressions add to the voice's. An expression that overrides blinking (VRM's
overrideBlink: an avatar's happy often does) holds the eyes as it says.



Its pose and face are kept in a save, and a load starts the pose's animation again. An avatar
is let go when its character leaves the screen, and read again when it comes back. While a skip
shows nothing, the character keeps its last picture, and a motion played once doesn't play.
There's no face window (facewin) for an avatar. Edges aren't smoothed on the SDL engine (no
MSAA: GFX_Three.tjs). The settings are global variables in KAGEnvCharacterVRM.tjs, which
Override.tjs can change: vrmFrameTime, vrmMaxHeight, vrmMotionFade, vrmFaceFade, vrmEyeSmooth,
vrmMouthSmooth, vrmFov and vrmVowels.

● Objects That Move With Others



Since 0.26.0 a character or a layer can be attached to another, show another's picture, or be
clipped to another's outline (template/system/KAGEnvLinks.tjs). These are attributes of the object
like its xpos or its opacity, part of the World's state, so compiled scenes, saves, Back and Replay
carry them; the sample's Character demo shows them in its "Together" scene.

  attach=<name>        It moves, zooms and turns with the other object: its own xpos and ypos are
                       an offset from the other's anchor (World units, y going up), scaled and
                       turned as the other is, and its own zoom and rotate are added to the other's.
                       It's drawn just above the other, faded with it, and it leaves when the other
                       leaves (hidden, or deleted with [dellay]/[delchar]). It follows every move,
                       zoom and turn as it happens, actions and timed moves included.
  attachbehind=true    Drawn just behind the other instead (false: just above it).
  attachkeep=true      Stays when the other leaves, hidden until it's back.
  follow=<name>        Its picture is the other's as drawn (any character, a Live2D or VRM one
                       too, or a layer), each frame, so it blinks and moves with it: a reflection,
                       a shadow, a second view. Its own flipx, flipy, zoom and rotate turn it about
                       the other's anchor, and its xpos and ypos then move it; drawn just behind the
                       other. A reflection is flipy=true moved down by twice the height of the
                       other's anchor above its feet.
  clipto=<name>        Drawn only where the other is drawn: its alpha multiplied by the other's,
                       on the screen (a light on a character, a pattern on a costume).
  relative=<name>,<dx>,<dy>
                       Placed once at the other's xpos and ypos plus dx, dy (no lasting link).
  detach               Lets go of all of them; the object goes back to its own place.

    [ai standard posleft]
    [pip standard posright]
    [newlay name=bubble file=prop_bubble attach=pip xpos=210 ypos=330 show]
    [pip center time=800]          (the bubble goes with him)
    [newlay name=light file=prop_light attach=ai clipto=ai xpos=180 ypos=760 opacity=220 show]
    [newlay name=view follow=ai zoom=38 flipx=true xpos=1180 ypos=1020 show]
    [pip hide]                     (and his bubble with him)

An attached or following object's layer is placed from the other's place on the screen, after the
camera, so it keeps its place on the other through the camera's moves too. Leaving with the other
is immediate: an attached prop disappears as its character's hide transition begins.



● Pictures and Outfits an Earlier Choice Changes



An earlier choice (glasses or not, which outfit) can change the pictures and outfits shown later
while the script still names one, with no branch in every scene that shows them. Two tab-separated
tables, anywhere on the auto path (the sample's are in data/main), each read when the World starts;
a line starting with # is a comment, and the first row whose condition holds wins (TJS; f is the
playthrough's flags, sf the system's):

  imagenamemap.txt    <name the script uses> <tab> <picture shown> <tab> <condition>

● About Actions



Coordinates, magnification, etc. of a layer can be changed over a specified time.
This function is called an "Action".



◇ The Sample's Staging Kit



The sample (since 0.18.0) has a word for each of these, written on the actions below:

    gestures, envinit.tjs's actions ([ai nod]): nod, nods, headshake, sigh, laugh, shrug,
      lookaround, wobble, slump, startle, tremble, bounce, leanin, stepback, sway, stomp, pop,
      tilt, giggle, faint (besides bow, shock, hop and shiver); each a relative action, so the
      character ends where it began. [wact] waits for one to end.
    screen shakes, camera actions run by macro.ks's [quake], [thud] and [rumble]
      ([env actioncamera=quake])
    [closeup] and [closeupend]: the camera closes in (zoom=140, x=, y=, time=) while the
      background blurs (blur=8), and back
    [dim], [whiten] and [undim]: a translucent black or white veil over the scene for inner
      thoughts (a World layer named veil at level 5; opacity=)
    [eyecatch]: a card between scenes (data/image/eyecatch.png, from tools/assets/make_opening.py)
      for time= ms, which a click skips
    trans=showslide (envinit.tjs's transitions): a character slides in as it fades in

The Character demo's "Staging Kit" scene plays each with its name.



◇ Automatic Action



If `time` is specified simultaneously with parameters like `zoom`, `rotate`,
those parameters are automatically action-processed.
A smooth change from the current value to the specified value is executed over the specified time.
However, if `trans` is specified, transition processing takes priority.



Example: Magnify to 2x size over 1 second.
[layer zoom=200 time=1000]



Note that when specifying parameters, if you use initialization specification (Parameter=SpecifiedValue:InitialValue),
it first resets to the initial value and then executes the action until it reaches the specified value.



Acceleration/Deceleration of the action can be specified with the `accel` parameter.



◇ Action Command



Advanced actions can be applied by defining actions.
Operations on multiple parameters can be described in these definitions.



1. Define name and parameters in `actions` of `envinit.tjs`, or
　 create a definition file in the form `action_Name.tjs`.



2. Specify with `action` parameter.



※ Default parameters can be overwritten by other parameter specifications.



◇ Action Synchronization Rules



Principle 1: Action specifications are executed asynchronously.



Scripts proceed even while an action is in progress.
If waiting for processing until the action completes, specify the `sync` parameter.



Actions operating synchronously with `sync` specification are canceled by click operations.
Cancelled actions enter the state where the specified action is completed.



Principle 2: Actions in operation are canceled by page break processing.



If you want to ignore page break cancellation and continue the action
across multiple texts, specify the `nowait` parameter.



Note that using `stopaction` forces actions specified with `nowait` to stop as well.



● About Transitions



The process of switching the display content of a layer is called a "Transition".



Transition processing is executed in the following cases:
・When displayed
・When erased
・When display content changes



◇ Individual Transition and Global Transition



In World Extension, in principle, transitions can be specified for the display of individual objects.
However, in the following cases, it is automatically treated as a Global Transition:



・When the display level of an object changes.



・When commands affecting other objects are used.



  - Changing background with background effects (Effect layer changes).
　- Changing background time (Character changes simultaneously).
  - Changing background while Event CG exists (Event CG is erased).
  - Executing environment commands for effect manipulation (Effect reaches all images).



・When a transition specified with the `trans.transall` parameter is used.



A Global Transition is a process that transitions the entire screen at once.
Besides the aforementioned automatic processing, it can be explicitly executed with `begintrans`/`endtrans`.



◇ Specification Method



1. Define name and parameters in `transitions` of `envinit.tjs`, or
　 create a definition file in the form `trans_Name.tjs`.



2. Specify with `trans` parameter.



※ Default parameters can be overwritten by other parameter specifications.



3. Or give `trans` a transition method's name, with its attributes in the same tag:
　 [night trans=blurfade time=1500 blur1=48]. The methods are the engine's, extrans's
　 and extNagano's (doc/kagex.txt, "trans (Extension)"). A registered transition can hold
　 what a tag can't, such as morphing's triangle arrays.



◇ Transition Synchronization



Transitions wait for processing to complete by default (sync state).
However, if `nosync` is specified, it executes asynchronously.
If a transition is executed on a layer currently executing a transition,
it executes after the previous one is cancelled.



This behavior can be reversed by defining "nosynctrans" in `envinit.tjs`
(Default becomes asynchronous like action, sync can be done with `sync`).
Also, transitions specified with the `waittrans` parameter are synchronized.



Transitions operating synchronously are canceled by click operations, just like actions.
Cancelled transitions enter the state where the specified transition is completed.



Transitions in operation are canceled by page break processing, just like actions.
If you want to ignore page break cancellation and continue the transition
across multiple texts, specify the `nowait` parameter.



Using `stoptrans` forces actions specified with `nowait` to stop as well.



Global Transitions can also be executed asynchronously with `nosync` specification like individual transitions,
but in principle, only one Global Transition can be executed at a time.
During a Global Transition, if another Global Transition or drawing update processing (various transitions and actions)
of individual objects is executed, the currently running Global Transition is cancelled
to prevent inconsistencies.



※ A warning message will be displayed in the log.
　If this appears, the timing specification is unreasonable, so
　it is recommended to review the description.



● delayrun



Commands can be executed with delay.



[Command delayrun=DelaySpecification]



・Delay is canceled before page break processing by lineMode (after click wait),
  or by the `[delaydone]` command.
・If a number is specified, it executes after delaying for the specified time (in ms).
・If a string is specified, it executes at the timing of the label in the voice played next.
・With string specification, if there is no voice playback, execution is forced at the beginning.
