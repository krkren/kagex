Title: About Kirikiri/KAGEX

Author: Limited Partnership Wamsoft, Tsuyoshi Watanabe



● Kirikiri/KAGEX Overview



This is a system that largely extends Kirikiri/KAG, mainly in terms of layer functionality.



・Layer rotation and scaling processing

・Processing for layer stacking level control

・Layer automatic action processing



The basic concept of the system remains the same as Kirikiri/KAG, and basic functions

are maintained as they are. Before reading this document, please understand the

entirety of KAG first.



For details on KAG, please refer to



 http://devdoc.kikyou.info/tvp/docs/kag3doc/contents/



.



● Notices



fadepausebgm/setbgmlabel/clearbgmlabel/setbgmstop/clearbgmstop 

timeout/ctimeout/click/cclick/wheel/cwheel have been integrated into KAG.



The origin rule for Affine transformation processing has changed.

In the current system, rotation center = layer origin.

To use the traditional layout, you need to set afx, afy to center

and shift the display coordinates by that amount.

● Explanation of Extensions



◇ Control System Extensions



◆ Wait Commands General (Extension)



For wait commands where the wait parameter is specified, after the standard wait action,

the system waits for the additional specified "time".

If the action is cancelled by a click, this additional wait does not occur.



Attributes

	wait	Additional wait specification (in ms)



* This extension is invalid for wait, wd, waituntil



◆ Wait-Enabled Commands General (Extension)



Attributes have been added to automatically execute a wait action for commands

that have a corresponding wait behavior.



Attributes

	sync	Execute wait

	wait	Additional wait specification (in ms)



Supported commands



 quake, animstart, trans, move, action, 

 fadeinbgm, fadeoutbgm, fadepausebgm, fadebgm, xchgbgm, 

 fadeinse, fadeoutse, fadese,

 playvideo



◆ Commands General (Extension)



Commands with the delayrun parameter specified are executed with a delay during wait processing.



Attributes

	delayrun    Delay parameter specification

				Number: Executed after a delay of the specified time (in ms) or more

                String: Executed at the timing of the corresponding label in BGM/SE



Delayed execution is cancelled (executed immediately at that point) before page break processing

by lineMode (after waiting for a click) or by the [delaydone] command.



◆ delaydone (New)



Forcibly executes all commands whose execution is currently delayed.



◆ delaycancel (New)



Cancels all commands whose execution is currently delayed.



◆ wd (New)



Delay wait. Waits until the corresponding label in BGM/SE is passed.

If the label has already been passed, it is ignored.



Attributes

	name	Wait label

	canskip If skippable, true



◆ td (New)



Delay execution label registration. Manually registers labels for delay processing

separately from BGM/SE labels.



Attributes

	Can register arbitrary labels in the form of LabelName=DelayTime.



◆ waituntil (New)



Functionally equivalent to the until parameter of waittag.

However, if clicked even once, the time origin of resetwait is cleared and

subsequent waituntil commands are invalidated.



◆ showwait (New)



Test command. Logs the difference from the time origin at the moment the command is executed.



◆ set (New)



Sets a variable.



Attributes

	name	Variable name tf.* f.* sf.*

	value	Value (treated as a string)



◆ func (New)



Calls a TJS function.



Attributes

	name	Global function name

	others	Parameters are passed to the function's first argument as a dictionary.



◇ Layer Extensions



◆ Non-primary layer status of the base layer



In KAGEX, the base layer is no longer Window.primaryLayer.

Please be careful.



◆ Introduction of the level concept to foreground layers



Original KAG foreground layers have a display order based on numerical order.

KAGEX introduces the concept of "levels", and display order is determined by level units.



・Layer groups with smaller levels are displayed underneath.

  -> Controllable via the laylevel command.



・Display control for "frontmost" and "backmost" is possible within the same level.

  -> Controllable via layfront / layback commands.

	Optional parameters for static (TV static, template/system/GFX_Static.tjs)



		Moving static for a broken screen, a bad signal or a memory breaking up:

	Optional parameters for roll (a credits roll, template/system/GFX_Roll.tjs)

		A staff list in a text file scrolls up over the layer, taking a time of its own or the

		rest of the music playing (since 0.17.0):

		[image layer=1 page=fore flip=credits fliptype=roll rolltime=bgm visible=true]. The

		file (credits.txt; a language's own in data/lang/<code>/ stands in for it) holds a line

		for each name, and these: "# Heading" (a heading, larger), an empty line (a gap),

		"@size 30" (the lines' size from there on), "@gap 120" (a gap of so many pixels), and

		"@image event1 1300 480" (a picture scrolling with the text: its left at 1300 and 480

		wide; without them, centred, taking its own room). Each frame only the lines in view

		are drawn, so a long list costs no memory. The trigger rollend goes when the last line

		has gone, and sf["roll:<file>"] (KAGRollSeen(name)) says it was seen to the end, so a

		scenario can let a click skip it only then:

		[waittrig name=rollend canskip=&sf['roll:credits']]. A save keeps how far it got.

		rolltime      ms the roll takes, or bgm: the rest of the music playing. Default 30000.

		rolloffset    ms more (or less, negative) than that, for a track whose end is quiet.

		              (rollfrom=6000), or a label of its loop file (<file>.sli, Label

		              { Position=<sample>; Name=credits; }). The roll waits for the music to reach

		              rollfrom and ends as it reaches rollto, for a song with an intro or a

		              reprise (since 0.18.0). Without rollfrom it starts at once, without rollto it

		              ends with the track; a label the file lacks is logged. They win over

		              rolltime, which stays the length when the music has neither. Prefer times:

		              music with labels can hang the engine now and then (UPSTREAM.md 44).

		rollx         The text's centre. Default: the layer's middle.

		rollsize      The names' size. Default 32; headings are 1.3 times.

		The sample's Credits demo (credits.ks) rolls the sample's credits to its music, from

◆ trans (Extension)





Besides the engine's transitions (universal, crossfade, scroll) and extrans's (wave, mosaic, turn, rotatezoom, rotatevanish, rotateswap, ripple), method= takes the twelve of extNagano (plugin/extNagano.dll). The World's trans= takes the same names, with the same attributes in its tag (doc/world.txt).

A transition whose plugin didn't load runs as a crossfade, and the console says so once. KAGPluginTransitions (Initialize.tjs) says which loaded.

Since 0.28.0 method=glitch is kagex's own (the glitchtrans plugin, https://github.com/krkren/glitchtrans, which every engine ships with: plugin/ on the desktops, linked in on the web, Android and iOS): the old picture breaks up as a damaged video stream or a bad signal would and comes back as the new one, in stages: its strength rises, holds and falls with hiccups on either side, the faults jump at steps of irregular length and take turns, and the new picture arrives in macroblocks (in patches, stripes or sweeps), the same glitch each time for one seed. The faults: a datamosh (the new picture's motion applied to the old one, whose blocks slide and smear while the new picture's outlines come through, each block refreshed into the new picture at its own moment), a broken JPEG stream (colours drifting and blocks sliding from a point on, frequency patterns, lost blocks), damaged cells (KinoGlitch's runs: moved, from the other picture, colours shuffled or crushed), pixel sorting, a bad analog signal (jitter, shake, roll with its blanking bar, slant, a tracking band, colour lag, scan lines, interlaced fields), bands slid, stretched or smeared, the colours split, rows of static and garbage, displaced rectangles and frames of signal failure. style= picks which lead: mixed (the default), digital, analog or mosh. Attributes: time (needed), style, seed (a number: the same glitch every time; by default a new one), strength (0-100: how wild, 100), each fault's amount by the style's default: bands (how many), shift (how far a band slides, in pixels: a twelfth of the width), split (how far the colours part: a 96th), noise, blocks, damage, jpeg, mosh, sort, analog and flash (0-100 but blocks, a count), step (about how long a jump of the glitch holds, in ms, 50) and spread (0-100: how much of the time the new picture takes to arrive, 60). The World's trans=glitch takes them too, with noise and spread as glitchnoise= and glitchspread= (a World tag's noise= is every picture's own), and breaks up the whole screen, as a broken signal would: an image's or a character's trans=glitch goes through the screen's transition unless transall=false, which glitches that layer alone; a piece a fault moves takes its alpha with it, so a layer glitched alone breaks up with its shape over the scene. The sample's macro.ks has [glitch time= strength= seed= style=], a glitch of the whole screen. GlitchTrans.apply(layer, %[ frame, seed, style, ... ]) draws one glitched frame of a layer's own picture over it (the same options; frame picks the moment), for a broken screen held still. The plugin draws on the engine's draw threads. The screens' own transitions can be the glitch too ("Screens Change With", below).

Five of extNagano's transitions, as krkrz_dev rebuilt the plugin, don't do what they say (UPSTREAM.md 42): book's page stops three quarters of the way and the rest of the old picture vanishes at the end, multiripple brings the old picture back where two or three ripples have passed, rgbfade's colours each take the shortest one's time and a pixel without alpha comes out in a solid colour, zoomfade's zoom is jagged, and spin shows a flat panel growing from the middle instead of a turning box. kagex runs them as the plugin draws them (from 0.18.0 to 0.26.1 it drew these five itself, ScriptTransitions.tjs, under the plugin's names; that's gone), and the sample's transition.ks shows the seven others.

◇ Message Window Display System Extensions



◆ Overview of Extensions



To be convenient for creating ADV style games,

writing rules have been extended, and it is possible to assign automatic processing

for line breaks.



Also, extensions have been made internally to support "Name Layer" and "Expression Layer".



◆ Line breaking



English text (and any language with spaces between its words: KAGLanguage.wordWrap) breaks
between words, not in the middle of one: the word wrap follows each scenario line as it's
drawn, its tags taken out and [r] as a new line, so lines that start with a tag or a tab, have
[r] in them, or go on to the next page wrap the same way. The space a line breaks at isn't
drawn. Where krkr_richtext draws the message window (useRichText), the breaks come from its line
breaker (RichText.ParagraphLayout, the one its StyledLayout uses), which lays out the whole line
at once, as Config.tjs's lineBreakStrategy says:


    ;lineBreakStrategy = "quality";


  quality     Evens out ragged lines (minikin's HIGH_QUALITY: the last line can be short).
  balanced    Makes the lines of a passage about the same length.
  greedy      Fills each line as far as it goes.


The rest of a line already begun (text that carries on after an earlier line of the script) is
filled as far as it goes, then the remaining text is laid out. The plan is made again where the
text goes somewhere it didn't expect (a new page, [r], another font), and text the line doesn't
have ([emb], [ch], a macro) ends it for the rest of the line. Without krkr_richtext (the browser
and iOS builds), and as a check on the plan, each word that won't fit on the line goes to the
next one. The history log wraps by its own width, a word at a time.

Japanese and Chinese (no spaces between words) break where the same line breaker plans,
filling each line as far as it goes (lineBreakStrategy is for text with spaces). It follows the
Unicode rules with the language's: a closing bracket, a full stop, a comma or a small kana
doesn't start a line, and a word in Latin letters isn't split. Where KAG let such a character
hang into the margin at the end of the line (marginRCh), the line breaker takes the character
before it to the next line, so the margin stays empty. Without krkr_richtext, and in vertical
text, they keep KAG's own character wrap with its kinsoku, which also catches a line that runs
too long. Text that isn't the line's ([emb], a macro) leaves the rest of the line to KAG's wrap.

Where krkr_richtext draws the message window, the characters of a line are drawn together, as
its line breaker lays them out: each time the text stops (after every character at the usual
speed, once a line when it comes all at once), the line so far is laid out again (its
StyledLayout) and drawn whole. So the characters are kerned and shaped together (ligatures,
accents and emoji sequences made of several characters) and placed to a fraction of a pixel.
It's on unless Config.tjs says otherwise:


    ;useStyledLayout = true;


KAG still places each character and times it, so the text speed, waits, links and the word wrap
are as before: a run of characters is one font and colour on one line, and a character with
ruby is a run of its own, with KAG's ruby (rubySize, rubyOffset) over it. Vertical text, a
pitch ([style pitch]) and the character fade (hasChFadeLayer) draw a character at a time.

● About Special Specification Changes



◇ Change in specification of askYesNo function



The behavior related to askYesNo has undergone a major specification change.

Please be careful as you need to completely revise the code if you were

using it uniquely in KAG.



Previous version: 



  askYesNo(message, title)



　Execution of TJS is blocked until the dialog processing is finished, and the YES/NO result is

　returned.



New version:



  askYesNo(message, title, yesFunc, noFunc, param, doneFunc);



  yesFunc  : Processing executed when YES

  noFunc   : Processing executed when NO

● Languages


A game can be shown in more than one language, and the player can switch between them while
playing: F9, the controller's L2 (VK_PAD7) or a button of the game's (the sample's Config
screen has one) draws the message on screen, the choices on show and the screen on show again
in the other language. The backlog keeps each line in the language it was shown in.

The story is in the compiled scenarios (doc/scn.txt), as in Wamsoft's multi-language games:
each script's translations are compiled into its .scn file with it, so one file holds every
language's text, speakers' names, choices and scene titles, and the scene player shows the
language shown. The interface (the screens' images with words on them, the prompts and labels
the screens draw) is in each language's folder.


◇ Setting up


Config.tjs lists the languages, the one the scenarios and scripts are written in (the source
language) first:


    ;global.KAGLanguageList = "en,ja,zh-cn,zh-tw";


(The sample's, since 0.28.1: English, Japanese, and Simplified and Traditional Chinese.) With one
language (the template's "en") nothing changes. Each other language has a folder,
data/lang/<code>/ (lang/ja/ for Japanese, lang/zh-cn/ and lang/zh-tw/ for Chinese):


    lang/ja/scenario/   The scripts in !scnlist.txt, translated (◇ Translating the story)
    lang/ja/lang.json   The interface strings (◇ The interface strings)
    lang/ja/...         Anything else found by name, in that language: the screens' images
                        with words on them (the sample's data/lang/ja/ has the Japanese title
                        buttons, Config screen and the like, drawn by tools/assets/make_ui.py
                        --lang ja), a CSV, a voice


The folder (not its scenario/ folder) is on the search path while the game shows that
language, after every other path: a file in it stands in for the file of the same name
anywhere else. The image cache keys on the name a script loads, so a switch empties it
(System.clearGraphicCache). A zip patch (patch.zip and on, or DLC through KAGMountPatchZip)
can carry lang/<code>/ folders of its own, which join the language's.

A language whose characters the engine's own fonts don't have (Chinese: the engine brings
Roboto, and the template Noto Sans JP, whose kanji are Japanese forms) needs a font of its
own: list it in fonts.csv with the language in its languages column (● Fonts and Text Styles), and the text
of that language is drawn in it first. The sample ships Noto Sans SC for zh-cn and Noto Sans TC
for zh-tw, cut down by tools/assets/make_fonts.py to the characters its texts use and the
common ones (GB2312's first level, Big5's), about 1.6 and 3.2 MB. The name inside a font file
has to be the face fonts.csv gives it: the engine's own drawing (Layer.drawText, a Yes/No
prompt, the help line) finds a registered file's font by that name, and with another one draws
a system font in its place, a "?" for every character that font lacks (make_fonts.py renames
Noto CJK's "Noto Sans CJK SC" and the like; up to 0.28.0 the serif font drew this way outside
the message window).


◇ Translating the story


A script's translation is a copy of the script with its text in the other language, in
lang/<code>/scenario/ under the script's file name: lang/ja/scenario/char.ks for char.ks. Only
its text is used: the messages, the display names after a slash (【ai/？？？】), the choices'
text ([seladd text=...]) and the scene titles (*label|Title). Everything else comes from the
script, so the translation keeps the script's labels, tags and messages, in the same order,
each said by the same character; where a tag splits a message ([emb], a World tag) the
translation is split by it too. Line breaks ([r]), ruby and font commands can differ.


    char.ks                                    lang/ja/scenario/char.ks

    *start|Start                               *start|スタート
    [ai standard center]                       [ai standard center]
    【ai】If a voice number is specified...     【ai】ボイス番号が指定されていると...
    【ai/???】To change the display name...    【ai/？？？】表示名を変更する場合は...


The compiler (SceneParser.tjs) compiles each translation with its script and matches them
scene by scene, then text by text and choice by choice. A scene that doesn't match (another
number of texts or choices, a text said by someone else) shows the script's own text in that
language, as does a script without a translation; the compiler says so (a warning in the log,
or kagex-release's compile-scenarios.log). Changing a translation compiles its script again.
A release leaves the translations out with the scripts (tools/release/README.md).

A speaker's displayed name, when the line gives none, is the character's nameAlias in
envinit.tjs, which can be a dictionary by language (the source language's stands in for a
language it lacks):


    "ai" => %[ "nameAlias" => %[ "en" => "Ai", "ja" => "あい" ], ... ],


Scripts KAG plays itself (the title screen, the system screens, a script not in !scnlist.txt,
or any with -scnplay=no) are shown as written, with the source language's names.


◇ The interface strings


lang/<code>/lang.json, JSON in UTF-8 (or UTF-16, with or without a BOM), holds the strings the
screens draw at run time (tr(), below), keyed by the source text; a string it doesn't have is
shown as written.


    {
      "name": "日本語",
      "strings": { "Load this save?": "このデータをロードしますか？", "Characters": "キャラクタ" },
      "wordWrap": false
    }


  name      The language's name in itself.
  strings   Prompts, labels and messages, looked up as written, then without spaces at their
            ends.
  wordWrap  Whether the story's lines break between words (true) or anywhere, with KAG's
            line-breaking rules (false). Default: false for Japanese and Chinese, true
            otherwise.


The framework's own strings (the Yes/No prompts, Yes and No, About, the backlog's "Choice:
%s") are in system/kagex_<code>.json, which the game's table can change. A save slot shows the
title of the scene it was saved in, in the language shown: a compiled scene's own title, or
for a script KAG plays itself its title through the strings (getBookMarkPageName).


◇ Which language


Until the player chooses one, the game shows the language the system prefers: the engine's UI
language (System.uiLanguage, the system locale or -language=), then
System.uiLanguageCandidates, then the source language. The player's choice is saved with the
system variables (scflags.language) and wins from then on.


◇ Script interface

  KAGLanguage.list              The languages, the source language first.
  KAGLanguage.available         Whether there's more than one.
  KAGLanguage.nameOf(code)      A language's name in itself.
  kag.setLanguage(code)         The player's choice: saved, and shown now, or at the next
                                click wait when text is still being drawn (not while a Yes/No
                                prompt is open).
  kag.switchLanguageByKey()     The next language (F9, L2).
  kag.languageChangeHook        Functions called (code, previous) once the game is drawn in
                                another language: draw the screen on show again here (the
                                sample runs the label that draws it, redisplayScreen in
                                Override.tjs).
  tr(text)                      An interface string in the language shown (its strings).
  KAGLanguage.ui(text[, lang])  The same, in the language given.
  scnTitleIn(scene[, lang]), scnTitles(scene)

                                code (KAGEnvPlayer.tjs; the scenes of a StorageData).
  KAGLanguage.menuCode          The language of the menus (since 0.26.0): menuLanguage, or the
                                story's (current) when the player hasn't chosen one for them.
  kag.setMenuLanguage(code)     The menus in a language of their own ("": the story's), shown

The message window records what each page draws (MessageLayer.redrawTextEnabled, on when
there's more than one language), with each compiled text and the speaker's name in every
language, and draws the page again from that record in the new language
(MessageLayer.redrawTextIn). A message layer with buttons or links on it isn't drawn again:
the screen it belongs to is (languageChangeHook). The system buttons ([sysbutton]) load their
images again by name.


◇ The menus' own language, and two languages at once (since 0.26.0)

The menus can be in a language of their own while the story is in another (the options
menuLanguage and secondLanguage, Options.tjs; the sample's Config has them on its last page,
Languages). With one, data/lang/<code>/ on the search path, the strings (tr()), the menu bar,
the options' labels, the quick menu, the manual and the fonts of every role but "message" are
the menus' (KAGLanguage.menuCode); the story's text, its speakers' names, the choices, the
scenes' titles, the message window's font and its line breaking are the story's
(KAGLanguage.current). F9 and the Language buttons change the story's language; with no menu
language of their own the menus follow it, as before 0.26.0.

A second language shows each message again under it, at the click wait, in a smaller size
(kag.secondLanguageScale, 0.72 of the window's) and another colour (kag.secondLanguageColor):
for language learners, and for two players who read different languages. It's the compiled
scenes' own translation of each text (scripts KAG plays itself have none), recorded with the
page (MessageLayer.beginSecondText), so switching languages, swapping the two (Shift+F9, the
action swapLanguages) or turning it off draws the page again as it should be. A message too
long for the window's lines is cut where the window ends. The backlog keeps the story's
language. The player's choices are kept in the system variables (scflags.menuLanguage,
scflags.secondLanguage).



● The Interface



The SDL engine has no menu bar and no native dialogs, so the framework draws its own in the
game window, which the mouse, the keyboard, a controller and a screen reader all work: the menu
bar (in a window), the controls list, the Yes/No prompts and About. The menu bar and the
controls list are drawn with the engine's Elements UI (ElementsDialog, ElementsPanel) in the
dialogs' look; where the engine has no Elements UI they aren't there, and F10 does nothing.



◇ Key bindings



The keys the game window acts on are a list, kag.keyBindings, which the controls list reads, so
a game that changes them gets a correct list. A game adds its own in AfterInit.tjs (the sample
binds F1-F8 there):


    kag.bindKey(VK_F2, 0, startSave, "Save");
    kag.bindKey(VK_F5, 0, toggleFullScreenByKey, "Full screen or window", true, false,
        function { return kag.displayMenu.enabled; });


  kag.bindKey(key, shift, action, label, early = true, debug = false, when = void)
    key       The key (VK_*).
    shift     The modifier keys held, compared exactly (0, ssShift, ssCtrl, ssAlt or a sum: a
              held key's repeats carry ssRepeat, so they don't match), or void for any.
    action    A function, called with (key, shift), or an expression.
    label     What it does, in English, for the controls list (shown through tr() in the
              language shown); void leaves the key out of the list.
    early     true: it runs before the layer with the keyboard focus gets the key, so it works
              over the choices and dialogs too (as a keyDownHook function does). false: only
              when nothing else took the key, as the framework's own.
    debug     true: only in KAG's debug mode (debugWindowEnabled; -debugwin=no turns it off).
    when      void, or a function: the binding is there while it returns true.
  kag.unbindKey(key, shift)
              Removes the binding of key with shift.


A function written outside any object (in AfterInit.tjs) runs with the global object as this.
The framework binds F, B, A, S and L (free save mode), R and Shift+Up, Esc, F9 (the next
language), F10 (the menu bar's first menu, in a window), F12 and Print Screen (a screenshot),
and in debug mode Shift+F12 (the
debug window), Shift+F11 (the debug level) and Shift+Backspace (back to the last pass record).
A key a keyDownHook function handles still works, but the controls list can't show it.

A controller's buttons send keys (kag.padKeyMap, from initialPadKeyMap in MainWindow.tjs): the
D-pad and the left stick the arrows, A Return, B Esc, X the message history, Y auto mode, R1
skipping to the next choice or unread text, R2 held skipping (Ctrl), L2 the next language,
and START and R3 (the right stick pressed) F10. A button mapped to a key does what the key does,
so the controls list shows the button with the key's binding (a button mapped to a function,
with the binding that has that function). A game changes the map in AfterInit.tjs (the sample's START,
BACK and L1 are F4, F2 and F3):


    kag.padKeyMap[VK_PAD10] = VK_F4;
    kag.recreatePadKeyMap();



◇ The menu bar



In a window, the items KAGWindow_createMenus makes (Menus.tjs; a game's own in Override.tjs)
show as a menu bar, as Kirikiri's Win32 menu bar did: the window is kag.menuBarHeight pixels
taller than the game, the game is drawn under that strip (Window.setViewport), and the strip
holds the top menus' titles. Full screen has no menu bar, as it had none in Kirikiri. The
framework's menu has System, Display (a window or full screen, the window size, a
screenshot), the message commands, Help (Controls, About) and, in debug mode, Debug.

A click on a title drops its menu down over the game (a top item without a submenu does what
it does at once); while a menu is open, moving the mouse to another title opens that one, and
resting on an item with a submenu opens the submenu. F10, START and R3 open the first menu from
the keyboard. In a menu the arrows or the D-pad move (Right opens a submenu or the next menu,
Left closes a submenu or goes to the menu before), Return or A chooses, Esc or B closes a
submenu or the menu, and a click outside it, a right-click or F10 closes it. Choosing an item
closes the menu and then does what the item does. The items show as they are now (enabled,
checked, the radio groups' choice).

An item's caption is in English, with an "(&X)" accelerator and a "\t" shortcut after it, as
for a menu bar: the bar takes the accelerator off, shows the caption through tr() in the
language shown and the shortcut at the right ("Save(&S)\tF2" shows as Save, with F2). An item
is left out while its visible is false (Menu_visible_config in Config.tjs) or its
menuBarHidden is true, and so is Help > Contents without the help file.

  kag.showMenuBar()         Opens the first menu, or closes the one open (F10; false: there's
                            no bar now).
  kag.menuBarShown          Whether the bar is there: in a window, with the menu visible, on an
                            engine with the Elements UI and Window.setViewport.
  kag.menu.visible          false takes the bar away (and the window loses the strip); true
                            brings it back.
  kag.menuBarEnabled        false: no menu bar, in a window either (F10 and START do nothing).
                            Set it in AfterInit.tjs.
  kag.menuBarHeight         The strip's height in screen pixels (30). Set it in AfterInit.tjs.
  kag.updateMenuBar()       Draws the titles again, after a game changed its top menus.



◇ The controls list



The controls list shows what each key, mouse button and controller button does, read from the
bindings themselves: the window's key bindings (above), the controller's map, and what the
framework does in code for Return, Space, Ctrl, the arrows and the mouse; keys with the same
action share a row. The controller's buttons are named by the controller in use
(System.padStyle: ✕ ○ □ △ on a PlayStation pad, A B X Y elsewhere), and in debug mode the
debug keys have a section of their own.

  kag.showControls()        Opens it (Help > Controls; the sample's Config screen has a
                            Controls button that calls it).
  KAGControlsList(kag)      The list: an array of sections %[title, rows], each row
                            %[keys, action, said] (said: the keys as a screen reader reads
                            them, when it differs).



◇ Screenshots



F12 (and Print Screen, where the system passes it on) saves what the screen shows as a PNG,
screenshot-<date>-<time>.png, in the save folder, and says so in a corner for a moment. Writing
a 1920x1080 PNG takes about 90 ms, which shows as a hitch, so where the window has
startSaveLayerImage (the layerExSave plugin, which Initialize.tjs links before the window is
made) and the folder is a local one, the PNG is written on another thread; elsewhere it's
written in one go.

  kag.saveScreenshot()      Saves one; returns the file's name.
  kag.screenshotEnabled     false: F12 does nothing.
  kag.screenshotFolder      The folder (void: the save folder, System.dataPath).
  kag.screenshotNotice      false: no notice.
  kag.screenshotHook        Functions called with the file's name once it's written (void if
                            it couldn't be).



◇ Screen readers



KAG has no screen reader support of its own. The framework passes the game's text and UI to the
system's screen reader (Narrator, VoiceOver, Orca) through the engine's ElementsDialog (the
engine guide's "Accessibility"):


  ・The text of each message is read out with the speaker's name when it waits for a click (in
    auto mode, when the wait starts). Text skipped through isn't read.
  ・The choices are a list, which the screen reader can move through and choose from.
  ・The Yes/No prompts and About show their text and buttons.
  ・The menu bar's titles, its menus and the controls list are read as they are (Elements
    screens).
  ・Saving a screenshot is announced.
  ・The screens drawn on the message layers (since 0.25.0: the sample's Config, save and load,
    Extras) are read: each button, link, text box, check box and slider, named by its label or
    its help line, with the screen's help line as the screen's description; the focus follows
    the keys, and the screen reader can press them. A scrolling list or another layer on the
    screen that shows its own nodes (the music room's tracks, the player) is merged in.


Where the engine has no such interface (the browser build; the Android and iOS builds are made
without it) all of this does nothing. A game shows its own UI drawn on layers through KAGA11y
(Accessibility.tjs):

  KAGA11y.available                     Whether the engine has the interface.
  KAGA11y.announce(text, assertive)     Reads text out (assertive: interrupting).
  KAGA11y.setNodes(owner, nodes, focus) Shows owner's UI, in front of everyone else's: nodes
                                        as ElementsDialog.setGameA11y takes them (id, role,
                                        name, states, rect, parent), focus the id of the node
                                        the player is on. The screen reader's actions on them
                                        (focus, click) come to owner.onA11yAction(id, action,
                                        arg).
  KAGA11y.updateNodes(owner, nodes, focus)
                                        The same, where owner's nodes are now.
  KAGA11y.removeNodes(owner)            Takes them away; the ones behind come back.
  KAGA11y.rectOf(layer)                 A layer's place on the screen, for a node's rect.
  kag.a11yReadText                      false: the messages aren't read out.

A message layer's links (since 0.25.0) become nodes by themselves, as soon as the layer shows
them and whenever they change:

  the screen                            A group named by KAGA11yScreenNames[<the screen's
                                        scenario, without .ks>] (through tr(); otherwise the
                                        name as words), its description the screen's help line
                                        (helptexts.csv's "<screen>._").
  a link's name                         Its button's a11yLabel (the sample's drawButtonLabel
                                        sets it to the label it draws), else its help line
                                        (helptexts.csv, hint=), else its name as words
                                        ("extra_cgmode": "Extra cgmode"). The help line is its
                                        description when the name isn't it already.
  KAGMessageA11yLater()                 The fore message layers' nodes again, in a moment: the
                                        framework calls it as links are added or cleared, the
                                        focus moves or the pages are exchanged; a game calls it
                                        after changing a link's picture or state itself.

An owner of KAGA11y.setNodes whose layer is inside another owner's (a KAGScrollList on a
screen's message layer) is shown with it: the outer owner's nodes come with the inner ones'
merged in, whichever of them called last, and the screen reader's actions go back to the one
each node came from (onA11yAction gets the owner's own id).


To check without a screen reader, run the engine with a REPL and read Agent.a11yLog() (roughly
what it would say) and Agent.a11yTree(), or press a node with Agent.a11yAction(id, "click")
(tools/smoketest.py does).



● Actions, Rebinding and Gestures

What the player can ask the game to do is one table (since 0.19.0, template/system/Actions.tjs):
skip, auto mode, the message history, hiding the window, going back, save, load, quick save
and load, playing the voice again, the scene moves of compiled scenes (rewind, back to the
start of the scene, back to the last choice, on to the next scene), the next language, the
menu, a screenshot and going on to the next text ("next", since 0.20.0). Keys, controller buttons, gestures and on-screen buttons name an action,
so changing what an action does, or which key does it, changes it everywhere.

    KAGDefineAction(%[ name:"photo", label:"Take a photo", func:takePhoto,
                       available:function { return sf.cameraUnlocked; }, enabled:canTakePhoto ]);
    kag.bindKey(VK_F6, 0, "@skip");          // a key names an action with "@"
    kag.padKeyMap[VK_PAD6] = "@skip";        // and so does a controller button
    kag.gestureActions.left = "rewind";      // a gesture takes the bare name
    KAGActions.quickSave.func = mySave;      // the game's own way of doing a framework action
    KAGRunAction("backlog"); KAGActionEnabled("quickLoad"); KAGActionLabel("auto");

  available    whether the game has the action at all (quick saves only with a quick save slot);
               keys and buttons bound to it are left out of the controls list while it's false
  enabled      whether it can be done now (a quick load needs a quick save; the framework's
               follow the window's menu items); KAGRunAction does nothing while it's false

The mouse's back and forward buttons are keys of their own (VK_XBUTTON1, VK_XBUTTON2; since
0.20.0): back a line and on to the next text, and Change Controls takes them as any key.

Change Controls (the controls list's Change… button, or kag.showBindings()) lists the actions
with their keys, controller buttons and gestures: picking one waits for a key or a controller
button (Esc leaves it, Backspace takes its keys away), its gesture cell goes round the
directions, and Reset puts the game's back. The player's choices are kept in the system
variables (scflags.keyRebinds, padRebinds, gestureRebinds) and laid over the game's bindings
at start, after AfterInit.tjs (kag.applyPlayerBindings); a game's own screen can use
kag.rebindKey(key, shift, name), rebindPad(button, name), rebindGesture(dir, name) and
resetPlayerBindings(). The framework keeps F10, Shift+F11, Shift+F12, Return, Space, Tab, Ctrl,
Shift and the arrows (kag.reservedKeys).

Gestures: in the story (no system screen, prompt, history or choice showing), a swipe on a
touch screen, or a drag with the right mouse button, runs kag.gestureActions[left, right, up,
down], and the click or right click it would have made is dropped. The framework's are up for
the message history and down to hide the window; the sample adds left to rewind and right to
skip. A swipe is at least 12% of the window's shorter side within 0.8 s, mostly one way
(kag.gestures.gestureDistance, gestureTime); two fingers are a pinch. KAG clicks at a press,
and SDL and the engine send the mouse events a touch makes before the touch's own, so on a
touch screen, in the story, the press's click is held until the release (since 0.20.0; up to
0.19.0 a swipe's press had gone on to the next text): a tap clicks then, a swipe runs its
gesture and makes no click, and a drag as long that takes longer than a gesture is neither
(kag.gestures.holdClicks: void, on a touch screen, which Window.enableTouch says, or true or
false). A browser's touch screen isn't known until its first touch, so the window asks the
engine again at a press until it is. kag.gestures.when, a
function, can narrow "the story" to the game's own idea of it (the sample's, as its quick
menu's: after [initscene], not on the title or a system screen), and a drag that starts on a
scrolling list is the list's (ScrollList.tjs).

A long press (since 0.20.0): a finger held still on the story for kag.gestures.holdTime (600
ms) runs kag.gestureActions.hold (the framework's is none; the sample's turns auto mode on or
off) and makes no click as it lifts; Change Controls has it after the four swipes. Meanwhile,
over a button with a hint, its tip shows above the finger, whatever Config's Tips switch says
(Tooltips.tjs). A long press on a quick menu button opens its panel instead.



● The Quick Menu

A strip of buttons for actions that can keep out of the way (since 0.19.0,
template/system/QuickMenu.tjs): shown all the time (pinned), or fading in when the pointer
comes near and out a moment after it leaves; on a touch screen a tap on its handle brings it
back, and as a finger leaves the pointer resting where it tapped, only taps on the strip keep it
there (since 0.20.0). A button is dimmed while its action can't be done and lit while its toggle is on;
which of the two is the player's, Config's Quick Menu option (kept in the system variables;
up to 0.20.0 a pin at the strip's end said it too, which since 0.21.0 it has no more: on a
phone it was easy to hit and looked as if it did nothing). It shows in the story only: not over a system screen, a prompt or the message
history, nor while the message window is hidden.

    with (KAGQuickMenuOf(kag)) {
        .items = [ %[ action:"quickSave", image:"msg_qsave", x:228 ],

● Scrolling Lists

A list or a grid of items on a layer of its own (since 0.19.0, template/system/ScrollList.tjs,
KAGScrollList), which the game draws an item at a time, only while it's in view, and which
scrolls with the mouse wheel, by dragging (the mouse, or a finger: a flick coasts on and slows
down), with its scroll bar, and with the arrow keys, Page Up and Down, Home and End (a
controller's D-pad sends the arrows). A click or a tap on an item, or Return on the focused
one, picks it; screen readers get the items in view as a list.

    var list = new KAGScrollList(kag, kag.current);
    list.setPos(316, 318);
    list.itemHeight = 76;  list.gap = 10;          // columns = 3 for a grid
    list.drawItem = drawRow;                        // function(layer, index, w, h, state)
    list.onPick = playRow;                          // function(index)
    list.itemName = rowName;                        // function(index): for screen readers
    list.count = rows.count;
    list.setSize(1332, 604);                        // its picture too
    kag.current.addLinkLayer(list);                 // a link of the message layer

  drawItem    draws item index into layer (w x h, cleared) for its state: "normal", "over"
              (under the pointer) or "focus" (the keys' item); the pictures are kept, so
              refresh() after the data changes
  position    how far it's scrolled (px); scrollTo(px, smooth), show(index)
  focusIndex  the keys' item (-1: none)
  loop        scrolling past the end comes round to the start
  barWidth (10), barMargin, barColor, trackColor   the scroll bar (barWidth 0: none)
  coasting    how fast a flick slows (what's left of its speed after a second, 0.05)

A drag on a list makes no swipe (the window's gestures), and the wheel over it is its own,
not KAG's (the message history, a click). messageLayer.addLinkLayer(object) makes a layer of
the game's own one of a message layer's links (link type ltOwn): the keys and a controller
move to it from the buttons and back (the arrows past its first or last item), [backlay]
copies it to the other page through its cloneFor(window, messageLayer), and clearing the
message layer's links invalidates it.

The sample's Search shows the lines it finds in one (searchList in Override.tjs), kept where
it was scrolled while a line plays; its backlog coasts after a flick too. Since 0.20.0 the
CG and Replay tiles are grids of four across (cgList, replayList) and the music room's tracks a
list (musicTrackList), as many as there are, in place of pages of sixteen and twelve buttons;
screenList and listTile in Override.tjs make them and draw a tile as its button was drawn.

● The Mouse Pointer

The game's own pointers (since 0.27.0, template/system/GameCursor.tjs). The SDL engine shows the
system's arrow whatever a layer's cursor says, even over buttons (it loads no cursor file and
maps no cr* constant: UPSTREAM.md), so a game's pointers are drawn on a layer over everything
that follows the mouse, and the system's is hidden while the mouse is over the game. They're
listed in cursors.csv, a line each (# comments, tabs or commas between the fields):

  <kind>  <picture>  <hot spot x>  <hot spot y>

  default   anywhere else
  pointed   a button or a link (a layer whose cursor is crHandPoint: KAG's cursorPointed)
  click     a click wait (the base layer's cursor while KAG waits for a click)
  auto      auto mode's wait (click when there's no auto)
  text      a text field ([edit]: crIBeam, crHBeam for vertical text)
  drag      something to drag (crSizeAll, KAG's cursorDraggable, and the other drag cursors)
  wait      busy (crHourGlass, crAppStart)

A kind the table lacks shows default, a layer whose cursor is crNone hides the pointer, and
without cursors.csv (or a default line) the system's pointer shows as before. A picture's size
is its size on the screen: the pointer is drawn larger or smaller as the window zooms the game
(kag.gameCursor.minScale and maxScale, 0.5 and 4, bound how many of the game's pixels a
picture's pixel takes). The hot spot is the pixel that points, in the picture's own pixels.
Over the menu bar and the bars beside a full-screen game the system's pointer shows; a touch
hides the drawn one until the mouse moves; Hide the Pointer When Still hides it too; F12's
screenshots leave it out (kag.gameCursor.hideForCopy()). A native message box (an error) shows
the system's pointer, since the drawn one is under it. There's no pointer on Android and iOS.

Options for a Config screen (template/system/GameCursor.tjs):

  gameCursor     The Game's or The System's (only where cursors.csv has a default)
  promptPointer  where the pointer goes as a Yes/No prompt opens: Stays (where it is), To No or
                 To Yes, which also takes the keys' focus there. About and the controller test
                 put it on their button unless it's Stays. Before 0.27.0 every prompt moved the
                 pointer to No (DialogLayer.setFocusToLink's third argument, move, is false
                 for Stays: KAGOpenFocus)

The sample's pointers are tools/assets/make_ui.py's (cursors), and its Config has them on its
eighth page, with Hide the Pointer When Still.




● Advanced Settings

Settings for when something goes wrong (since 0.27.0, template/system/Advanced.tjs), out of the
casual player's way: in a window the menu bar's Advanced menu has them once Help > Show Advanced
Settings has shown it (kept in the system variables), and the manual's Advanced Settings page has
them on every platform (kagexmanual_advanced.txt, linked from the index and from "The Game Is
Slow"). They're options (Options.tjs), and each takes effect at once:

  memoryMode     Normal or Low: Low keeps the picture cache at KAGLowMemoryCache (64 MB) or less,
                 lets a layered file's CG variations go at once (KAGCGVariationLinger 0) and
                 lets go of the pictures kept now
  pictureCache   the picture cache: Automatic (the engine's size at start) or 128, 256, 512 MB
                 (System.graphicCacheLimit)
  drawThreads    the threads that draw: Automatic (the engine's) or 1, 2, 4
                 (System.drawThreadNum)
  padEnabled     the controller, and movieQuality, the movies' size (as on Config)
  resetAdvanced  a button: all of them back as they were (KAGResetOptions(KAGAdvancedOptions))

A game's menus get the Advanced menu from KAGAdvancedMenu(window, menu) and Help's item from
KAGAdvancedHelpItem(window, helpMenu), which KAGWindow_createMenus calls (a game with its own
copy of it adds the two lines); the menu's items are added once every option is defined
(KAGAdvancedMenuFill). KAGAdvancedOptions lists its options, and a game can add its own.

The options the engine reads only as it starts (-memusage, -renderer, -joypad, -gclim and the rest)
can't be set from a game (UPSTREAM.md: scripts can't write the engine's <exe>.cfu, and nothing
starts the game again); on a computer the engine's own settings screen sets them when the game is
started with -userconf, as the manual's page says.

changeUserConf(name, value) keeps an option the game's own scripts read (System.getArgument("-" +
name)) for the next start, and sets it now: the values are kept in the system variables
(scflags.userConf) and set with System.setArgument as the game starts. standview.tjs's sub-window
font size uses it; void forgets one.

● The Game in the Background

Since 0.28.0 (SystemSupport.tjs, through the sdlsystem plugin). The option backgroundMode ("In
the Background") decides what the game does while its window has lost the focus or is
minimized, and while a phone or a browser tab has put it away: keep playing ("play", the
default), mute ("mute": WaveSoundBuffer.globalVolume 0 until it comes back), or pause ("pause":
muted, and the story waits as it does for a dialog, under a dimmed screen that says Paused; the
click that brings the window back doesn't go on with the story). kag.systemEvents (a KAG plugin
of the window, KAGSystemEventsOf(kag)) reads the window's events four times a second;
.note(name) takes one by name (focus, blur, minimize, restore, show, hide, background,
foreground), .log has the last ones seen.

The urgent ones come at once, on the engine's thread (KAGSystemUrgentEvent): when a phone puts
the game away ("background"), when the system warns that memory is low ("lowmemory", Android and
iOS) and when it's about to end the game ("terminating"), the continue save and the system
variables are written there and then (KAGSaveBeforeError), since the system may stop the game
without another word; a low-memory warning also frees what the engine can (System.doCompact)
and shows "Memory is low: your place has been saved".

frameLimit ("Frame Rate Limit": none, 30 or 60) holds the game to that many frames a second,
for a laptop's battery or a fan (desktops, Android and iOS; the browser paces the frames on the
web).



● Reading Lines Aloud

Since 0.28.0 (template/system/ReadAloud.tjs, through kagex's speech plugin,
https://github.com/krkren/speech), for players who can't or don't want to read: each message is
spoken with one of the system's voices when it waits for a click, and played like a voice line:
auto mode waits for it, it lowers the music as voices do, and it plays at the voice volume (the
speaker's own, where they have one). A new line, a skip or the title ends the one before. While
it's on, the screen reader isn't given the lines too. The plugin speaks into a WAV file
(Windows' SAPI, macOS' and iOS' AVSpeechSynthesizer, espeak-ng on Linux, Android's
TextToSpeech), which plays on a sound buffer; on the web the browser's speechSynthesis speaks the
line itself, at the browser's volume (Speech.mode: "file" or "direct").

The options (Config's ninth page in the sample):

  readAloud        "off", "unvoiced" (lines without a voice of their own: narration, and
                   speakers who aren't voiced) or "all"
  readAloudVoice   the system voice: "" for the system's own, or a voice's id; the choices are
                   the first three voices of the story's language (KAGReadAloudVoices() fills
                   them before a Config page is drawn; not on the web)
  readAloudSpeed   how fast, in % (50-200)
  readAloudTest    a button that reads a sentence

envinit.tjs gives a character a voice of their own: "speech" => %[ voice: <id>, pitch: <%>,
rate: <%> ] (pitch and rate as a share of the player's: the sample's pitches tell Ai and Pip
apart with one system voice). readaloud.csv (on the search path, optional) says how to say the
words the system gets wrong: a line per word, its fields apart by tabs or commas: the language's
code (or * for any), the word as written, and as it's to be said.

KAGReadAloud.line(text, name) reads a message (MainWindow's a11yAnnounceText calls it),
.start(text, %[ voice, rate, pitch, volume ]) speaks any text, .cancel() stops, .state is idle,
making, playing or speaking. On Android, a game's APK has to declare the speech service it asks
for: kagex-release adds the query (platforms.android.ttsQuery).

● Carrying On and Quick Saves



Since 0.16.0 the game window keeps two kinds of bookmark for the player, set in Config.tjs's
window settings. Both may be numbered from numBookMarks on, past the menus' bookmarks:


    ;quickSaveSlot = 90;   // the first quick save's bookmark (-1: none)
    ;quickSaveSlots = 3;   // how many go round
    ;continueSlot = 93;    // the place to carry on from (-1: none)
    ;continueEvery = 5;    // save points between two continue saves


Quick saves go round quickSaveSlots bookmarks, so one wrong key can't overwrite the only one:
kag.quickSave() saves into the next (after the newest, scflags.quickSaveLast; a protected
bookmark is passed over) and shows "Quick saved" for a moment, and kag.quickLoad() asks, then
loads the newest. Shift+S and Shift+L do those where the game has quick saves; the sample binds
them to its own (Q.SAVE and Q.LOAD on the message window, which load through loadinit.ks).

  kag.quickSave()        The bookmark saved into, or -1 (nowhere to save from, or none free).
  kag.quickLoad()        Asks, then loads the newest; false without one.
  kag.newestQuickSave()  The newest quick save's bookmark, or -1.
  kag.quickSaves()       The quick saves, newest first.
  kag.quickSaveHook      Functions called with the bookmark after a quick save.

The continue save keeps the player's place as the game goes, so that the game can offer to
carry on from it at its next start, however it ended: it's written at the first stable state
(waiting for a click) after a save point of a new script or after continueEvery save points, and
when the game quits. Phones and browsers may end a game without it quitting, so the first two
matter there. It's only written from the main conductor where a bookmark can be saved
(kag.canStore(), not while skipping or with a dialog open). The sample's title asks once a run
("Carry on where you left off?", with the scene and the date) and loads it on Yes.

  kag.hasContinue        There's a place to carry on from.
  kag.continueOn         The player's switch (scflags): off, nothing is written or offered.
  kag.saveContinue()     Writes it now, where it can be; true when written.

When an uncaught error ends a release build, the framework first saves the system variables
(read marks, settings) and the continue save (KAGSaveBeforeError, Initialize.tjs).

The web build's saves go to /persist/<orgname>/<appname>/, which the browser keeps (in
IndexedDB): SDL's user:// there is in the page's memory, and everything saved in it went when
the page did (UPSTREAM.md). Save names are joined to the save folder with kag.saveDataFile(name),
which doesn't double the folder's slash.



● Options and the Config Screen

Since 0.17.0 the player's settings are declared once, in a table (template/system/Options.tjs),
and a Config screen lays its rows out from it: a game adds a setting without placing buttons
by hand, and Default and saving follow from the table. A game declares its own in AfterInit.tjs:

● Fonts and Text Styles

Since 0.22.0 a game lists its fonts once, in fonts.csv (the framework's in template/system; a
game's own in data/main takes its place), a font a line, its columns separated by tabs:

    Noto Serif JP	notoserifjp-subset.otf	message heading	*	Noto Serif JP	SIL Open Font License 1.1

  face       the name face lists use
  file       a font file the game ships, registered under face at start-up (empty: a font the
             system or the engine has, used where it's there)
  roles      what it's for: message, interface, heading, number (separated by spaces; * all)
  languages  the language codes it covers (* all)
  caption    its name for the player: Config's Text page offers the message fonts with one
  licence    its licence, which About lists (empty: a system font, nothing to show)

the file's order, then Roboto (the engine always has it): KAGFontFace(role, lang). The message
windows' default face (Config.tjs's userFace) still wins where it's set; the Yes/No prompts and

KAGFontLicences() what About shows. The sample adds Noto Serif JP, cut down to the characters its
text uses (tools/assets/make_fonts.py: run it again after adding text with new characters;
--check lists the ones missing).

so restyling or translating a screen is a change in the table. The framework's are "default" and
"dialog" ("dialog.title", "dialog.line", "dialog.small", "dialog.text"); a game adds its own in
textstyles.tjs (data/main), read on first use:

    KAGDefineTextStyle("slot.date", %[ size:32, color:0x5c4cb4 ]);

A style "a.b" starts from "default", takes "a"'s settings, then its own (parent= names another to
start from). Its settings: role (interface), face (a face list in place of the role's), size (24),
bold, italic, color (0xffffff), align (left, center, right), valign (top, middle, bottom), lines
(1), lineSpacing (4), fit (true: shrinks down to minSize (12) to fit), ellipsis ("…": what ends a
text cut to fit), edge, edgeColor, edgeExtent, edgeEmphasis, shadow, shadowColor, shadowOffsetX,
shadowOffsetY, gradColor, edgeGradColor, shadowGradColor, gradDir (as [font]'s, below).

  KAGDrawStyledText(layer, style, text, x, y, w, h, changes)   Draws text inside a rectangle of
                       layer in a style (its name or a dictionary), aligned, wrapped (Latin words

                       dictionary) overrides some settings for this text (a hovered row's

● The Glossary

Since 0.22.0 the words the story explains (a place, a gadget, a piece of jargon) are marked where
the message window draws them: in the glossary's colour, underlined. A click or a tap on one,
while the game waits for a click, shows its entry as a card without going on, and a tip names it
under the pointer. The table is terms.csv (data/main; a language's own in lang/<code>/), a term a
line, separated by tabs (template/system/Glossary.tjs):

    world	World|Worlds	The World	The part of KAGEX that keeps the scene ...

  id      the term's name for scripts and the system variables, the same in every language
  words   what marks it in the text, separated by |, as written (case too); in a language with

  title   its entry's title
  text    the entry (\n: a new line)

(the scene player), so a translation is marked by its own table and a page drawn again in another

  KAGGlossary.show(id)               Its card.
  KAGGlossary.find(text, words)      Where the terms are in a text: [ start, end, id ] by start.
  MessageLayer.termAt(x, y)          The term at a place in a message window.

The sample marks KAGEX, the World and Pip (and their Japanese), and its Extras has a fifth tab,

● Text Effects

The sample's Text Effects demo (data/scenario/text.ks, since 0.23.0) shows, a page each, what a
message window does with its text: colour, size, weight and slant, another font ([font face=]),
outlines and shadows, gradients, ruby, pictures in a line ([graph char=false]: a picture as it is;
char=true, the default, draws its shape in the text's colour), alignment, letter and line
spacing ([style align= pitch= linespacing=]), indents, speed and pauses ([delay], [nowait],
[wait], [l] in the middle of a line), characters that move and come in (below), a name shown as
another for a line (【ai/A Voice】), [emb], the glossary's marks, a window style ([env
msgstyle=]) and vertical text.

Characters that move (since 0.23.0): the characters drawn after these keep moving while the page
shows, until [resetfont]:

    [font anim=wave]rolls like the sea[resetfont]
    [font anim=shake animsize=6 color=0xff9090]Eek![resetfont]
    [font appear=drop anim=wave]comes in, then keeps moving[resetfont]

  anim         shake (each character jumps about), wave (a wave runs along them), pulse (they
               fade and come back, one after another), rainbow (each runs through the colours);
               none or "" stops (default: [deffont anim=]'s)
  animsize     how far a shake or a wave goes, in px (default: a sixth of the size for a wave,
               a fourteenth for a shake)
  animspeed    how fast (1: the motion's own)
  appear       how each character comes in as it's drawn: fade, rise (from below), drop (from
               above), slide (from the right), over appeartime ms (400)

[deffont anim= appear=] sets them for the window. Each such character is drawn on a small layer of
its own over where it would have been drawn (a rainbow's once in each of its twelve colours,
side by side, the layer showing one at a time); [backlay] copies them to the back page, so a
transition keeps them. Reduce Motion (Config) holds them still and brings them in at once, and
skipping brings them in at once. Vertical text doesn't move. The history shows the text plainly.

Vertical text ([position vertical=true]): since 0.23.0 it lays out on the SDL engines too.
KAG put one "@" before the window's face, which since 0.0.x is a list, and the engine found no
font for "@Noto Sans JP,Roboto": every character was the icon font's arrow, 0 wide, drawn on the
last. KAGVerticalFace(list) puts it before each face (KAGHorizontalFace takes it off again, for
[hch]). The SDL engines draw a vertical face's characters upright from the point given, as
horizontal text, not as Windows GDI does (left of it), which KAG was written for:
KAGVerticalUpright(window) finds out which once, and on such an engine each character is centred
on its line, the full stop and the comma go to the top right of their cell (KAGVerticalCorner)
and brackets and dashes are drawn turned a quarter (KAGVerticalTurned), as vertical forms are.

A [style] given before a line's text in a line mode outlives the clear before the text, as a
[font] has since 0.22.0 (kag.clearForLine re-applies both). In Japanese and Chinese a character
that may not start a line (。、」...) isn't broken before in the middle of a line: it hangs into
the margin, as KAG's own wrap lets it (the text after an [emb] is a piece of its own, and the
line breaker put its 。 at the start of the next line).

● The Flowchart

Since 0.24.0 the framework draws a game's compiled scenes as a chart: a node for each scene with
a title of its own (*label|Title; a scene without one belongs to the node before it), lines for
what the compiler found each goes on to (a jump, the next scene, a choice, and dashed, a jump that
may not happen: [jump cond=], a jump inside [if]), and a mark beside a node for a jump back to
one on the way there (a demo going back to its menu). The scenes the player has read are drawn
and can be played; the others are "?". The first time the story enters a node (not while a seek
or a replay plays its way there) the game keeps a copy of its flags (f) in sf.chartFlags, marks
it new and notes it as the story's place; playing a node from the chart puts those flags back
first, so a later scene finds the choices made (template/system/Flowchart.tjs).

flowchart.csv (optional: data/main in the sample) names and places them, a line each:

    Script,Label,Caption,Chapter,Column,Row,Unlock
    s0001,start,Demo Menu
    char,,,Characters

  Script, Label  the scene (Label empty: every node of the script, for a Chapter)
  Caption        what the node says in place of its scene's title (through tr())
  Chapter        a name drawn over the first node of it
  Column, Row    where the node goes on the grid (empty: laid out by the chart, a branch to a row)
  Unlock         a TJS expression: while it's true the node plays before it's been read

  KAGChartData()            the chart: nodes (id, storage, label, title, caption, chapter, x, y,

  KAGChartView              the chart on a layer: a drag moves it (a flick coasts), the wheel or a
                            pinch zooms, the arrow keys (a controller's D-pad) go to the nearest

● The Music Playing

KAGNowPlaying (template/system/MusicPlayer.tjs, since 0.24.0) is a panel for a music room: a
picture that turns while the music plays (picture: a record; still with Reduce Motion), the
track's title (titleOf), how far it has played of how long, and a bar that seeks: a click or a
drag on it, or the left and right keys five seconds at a time. bufferOf gives the sound buffer
(kag.bgm's by default); on a message layer, addLinkLayer makes it a link. It reads a buffer's
times only while it plays or is paused: an empty buffer's times kill the engine (UPSTREAM.md 49).

Since 0.25.0 the bar and the time follow a clock set from the buffer's position (the engine's
position moves in blocks of samples, and is a buffer ahead for about half a second after a seek
or a loop, which made the knob shake): set again when the track, the buffer or its pausing
changes, at a jump, or when the two stay apart (driftLimit, driftTime). A click on the picture,
Space or Return pauses the music and plays it on (togglePause, paused; onPause(paused) tells the
game), with a pause mark over the picture; a level meter under the times (meter,
meterSegments) reads WaveSoundBuffer.getSoundLevel while the music plays.

The sample's music room: Play turns to Pause while a track plays; One (the track again), In
Order (the list's tracks in turn) and Shuffle (any other at random) say what comes next. Its
Music view shows every track or a playlist (three, sf.musicPlaylists, picked with the arrows
above the list): with every track shown, a row's 1, 2 and 3 put the track in those playlists
(or the keys 1, 2, 3); in a playlist, a handle puts its tracks in order. A track plays on
through the list it was picked from.

  When    conditions separated by spaces, all true: morning (5:00 to 11:59), afternoon (to
          16:59), evening (to 20:59), night, weekend, date:MM-DD, first (the first start in this
          save folder), back (after 3 days away or more; back:N), any, exp:<a TJS expression>
          (last: the rest of the field)
  Text    the line, through tr(); %name% is KAGGreetingNameOf()'s (f.name; the sample's: the name
          the player gave), and a line with it is left out while there's none
  Voice   a sound with it (optional); Weight how often among its equals (1)
  Who     who says it (since 0.25.0): only while KAGGreetingGreeter() names them; empty, anyone

The lines that hold with the most conditions win (first, back and a date count ten times as
much; the greeter's own lines win over anyone's with as many), one of them at random, the same
for the rest of the run: KAGGreeting() gives %[ text, voice, who ], KAGGreetingText(g) the text
as shown, KAGGreetingAgain() picks again (after the greeter changes, without counting the visit
again). The sample's greeter is Config's Title Greeting: Ai, in a bubble beside her, Pip, on the
road below his bubble with his lines spoken (babble: tools/assets/make_pip.py greet and title,
data/voice/pipgreet*.ogg, data/image/title_pip.png), or no one.

● Sprite Mode

Template/system/SpriteMode.tjs (since 0.24.0) is what a character viewer needs: the World's

stage shows, and a right-click or the button in the corner brings it back. The panel and the
World change between [begintrans] and [endtrans], so they fade in as one.

● CG Variations From One Layered File

A CG often comes in variations, one layered file with some of its layers shown: the same scene in
the evening, with another face, with a hat. Template/system/CGVariations.tjs (since 0.26.0) puts
such a picture together from the file as it's shown, so the game ships the file once rather than
a flat picture for every variation. Each variation has a name of its own, listed in
cgvariations.txt (tab-separated, # comments):

  # name         file (or a variation)   what changes from the file's own visibility
  pipcg_day      pipcg                   !Sky/Day, Sun, Clouds, !Arms/Wave, !Faces/Smile
  pipcg_laugh    pipcg_day               !Arms/Cheer, !Faces/Laugh

The name is a picture's name wherever a script loads one: [image storage=pipcg_day], [EV
file=pipcg_day], [newlay file=pipcg_day], a stage's image, imagenamemap.txt's replacements
and cglist.csv, so the gallery shows it and sf["cg_PIPCG_DAY"] marks it seen, each
variation by its own name. The file is the layered file without its extension: <file>.txt,
psdlayer.tjs's layer structure with a picture per layer (<file>_<layer id>, in any image format),
which is what kagex-release splits a .psd or .clip into, so a release reads it on every platform;
else <file>.psd or <file>.clip itself, through the psdfile or clipfile plugin (the desktop
engines). In its place the name of another variation starts from that one's layers, its own
changes after. The changes, in order, separated by commas:

  <layer>       shown, with the folders it's in; a folder is shown with everything in it. A
                name, a folder's name, or a path from the top (<folder>/<layer>), which tells
                apart layers of one name in different folders
  !<layer>      the same, and the others in its folder hidden (one face of several)
  -<layer>      hidden; a folder with everything in it
  *             everything hidden first

Everything else keeps the file's own visibility. A name the file has no layer or folder for is
an error that names it. The picture is put together when a layer loads it (KAG and World layers
alike), in some tens of milliseconds for a 1920x1080 picture of thirty layers. The file's layers
are kept for ten seconds after the last picture drawn from it (KAGCGVariationLinger, in ms; 0
keeps them), so a gallery's tiles and its viewer read it once, and the layers don't stay in
memory for the rest of the game. Scripts load one into a plain Layer through

  KAGLoadPicture(layer, name)     a variation, or the image of that name (loadImages)
  KAGCGVariation(name)            the variation of that name, %[ name, file, layers ], or void
  KAGCGVariationNames()           every variation's name

The sample's Animated Character demo shows four, pipcg_day, pipcg_laugh, pipcg_evening and
pipcg_night, made of data/evimage/pipcg.txt and its pictures (tools/assets/make_pip.py cg), which
are one tile in the gallery.

A CG drawn as whole pictures, one for each variation, is kept smaller by kagex-release (since
0.27.0; its README, "Media", CG pieces): in the CG folders (evimage by default) a picture that is
the first of its run with a little changed (a face, an arm) ships as the rectangle that differs,
and the release's cgpieces.txt says where it goes (tab-separated, # comments):

  # name     base      x     y
  ev01b      ev01a     812   236

The picture of that name is then the base (a picture, a variation or a piece itself) with the
file <name>, which holds only the rectangle, drawn over it at x, y. It's put together wherever a
variation would be (KAG and World layers, KAGLoadPicture), so the scripts name ev01b as before.
Scripts of a game's own that load a CG into a plain Layer with loadImages get only the rectangle in
a release: load it with KAGLoadPicture. A patch or DLC (KAGMountPatchZip) that brings a
cgpieces.txt or a cgvariations.txt has its tables read again.

  KAGCGPiece(name)                the piece of that name, %[ base, x, y ], or void

● The Manual

Template/system/Manual.tjs (since 0.26.0) shows a manual in the game window, on every platform:
pages of help with links between them, Back and Forward, and links that change a setting there
and then or open a screen. Help > Contents opens it, as do the action "manual" (F1, unless the
game binds F1 to something else) and KAGShowManual(page) from a script or a button
(exp="KAGShowManual()"). Every game gets the framework's pages (template/system/kagexmanual_*.txt,
in English, Japanese and Chinese): an index, the controls, saving and loading, the settings, and answers
for a game that's slow, a picture stretched or blurry, no sound, movies that don't play, and
making the game easier to see, hear and play, and getting help. KAGManualEnabled = false turns
it off (Help > Contents then opens helpFile, as before).

A page is a text file found by its name: the game's manual_<page>.txt (a language's own in
data/lang/<code>/, as its pictures), else the framework's kagexmanual_<page>_<language>.txt,
then kagexmanual_<page>.txt. So a game adds pages, and puts its own in place of the framework's
(manual_index.txt for its first page, manual_support.txt with its own address). A page's lines:

  # The page's title             its first line
  ## A heading
  A paragraph: lines that follow each other make one; a blank line ends it.
  - an item of a list
  > a note, in a box
  ---                            a rule across the page
  ; a comment

and in the text:

  [what it says](where it goes)  a link:
      <page>, page:<page>          another page
      option:<name>=<value>        an option (Options.tjs) set there and then, with a box before
                                   it that's filled while the option has that value: rows of
                                   them work as Config's buttons do
      action:<name>                the manual closes and the action is done: one of Actions.tjs,
                                   an option's button by its name (padTest), controls or about
      url:<address>                opened in the browser where the engine can, else copied
      copy:<text>                  copied to the clipboard
  {title} {version}              the game's title and version (sf.software_title, _version)
  {engine} {platform}            the engine's version, and Windows, Linux, macOS, Android, iOS or
                                 a web browser
  {savefolder} {screenshots}     where the saves and the screenshots go
  {key:<action>}                 the keys, controller buttons and gestures that do an action now
  {option:<name>}                an option's value now, as Config shows it
  \[ \] \{ \} \\                 the character itself

A link this platform can't follow (an option it hasn't, a screen the game hasn't) shows as text.

The keys: up and down move between the links and scroll, Return or A follows one, left or
Backspace goes back, right forward, Page Up and Page Down scroll, Home goes to the index, Esc or
B closes it. The wheel, a drag and the scroll bar scroll; a click follows a link; a right-click
goes back, or closes it on its first page. Screen readers get the page as headings, paragraphs
and links (an option's as a checkbox). Its colours are KAGManualTheme's, its text styles
"manual.title", "manual.heading", "manual.text" and "manual.button" (Fonts.tjs).

The sample's manual adds a page about its demos and its own support page, and Config has a Manual
button under its panels.

● Debug Helpers

Template/system/DebugTools.tjs (since 0.26.0) helps a game's writers and its tests. Its Debug
menu items (the Debug menu shows in debug mode: debugMenu.visible in Config.tjs) come after the
framework's own:

  Restart This Script       the script the game is in, from its top
  Go to a Line ...          the script's lines with text (a compiled script's, each with its
                            line number, speaker and text; a script KAG plays, its labels) in the
                            manual's viewer: a link plays from that line (player.seek)
  Flags ...                 the game's flags (f., sf., tf.) with their values, in the manual's
                            viewer; the ones flaglist.txt lists come first, with what they are and
                            links that set them to the values it offers (tab-separated: the flag,
                            what it is, the values by commas), and true and false for the others
  Copy the Voice's File Name, Copy Where the Game Is
                            to the clipboard: the voice of the line shown; the script, line,
                            label, speaker and text
  Write a Bug Report        bugreport-<date>.txt in the save folder (the game, the engine, where
                            it is, the voice, the language, every f. and sf. flag, the World's
                            objects and the log's last 200 lines) and bugreport-<date>.png (the
                            screen); its path is copied
  Trace Tags in the Log     every tag the main conductor runs, with where, its attributes, what
                            its handler returned and how long it took (KAGDebugTrace)
  Layers and World into the Log
                            the layers shown, as a tree, and the World's objects (KAGDebugLayers,
                            KAGDebugWorld)

-allseen=yes on the command line makes every CG, scene, song and movie count as seen for that run
(tf.allseen, which isn't saved; not in a signed build). -instance=<name> gives the run a
single-instance lock of its own, so several copies of a game can run at once (for tests).

KAGPlaytest plays a route on its own: KAGPlaytest.start(%[ storage, label, choices, skip, until,
stuck, timeout ]) plays from the script (and label), skipping read and unread text alike unless
skip is false, clicking on at every wait, answering a Yes/No prompt Yes, taking choices[n] at the
n-th choice (the first option past the list) and stopping at until (a script, once it has left
the first one), or as "stuck" when nothing has moved for stuck ms (20000), or after timeout ms.
KAGPlaytest.report() says what happened in one line: status|where|choices taken as
picked/options|ms|message.

tools/playtest.py runs a game's routes with it, each in a game of its own (headless on Linux, its
own save folder and log), and reports each one: done, stuck, or the first script error with its
trace (the engine's "Script exception raised" or KAG's "A fatal error has occurred", which names
the script, line and tag):

  python3 tools/playtest.py --start char.ks --until s0001.ks --all --jobs 2
  route 1: done    choices 0/2      9.7 s  at s0001.ks:3
  route 2: done    choices 1/2      9.0 s  at s0001.ks:3

--choices 1,0 plays one route; --all plays every one, the first without choices given, then for
each choice a route made one route for each of its other options (--max-routes stops it); --jobs
runs that many at once. Its exit code is the number of routes that failed.

● Typing on Phones

A phone has no keyboard until something asks for one, and the engine asks for its own text boxes
only, so an [edit] field took no text on Android, nor in a phone's browser (since 0.18.1,
template/system/TextEntry.tjs):

  On Android and iOS without a keyboard plugged in, tapping an [edit] field (or Return, a pad's
  A, on it) opens a box of the engine's at the top of the screen, above the system's keyboard,
  with the field's text selected: what's typed shows in the field as it's typed, OK or the
  keyboard's Enter keeps it and runs the field's enter=, and Cancel, Back or Esc puts back what
  was there. Its title is the field's prompt=, through tr():

    [edit name="tf.heroGiven" prompt="Given Name" maxchars=12 enter="nameOK()"]

  KAGTextEntryMode is "auto" (that), true (the box everywhere, to try it on a desktop) or false.

  In a phone's or tablet's browser, the page's script (kagex-web.js) does it: a tap on an [edit]

● Fields of Several Lines, and Asking for Text

Since 0.28.1 an [edit] field can hold several lines, wrapped to its width (template/system/
EditLayer.tjs):

    [edit name="tf.note" multiline=true rows=4 maxlines=6 maxchars=300 length=700]

  multiline  true: Return makes a new line (Ctrl+Return runs enter=), Up, Down, Page Up and Page
             Down move by rows, Home and End go to a row's ends, a click places the cursor, and
             the field scrolls (a mark at its right shows where) when the text has more rows
             than it shows.
  rows       The rows it shows (3); its height follows from them and the font.
  maxlines   The most lines Return may make (none by default); maxchars still counts characters.

The text has a "\n" between lines (a TJS string's new line). Words wrap at spaces, and a
Japanese or Chinese line anywhere, but not before 、。」 and the like. On a phone the field
takes the system's own keyboard in its multi-line mode while it has the focus (kagex's sdlsystem
plugin, SDLSystem.startTextInput), so Return there makes a new line too; in a
phone's browser the page types into a hidden <textarea>; where neither is there, the box above
gives the field a line to type in for each of its rows. Elements' own input_box is one line
(UPSTREAM.md 59), which is why the field is the framework's.

KAGAskText(message, initial, onDone, options) asks for text in the Yes/No prompts' look: the
message, a field and OK and Cancel. onDone(text, param) runs with what was typed on OK, and with
void on Cancel (Esc, a right-click); false comes back when it can't open (another dialog is).

  lines      The field's rows (3); 1 for a field of one line, where Return is OK.
  maxLines   The most lines; maxChars the most characters.
  ok         The OK button's label (through tr()).
  param      Handed to onDone (TJS functions have no closures).

    KAGAskText("What should the tea be called?", "", function(text) {
        if (text !== void) f.teaName = text;
    }, %[ lines:1, maxChars:20 ]);

● Games on Phones and in the Browser

Android and iOS run a game made for a desktop window, with these differences (since 0.21.0
this section collects them):

◇ The screen

The window fills the screen from the start: a switch to full screen changes nothing, and
Config's window sizes and the menu bar aren't offered there (Display.tjs, KAGIsDesktop). The
engine draws on a fixed 1920x1080 surface, scaled to fit the screen with bars where its shape
differs, and the window's inner size is always 1920x1080: a game whose screen (scWidth,
scHeight in Config.tjs) has another size is drawn shrunk, or only in part (UPSTREAM.md 48).
Make phone builds at 1920x1080; the framework logs a warning at start on Android and iOS when
the game's screen isn't that size. Don't pick a zoom for a phone: setZoom is for a desktop
window.

◇ Input

A phone has no right button, no keys and no wheel, and the pointer rests where the last tap
was (so tips by resting are off at first there: ● Tips). Everything the right button or Esc
does needs another way:

  Back (Android)     the game's Esc: closes the history, a panel, a prompt or a screen; on
                     the sample's title it asks whether to quit (krkrz_android's Back goes to
                     the engine as Escape through kagex's kit patch: UPSTREAM.md 46)
  Back (a browser)   the same, while there's something for Esc to do (kagex-web.js)
  two fingers (iOS)  a tap with two fingers is Esc (the engine's)
  a long press       gestureActions.hold, and a button's tip (● Actions, Rebinding and Gestures)
  swipes             gestureActions (up: the history, down: hide the window)
  the history        its close button, or its newest line pulled up past the end

A screen of the game's own needs a button that leaves it (the sample's all have one): the
smoke test leaves every screen with taps alone on Android, iOS and a phone's browser. [edit]
fields open a text box for the phone's keyboard (● Typing on Phones).

◇ Movies

[movie] plays <name>_sd where there is one (Movie Quality's Auto, ● Movies). On Android the
engine's movie player can lose a movie's sound (UPSTREAM.md 45): give each movie its sound as a
file of its own, <name>.opus or <name>.ogg beside it (for <name>_sd, <name>'s will do), and
there the movie plays muted with that file alongside, in step with the picture
(KAGMovieSoundPlatforms in Movies.tjs lists the platforms). ffmpeg copies a WebM's sound out as
it is:

    ffmpeg -i opening.webm -vn -c:a copy opening.opus

◇ The app

kagex-release names the app and gives it its icon, and makes the strip below the game (where
Android's navigation bar is) black rather than the theme's white (a themes.xml in the build's
res-override; the sample's is platform/android-res).

● Movies

    [movie storage=opening alpha=0 song=bgm01 color=0x000000 skip=seen fit=true layer=]

plays a movie as commercial games do (since 0.17.0, template/system/Movies.tjs): over everything
but the prompts, centred on a KAG layer (the last one, or layer=), and waits for it to end.

    storage   The movie, without its extension (.webm on the SDL engine).
    alpha     As [image movie=]: 0 opaque, 1 alpha below, 2 alpha to the right.
    color     A colour that fills the screen behind it.
    song      Music it plays, unlocked in the music room (sf["bgm_<NAME>"]; several with commas).
    skip      seen (the default): a click skips it only once it has been seen; always: any time.
    subtitle  false: no subtitles; a file: those instead of <name>.vtt.
    fit       true (the default): zoomed to fill the screen, keeping its shape; false: shown at
              its own size (since 0.17.2).

It's noted as seen (sf["movie:<name>"], KAGMovieSeen(name)) when it ends or is skipped. Skip
mode stops before a movie not seen yet, and passes a seen one where Config says so
(movieSkipping); the right button skips a seen one where it says so (movieRightClick). A
movie with a smaller version, <name>_sd, plays that when Movie Quality says Smaller, and by
itself on the web, Android and iOS (Auto), zoomed to fill the screen like any movie of another
size (the sample's opening_sd is 960x540, half the screen each way). On Android the first two
frames of a movie aren't shown (KAGMovieHideFirst, since 0.18.1): the opening glitched for a
frame as it started on a phone, whose decoder can change its picture format as its first frame
comes out. A movie that shows no picture in three seconds (no
decoder for it here), or whose picture stops for three seconds (since 0.17.2: the engine holds a
movie with sound at its first frame on a computer with no sound device, UPSTREAM.md 40), ends,
so the game goes on.

Subtitles: a movie on a layer whose [image] has subtitle=true ([movie] gives it that) shows the
cues of <name>.vtt (WebVTT: times and lines; a language's own in data/lang/<code>/ stands in for
it) at the bottom of the screen, timed from the movie, and screen readers get each one.
<name>_sd uses <name>.vtt when it has none of its own. Config's Subtitles turns them off.
[image movie=] takes fit=true too: the layers showing the movie are zoomed (affine layers) so its
frames fill the screen; [freeimage] puts the zoom back.

On the web (since 0.18.0) a movie inside an archive fetched from the site (the sample's
gamedata/data.xp3) is copied out of it into the page's memory before it opens
(KAGMovieOpenable, Utils.tjs, for [movie], [image movie=] and KAG's [video]): the engine's player
asked the server for it by a URL made from its archive path and got nothing (UPSTREAM.md 41), so
no such movie played there. A loose movie (kagex-release's files mode) streams from the site.



● Loudness

A table evens out the sounds' levels without re-recording them (since 0.18.0,
template/system/Loudness.tjs): loudness.csv has a gain in dB per kind of sound or per file, which
the engine applies as each Ogg Vorbis or Opus file is decoded (WaveSoundBuffer.
setGainQueryCallback), so a quiet voice can be raised past the volume's 100%:

    bgm            -4      every file in a bgm folder
    se             -2      in a sound (or se) folder
    voice          +1      in a voice folder
    voice:hiyori   +2.5    one speaker's voices (envinit.tjs's voiceFile patterns say whose)
    pip000009      +5      one file, with or without its extension: it wins over its kind

Lines starting with # are comments. KAGLoudness.set(key, dB) changes one while the game runs, for
the files opened after it, and KAGLoudness.gainOf(storage) says what a file gets. WAV files get
no gain. The sample's table (data/main/loudness.csv) brings its synthesized voices up to the
others (measured with EBU R128) and puts the music 4 dB under the voices.

kagex-release measures the sounds too (since 0.27.0; tools/release/README.md, "Media"): a build
with loudness.measure writes each sound's loudness into a report, and with loudness.targets it
adds a line to the release's loudness.csv for each sound far from its kind's target; kagex-release
--cli loudness prints the measurements without building.



● Interface Sounds

Every button, page turn, slider, prompt, choice and menu item can play its sound from one table
(since 0.18.0, template/system/InterfaceSounds.tjs), so changing the click for the whole game is
one line. uisounds.csv names a sound for each tag, <screen>.<part>.<event>:

    @click              ui_click     an alias: a file, and a system sound buffer if wanted
    *.click             @click       every click no other line names
    *.enter             ui_hover     the pointer, the keys or the pad reaching a button
    *.return.click      ui_cancel    every screen's Return button
    title.start.click   ui_ok
    config.config_*.click  ui_toggle  Config's switches
    dialog.open         none         a wildcard's sound taken back

Lines starting with # are comments; the columns are separated by tabs or spaces. A sound is a file
on the auto path (its extension may be left out), an @alias or none; a third column picks the
system sound buffer (0, the first, by default; numSysSEBuffers in Config.tjs). A * matches any
characters, dots too, and of the lines a tag matches the one with the most other characters wins
(of two as long, the later). A button's own sound (clickse=, enterse=, changese=, [selopt]'s and
the like) comes first: the table is asked only for parts without one. The tags:

    <screen>.<name>.click, .enter     [button] (its name=, else its picture's), [link] (name=,
                                      else link). <screen> is the scenario that made it, without
                                      its extension: title, config, save ...
    <screen>.<name>.change            a slider let go, a check box (their name=)
    message.<name>.click, .enter      [sysbutton]s
    dialog.open, dialog.<name>.click, .enter, dialog.skip.change
                                      Yes/No prompts (yes, no, and the "Don't ask again" box),
                                      About (close)
    choice.open, .enter, .click, .close   [select]'s choices
    backlog.open, .close, .prev.click, .next.click   the backlog
    menu.open, .enter, .click, .cancel    the menu bar's menus (in a window)
    controls.open, .close.click, .cancel  Help > Controls (an Elements screen's soundScreen)

KAGInterfaceSounds.play(tag) plays one from a script (KAGInterfaceSound(tag) is the same, and does
nothing in a framework without the table), soundOf(tag) says what it plays, set(tag, sound) and
alias(name, sound) change the table while the game runs (buttons made before keep what they had).
An .enter sound within enterQuiet (150) ms of another sound is left out: a click that redraws a
screen under the pointer, or a prompt that moves the pointer to its button, would play one. In
debug mode two sounds started within doubleTime (20) ms are logged, with where each came from:
that's usually one sound played twice. The sample's table is data/main/uisounds.csv, with sounds
from tools/assets/make_sounds.py.



● Reduce Motion

Config's Reduce Motion (the reduceMotion option, since 0.18.0; KAGReduceMotion() says whether it's
on) stops demanding animation, for slow machines, batteries and phones, and for players bothered
by motion:

    Effekseer effects    one played once ends at once (its efkdone goes, so a script waiting
                         goes on); a looping one shows nothing
    movies on layers     a looping one ([image movie=... loop]) pauses on its frame; one played
                         once, as [movie] plays them, plays as before
    alpha movies         a looping one stops on its frame
    the TV static        stops on its frame
    Live2D and 3D layers stop as they show, once a motion played once has ended
    actions              end where they'd end on the next frame; a looping one stops (since
                         0.19.0; kag.reduceMotionActions = false leaves them to the game)
    .asd animations      stay on their first frame, the click glyphs' too (since 0.19.0; a
                         layer's animReduceMotion = false keeps its own running)

Turned on while they play, they stop where they are; turned off, they move on. An [image] or a
World layer can name a picture to show in place of its animation while Reduce Motion is on:

    [image layer=1 flip=sparkle.efk still=sparkle_still]
    [newlay name=petals efk=petals still=petals_still show]

The picture is loaded instead of starting the animation, as an image of its own size; it stays
until the layer is drawn again. The sample's Effects demo has stills for its petals, sparkles
and magic circle (tools/assets/make_effects.py stills), and Config's last page has the switch.
Transitions are Screen Effects' (noeffect), not this option's.

● About Automatic Label Processing



◇ Overview



"Saving" in KAG is performed in units of "labels" explicitly attached by the user.



Reference:

  http://devdoc.kikyou.info/tvp/docs/kag3doc/contents/SaveLoad.html



In ADV type games, this restricts save points,

which is quite inconvenient for users.



In KAGEX, there is an "Automatic Label Mode", and enabling this allows saving

at every [p]. If line mode is enabled, this becomes effective at every

virtual [p].



Accordingly, read management is also not in units of normal simple labels,

but in units of labels + line count from the label, enabling fine-grained control.



Specify the following variables. Can be specified in Config.tjs.



 kag.autoLabelMode      Automatic Label Mode. Enabled with true.

 kag.autoLabelType      Specification of control type for Automatic Label Mode 0: call method 1: line number method

 

◇ call Method



　This is the autoLabelMode in old KAGEX.

  It is a method of labeling by calling call processing at every [p].



　Due to the process of returning from the call recorded in this mode, the check for

　restoration processing is strict, and restoration of saved data when scenario data

　is rewritten is harder to guarantee than with labels. Please be careful.



◇ Line Number Method



  This is a new method. By modifying KAG's load processing and execution system,

　information is recorded by the nearby label and the skip processing by line count

　from there.



　・Since it does not go through call, there is a high possibility of restoration even when information shifts.

　・Errors due to file modification during scripting work do not occur.

　

　It has such features. Basically, it is recommended to use this for new projects.



　Note that when using this mode, saving as a label is the same as when autoLabelMode = false,

  so by manually placing savable labels at key points in the scenario file,

　it is possible to use "Return to previous label" and "Proceed to next label"

　via the "Automatic Label Save" of the debug menu.



● About Voice Parse Function



◇ Overview



An application of line mode extension, this allows voice number assignment to be processed

according to the absolute position in the file rather than by the flow of the scenario.

It has the merit that the file number specification does not change even if there is branching in the scenario.



◇ Specification Method



[parse voice=1]



All commands after this instruction are parsed in advance,

and dedicated voice processing is embedded. The handling of voice differs.



・The character voice specification function is always overwritten, so it becomes meaningless.

・Use the following special voice specifications:



// Voice number specification

[voice name=CharName voice=123]



// Voice complete stop (specify a negative number)

[voice name=CharName voice=-1]



// Voice single-shot ignore

[voice name=CharName ignore]



// Voice single-shot ignore replacement

[voice name=CharName ignore replace]



// Voice single-shot interrupt

[voice name=CharName voice=VOICE123]



// Voice single-shot interrupt (in case of number)

[voice name=CharName voice=123 once]



// Voice single-shot replacement

[voice name=CharName voice=VOICE123 replace]



// Voice single-shot interrupt (in case of number)

[voice name=CharName voice=123 replace]
