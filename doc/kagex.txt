Title: About Kirikiri/KAGEX

Author: Limited Partnership Wamsoft, Tsuyoshi Watanabe



● Kirikiri/KAGEX Overview



This is a system that largely extends Kirikiri/KAG, mainly in terms of layer functionality.



・Layer rotation and scaling processing

・Processing for layer stacking level control

・Layer automatic action processing



The basic concept of the system remains the same as Kirikiri/KAG, and basic functions

are maintained as they are. Before reading this document, please understand the

entirety of KAG first.



For details on KAG, please refer to



 http://devdoc.kikyou.info/tvp/docs/kag3doc/contents/



.



● Notices



fadepausebgm/setbgmlabel/clearbgmlabel/setbgmstop/clearbgmstop 

timeout/ctimeout/click/cclick/wheel/cwheel have been integrated into KAG.



The origin rule for Affine transformation processing has changed.

In the current system, rotation center = layer origin.

To use the traditional layout, you need to set afx, afy to center

and shift the display coordinates by that amount.

● Explanation of Extensions



◇ Control System Extensions



◆ Wait Commands General (Extension)



For wait commands where the wait parameter is specified, after the standard wait action,

the system waits for the additional specified "time".

If the action is cancelled by a click, this additional wait does not occur.



Attributes

	wait	Additional wait specification (in ms)



* This extension is invalid for wait, wd, waituntil



◆ Wait-Enabled Commands General (Extension)



Attributes have been added to automatically execute a wait action for commands

that have a corresponding wait behavior.



Attributes

	sync	Execute wait

	wait	Additional wait specification (in ms)



Supported commands



 quake, animstart, trans, move, action, 

 fadeinbgm, fadeoutbgm, fadepausebgm, fadebgm, xchgbgm, 

 fadeinse, fadeoutse, fadese,

 playvideo



◆ Commands General (Extension)



Commands with the delayrun parameter specified are executed with a delay during wait processing.



Attributes

	delayrun    Delay parameter specification

				Number: Executed after a delay of the specified time (in ms) or more

                String: Executed at the timing of the corresponding label in BGM/SE



Delayed execution is cancelled (executed immediately at that point) before page break processing

by lineMode (after waiting for a click) or by the [delaydone] command.



◆ delaydone (New)



Forcibly executes all commands whose execution is currently delayed.



◆ delaycancel (New)



Cancels all commands whose execution is currently delayed.



◆ wd (New)



Delay wait. Waits until the corresponding label in BGM/SE is passed.

If the label has already been passed, it is ignored.



Attributes

	name	Wait label

	canskip If skippable, true



◆ td (New)



Delay execution label registration. Manually registers labels for delay processing

separately from BGM/SE labels.



Attributes

	Can register arbitrary labels in the form of LabelName=DelayTime.



◆ waituntil (New)



Functionally equivalent to the until parameter of waittag.

However, if clicked even once, the time origin of resetwait is cleared and

subsequent waituntil commands are invalidated.



◆ showwait (New)



Test command. Logs the difference from the time origin at the moment the command is executed.



◆ set (New)



Sets a variable.



Attributes

	name	Variable name tf.* f.* sf.*

	value	Value (treated as a string)



◆ func (New)



Calls a TJS function.



Attributes

	name	Global function name

	others	Parameters are passed to the function's first argument as a dictionary.



◇ Layer Extensions



◆ Non-primary layer status of the base layer



In KAGEX, the base layer is no longer Window.primaryLayer.

Please be careful.



◆ Introduction of the level concept to foreground layers



Original KAG foreground layers have a display order based on numerical order.

KAGEX introduces the concept of "levels", and display order is determined by level units.



・Layer groups with smaller levels are displayed underneath.

  -> Controllable via the laylevel command.



・Display control for "frontmost" and "backmost" is possible within the same level.

  -> Controllable via layfront / layback commands.

the following attributes can now be used.



color, storage, tile, flip are exclusive and valid in this order.

	Optional parameters for efk (Effekseer effects, template/system/GFX_Effekseer.tjs)

		The krkreffekseer plugin draws the effect with OpenGL ES into a canvas that is

		read back into the layer every frame. The effect sits at the canvas centre.

		The layer is drawn additively: ltAlpha and ltOpaque, which can't show an effect,

		become ltAdditive; other blend modes given with mode= are kept.

		            that fills the screen over time can start full.

		efky        Vertical position from the canvas centre, in pixels (down is +).

		efkrot      Rotation in the screen plane, in degrees (clockwise).

		            names from its effect.json work in place of the indexes.

		efktrigger  Sends triggers (index[,index...]) to the effect, once.

		efkstop     Stops making particles; the flip ends once the last one is gone.

		loop        Plays the effect again each time it ends (until efkstop).

		The krkrthreepp plugin (threepp, a C++ port of three.js) draws with OpenGL ES into a

	Optional parameters for static (TV static, template/system/GFX_Static.tjs)



		Moving static for a broken screen, a bad signal or a memory breaking up:

◆ Overview of Extensions



To be convenient for creating ADV style games,

writing rules have been extended, and it is possible to assign automatic processing

◆ Line breaking



English text (and any language with spaces between its words: KAGLanguage.wordWrap) breaks
between words, not in the middle of one: the word wrap follows each scenario line as it's
drawn, its tags taken out and [r] as a new line, so lines that start with a tag or a tab, have
[r] in them, or go on to the next page wrap the same way. The space a line breaks at isn't
drawn. Where krkr_richtext draws the message window (useRichText), the breaks come from its line
breaker (RichText.ParagraphLayout, the one its StyledLayout uses), which lays out the whole line
at once, as Config.tjs's lineBreakStrategy says:


    ;lineBreakStrategy = "quality";


  quality     Evens out ragged lines (minikin's HIGH_QUALITY: the last line can be short).
  balanced    Makes the lines of a passage about the same length.
  greedy      Fills each line as far as it goes.


The rest of a line already begun (text that carries on after an earlier line of the script) is
filled as far as it goes, then the remaining text is laid out. The plan is made again where the
text goes somewhere it didn't expect (a new page, [r], another font), and text the line doesn't
have ([emb], [ch], a macro) ends it for the rest of the line. Without krkr_richtext (the browser
and iOS builds), and as a check on the plan, each word that won't fit on the line goes to the
next one. The history log wraps by its own width, a word at a time.

Japanese and Chinese (no spaces between words) break where the same line breaker plans,
filling each line as far as it goes (lineBreakStrategy is for text with spaces). It follows the
Unicode rules with the language's: a closing bracket, a full stop, a comma or a small kana
doesn't start a line, and a word in Latin letters isn't split. Where KAG let such a character
hang into the margin at the end of the line (marginRCh), the line breaker takes the character
before it to the next line, so the margin stays empty. Without krkr_richtext, and in vertical
text, they keep KAG's own character wrap with its kinsoku, which also catches a line that runs
too long. Text that isn't the line's ([emb], a macro) leaves the rest of the line to KAG's wrap.

Where krkr_richtext draws the message window, the characters of a line are drawn together, as
its line breaker lays them out: each time the text stops (after every character at the usual
speed, once a line when it comes all at once), the line so far is laid out again (its
StyledLayout) and drawn whole. So the characters are kerned and shaped together (ligatures,
accents and emoji sequences made of several characters) and placed to a fraction of a pixel.
It's on unless Config.tjs says otherwise:


    ;useStyledLayout = true;


KAG still places each character and times it, so the text speed, waits, links and the word wrap
are as before: a run of characters is one font and colour on one line, and a character with
ruby is a run of its own, with KAG's ruby (rubySize, rubyOffset) over it. Vertical text, a
pitch ([style pitch]) and the character fade (hasChFadeLayer) draw a character at a time.

● Languages


A game can be shown in more than one language, and the player can switch between them while
playing: F9, the controller's L2 (VK_PAD7) or a button of the game's (the sample's Config
screen has one) draws the message on screen, the choices on show and the screen on show again
in the other language. The backlog keeps each line in the language it was shown in.

The story is in the compiled scenarios (doc/scn.txt), as in Wamsoft's multi-language games:
each script's translations are compiled into its .scn file with it, so one file holds every
language's text, speakers' names, choices and scene titles, and the scene player shows the
language shown. The interface (the screens' images with words on them, the prompts and labels
the screens draw) is in each language's folder.


◇ Setting up


Config.tjs lists the languages, the one the scenarios and scripts are written in (the source
language) first:


    ;global.KAGLanguageList = "en,ja";


With one language (the template's "en") nothing changes. Each other language has a folder,
data/lang/<code>/ (lang/ja/ for Japanese):


    lang/ja/scenario/   The scripts in !scnlist.txt, translated (◇ Translating the story)
    lang/ja/lang.json   The interface strings (◇ The interface strings)
    lang/ja/...         Anything else found by name, in that language: the screens' images
                        with words on them (the sample's data/lang/ja/ has the Japanese title
                        buttons, Config screen and the like, drawn by tools/assets/make_ui.py
                        --lang ja), a CSV, a voice


The folder (not its scenario/ folder) is on the search path while the game shows that
language, after every other path: a file in it stands in for the file of the same name
anywhere else. The image cache keys on the name a script loads, so a switch empties it
(System.clearGraphicCache). A zip patch (patch.zip and on, or DLC through KAGMountPatchZip)
can carry lang/<code>/ folders of its own, which join the language's.


◇ Translating the story


A script's translation is a copy of the script with its text in the other language, in
lang/<code>/scenario/ under the script's file name: lang/ja/scenario/char.ks for char.ks. Only
its text is used: the messages, the display names after a slash (【ai/？？？】), the choices'
text ([seladd text=...]) and the scene titles (*label|Title). Everything else comes from the
script, so the translation keeps the script's labels, tags and messages, in the same order,
each said by the same character; where a tag splits a message ([emb], a World tag) the
translation is split by it too. Line breaks ([r]), ruby and font commands can differ.


    char.ks                                    lang/ja/scenario/char.ks

    *start|Start                               *start|スタート
    [ai standard center]                       [ai standard center]
    【ai】If a voice number is specified...     【ai】ボイス番号が指定されていると...
    【ai/???】To change the display name...    【ai/？？？】表示名を変更する場合は...


The compiler (SceneParser.tjs) compiles each translation with its script and matches them
scene by scene, then text by text and choice by choice. A scene that doesn't match (another
number of texts or choices, a text said by someone else) shows the script's own text in that
language, as does a script without a translation; the compiler says so (a warning in the log,
or kagex-release's compile-scenarios.log). Changing a translation compiles its script again.
A release leaves the translations out with the scripts (tools/release/README.md).

A speaker's displayed name, when the line gives none, is the character's nameAlias in
envinit.tjs, which can be a dictionary by language (the source language's stands in for a
language it lacks):


    "ai" => %[ "nameAlias" => %[ "en" => "Ai", "ja" => "あい" ], ... ],


Scripts KAG plays itself (the title screen, the system screens, a script not in !scnlist.txt,
or any with -scnplay=no) are shown as written, with the source language's names.


◇ The interface strings


lang/<code>/lang.json, JSON in UTF-8 (or UTF-16, with or without a BOM), holds the strings the
screens draw at run time (tr(), below), keyed by the source text; a string it doesn't have is
shown as written.


    {
      "name": "日本語",
      "strings": { "Load this save?": "このデータをロードしますか？", "Characters": "キャラクタ" },
      "wordWrap": false
    }


  name      The language's name in itself.
  strings   Prompts, labels and messages, looked up as written, then without spaces at their
            ends.
  wordWrap  Whether the story's lines break between words (true) or anywhere, with KAG's
            line-breaking rules (false). Default: false for Japanese and Chinese, true
            otherwise.


The framework's own strings (the Yes/No prompts, Yes and No, About, the backlog's "Choice:
%s") are in system/kagex_<code>.json, which the game's table can change. A save slot shows the
title of the scene it was saved in, in the language shown: a compiled scene's own title, or
for a script KAG plays itself its title through the strings (getBookMarkPageName).


◇ Which language


Until the player chooses one, the game shows the language the system prefers: the engine's UI
language (System.uiLanguage, the system locale or -language=), then
System.uiLanguageCandidates, then the source language. The player's choice is saved with the
system variables (scflags.language) and wins from then on.


◇ Script interface


  KAGLanguage.current           The language shown.
  KAGLanguage.list              The languages, the source language first.
  KAGLanguage.available         Whether there's more than one.
  KAGLanguage.nameOf(code)      A language's name in itself.
  kag.setLanguage(code)         The player's choice: saved, and shown now, or at the next
                                click wait when text is still being drawn (not while a Yes/No
                                prompt is open).
  kag.switchLanguageByKey()     The next language (F9, L2).
  kag.languageChangeHook        Functions called (code, previous) once the game is drawn in
                                another language: draw the screen on show again here (the
                                sample runs the label that draws it, redisplayScreen in
                                Override.tjs).
  tr(text)                      An interface string in the language shown (its strings).
  KAGLanguage.ui(text[, lang])  The same, in the language given.
  scnTitleIn(scene[, lang]), scnTitles(scene)
                                A compiled scene's title in a language, and in every one by

The message window records what each page draws (MessageLayer.redrawTextEnabled, on when
there's more than one language), with each compiled text and the speaker's name in every
language, and draws the page again from that record in the new language
(MessageLayer.redrawTextIn). A message layer with buttons or links on it isn't drawn again:
the screen it belongs to is (languageChangeHook). The system buttons ([sysbutton]) load their
images again by name.



● The Interface



The SDL engine has no menu bar and no native dialogs, so the framework draws its own in the
game window, which the mouse, the keyboard, a controller and a screen reader all work: the menu
bar (in a window), the controls list, the Yes/No prompts and About. The menu bar and the
controls list are drawn with the engine's Elements UI (ElementsDialog, ElementsPanel) in the
dialogs' look; where the engine has no Elements UI they aren't there, and F10 does nothing.



◇ Key bindings



The keys the game window acts on are a list, kag.keyBindings, which the controls list reads, so
a game that changes them gets a correct list. A game adds its own in AfterInit.tjs (the sample
binds F1-F8 there):


    kag.bindKey(VK_F2, 0, startSave, "Save");
    kag.bindKey(VK_F5, 0, toggleFullScreenByKey, "Full screen or window", true, false,
        function { return kag.displayMenu.enabled; });


  kag.bindKey(key, shift, action, label, early = true, debug = false, when = void)
    key       The key (VK_*).
    shift     The modifier keys held, compared exactly (0, ssShift, ssCtrl, ssAlt or a sum: a
              held key's repeats carry ssRepeat, so they don't match), or void for any.
    action    A function, called with (key, shift), or an expression.
    label     What it does, in English, for the controls list (shown through tr() in the
              language shown); void leaves the key out of the list.
    early     true: it runs before the layer with the keyboard focus gets the key, so it works
              over the choices and dialogs too (as a keyDownHook function does). false: only
              when nothing else took the key, as the framework's own.
    debug     true: only in KAG's debug mode (debugWindowEnabled; -debugwin=no turns it off).
    when      void, or a function: the binding is there while it returns true.
  kag.unbindKey(key, shift)
              Removes the binding of key with shift.


A function written outside any object (in AfterInit.tjs) runs with the global object as this.
The framework binds F, B, A, S and L (free save mode), R and Shift+Up, Esc, F9 (the next
language), F10 (the menu bar's first menu, in a window), F12 and Print Screen (a screenshot),
and in debug mode Shift+F12 (the
debug window), Shift+F11 (the debug level) and Shift+Backspace (back to the last pass record).
A key a keyDownHook function handles still works, but the controls list can't show it.

A controller's buttons send keys (kag.padKeyMap, from initialPadKeyMap in MainWindow.tjs): the
D-pad and the left stick the arrows, A Return, B Esc, X the message history, Y auto mode, R1
skipping to the next choice or unread text, R2 held skipping (Ctrl), L2 the next language,
and START and R3 (the right stick pressed) F10. A button mapped to a key does what the key does,
so the controls list shows the button with the key's binding (a button mapped to a function,
with the binding that has that function). A game changes the map in AfterInit.tjs (the sample's START,
BACK and L1 are F4, F2 and F3):


    kag.padKeyMap[VK_PAD10] = VK_F4;
    kag.recreatePadKeyMap();



◇ The menu bar



In a window, the items KAGWindow_createMenus makes (Menus.tjs; a game's own in Override.tjs)
show as a menu bar, as Kirikiri's Win32 menu bar did: the window is kag.menuBarHeight pixels
taller than the game, the game is drawn under that strip (Window.setViewport), and the strip
holds the top menus' titles. Full screen has no menu bar, as it had none in Kirikiri. The
framework's menu has System, Display (a window or full screen, the window size, a
screenshot), the message commands, Help (Controls, About) and, in debug mode, Debug.

A click on a title drops its menu down over the game (a top item without a submenu does what
it does at once); while a menu is open, moving the mouse to another title opens that one, and
resting on an item with a submenu opens the submenu. F10, START and R3 open the first menu from
the keyboard. In a menu the arrows or the D-pad move (Right opens a submenu or the next menu,
Left closes a submenu or goes to the menu before), Return or A chooses, Esc or B closes a
submenu or the menu, and a click outside it, a right-click or F10 closes it. Choosing an item
closes the menu and then does what the item does. The items show as they are now (enabled,
checked, the radio groups' choice).

An item's caption is in English, with an "(&X)" accelerator and a "\t" shortcut after it, as
for a menu bar: the bar takes the accelerator off, shows the caption through tr() in the
language shown and the shortcut at the right ("Save(&S)\tF2" shows as Save, with F2). An item
is left out while its visible is false (Menu_visible_config in Config.tjs) or its
menuBarHidden is true, and so is Help > Contents without the help file.

  kag.showMenuBar()         Opens the first menu, or closes the one open (F10; false: there's
                            no bar now).
  kag.menuBarShown          Whether the bar is there: in a window, with the menu visible, on an
                            engine with the Elements UI and Window.setViewport.
  kag.menu.visible          false takes the bar away (and the window loses the strip); true
                            brings it back.
  kag.menuBarEnabled        false: no menu bar, in a window either (F10 and START do nothing).
                            Set it in AfterInit.tjs.
  kag.menuBarHeight         The strip's height in screen pixels (30). Set it in AfterInit.tjs.
  kag.updateMenuBar()       Draws the titles again, after a game changed its top menus.



◇ The controls list



The controls list shows what each key, mouse button and controller button does, read from the
bindings themselves: the window's key bindings (above), the controller's map, and what the
framework does in code for Return, Space, Ctrl, the arrows and the mouse; keys with the same
action share a row. The controller's buttons are named by the controller in use
(System.padStyle: ✕ ○ □ △ on a PlayStation pad, A B X Y elsewhere), and in debug mode the
debug keys have a section of their own.

  kag.showControls()        Opens it (Help > Controls; the sample's Config screen has a
                            Controls button that calls it).
  KAGControlsList(kag)      The list: an array of sections %[title, rows], each row
                            %[keys, action, said] (said: the keys as a screen reader reads
                            them, when it differs).



◇ Screenshots



F12 (and Print Screen, where the system passes it on) saves what the screen shows as a PNG,
screenshot-<date>-<time>.png, in the save folder, and says so in a corner for a moment. Writing
a 1920x1080 PNG takes about 90 ms, which shows as a hitch, so where the window has
startSaveLayerImage (the layerExSave plugin, which Initialize.tjs links before the window is
made) and the folder is a local one, the PNG is written on another thread; elsewhere it's
written in one go.

  kag.saveScreenshot()      Saves one; returns the file's name.
  kag.screenshotEnabled     false: F12 does nothing.
  kag.screenshotFolder      The folder (void: the save folder, System.dataPath).
  kag.screenshotNotice      false: no notice.
  kag.screenshotHook        Functions called with the file's name once it's written (void if
                            it couldn't be).



◇ Screen readers



KAG has no screen reader support of its own. The framework passes the game's text and UI to the
system's screen reader (Narrator, VoiceOver, Orca) through the engine's ElementsDialog (the
engine guide's "Accessibility"):


  ・The text of each message is read out with the speaker's name when it waits for a click (in
    auto mode, when the wait starts). Text skipped through isn't read.
  ・The choices are a list, which the screen reader can move through and choose from.
  ・The Yes/No prompts and About show their text and buttons.
  ・The menu bar's titles, its menus and the controls list are read as they are (Elements
    screens).
  ・Saving a screenshot is announced.


Where the engine has no such interface (the browser build; the Android and iOS builds are made
without it) all of this does nothing. A game shows its own UI drawn on layers through KAGA11y
(Accessibility.tjs):

  KAGA11y.available                     Whether the engine has the interface.
  KAGA11y.announce(text, assertive)     Reads text out (assertive: interrupting).
  KAGA11y.setNodes(owner, nodes, focus) Shows owner's UI, in front of everyone else's: nodes
                                        as ElementsDialog.setGameA11y takes them (id, role,
                                        name, states, rect, parent), focus the id of the node
                                        the player is on. The screen reader's actions on them
                                        (focus, click) come to owner.onA11yAction(id, action,
                                        arg).
  KAGA11y.updateNodes(owner, nodes, focus)
                                        The same, where owner's nodes are now.
  KAGA11y.removeNodes(owner)            Takes them away; the ones behind come back.
  KAGA11y.rectOf(layer)                 A layer's place on the screen, for a node's rect.
  kag.a11yReadText                      false: the messages aren't read out.


To check without a screen reader, run the engine with a REPL and read Agent.a11yLog() (roughly
what it would say) and Agent.a11yTree(), or press a node with Agent.a11yAction(id, "click")
(tools/smoketest.py does).

● Carrying On and Quick Saves



Since 0.16.0 the game window keeps two kinds of bookmark for the player, set in Config.tjs's
window settings. Both may be numbered from numBookMarks on, past the menus' bookmarks:


    ;quickSaveSlot = 90;   // the first quick save's bookmark (-1: none)
    ;quickSaveSlots = 3;   // how many go round
    ;continueSlot = 93;    // the place to carry on from (-1: none)
    ;continueEvery = 5;    // save points between two continue saves


Quick saves go round quickSaveSlots bookmarks, so one wrong key can't overwrite the only one:
kag.quickSave() saves into the next (after the newest, scflags.quickSaveLast; a protected
bookmark is passed over) and shows "Quick saved" for a moment, and kag.quickLoad() asks, then
loads the newest. Shift+S and Shift+L do those where the game has quick saves; the sample binds
them to its own (Q.SAVE and Q.LOAD on the message window, which load through loadinit.ks).

  kag.quickSave()        The bookmark saved into, or -1 (nowhere to save from, or none free).
  kag.quickLoad()        Asks, then loads the newest; false without one.
  kag.newestQuickSave()  The newest quick save's bookmark, or -1.
  kag.quickSaves()       The quick saves, newest first.
  kag.quickSaveHook      Functions called with the bookmark after a quick save.

The continue save keeps the player's place as the game goes, so that the game can offer to
carry on from it at its next start, however it ended: it's written at the first stable state
(waiting for a click) after a save point of a new script or after continueEvery save points, and
when the game quits. Phones and browsers may end a game without it quitting, so the first two
matter there. It's only written from the main conductor where a bookmark can be saved
(kag.canStore(), not while skipping or with a dialog open). The sample's title asks once a run
("Carry on where you left off?", with the scene and the date) and loads it on Yes.

  kag.hasContinue        There's a place to carry on from.
  kag.continueOn         The player's switch (scflags): off, nothing is written or offered.
  kag.saveContinue()     Writes it now, where it can be; true when written.

When an uncaught error ends a release build, the framework first saves the system variables
(read marks, settings) and the continue save (KAGSaveBeforeError, Initialize.tjs).

The web build's saves go to /persist/<orgname>/<appname>/, which the browser keeps (in
IndexedDB): SDL's user:// there is in the page's memory, and everything saved in it went when
the page did (UPSTREAM.md). Save names are joined to the save folder with kag.saveDataFile(name),
which doesn't double the folder's slash.



● Options and the Config Screen

Since 0.17.0 the player's settings are declared once, in a table (template/system/Options.tjs),
and a Config screen lays its rows out from it: a game adds a setting without placing buttons
by hand, and Default and saving follow from the table. A game declares its own in AfterInit.tjs:

    KAGDefineOption(%[ name:"shake", label:"Screen Shake", kind:"toggle", save:true, initial:true,
        values:[ ["On", true], ["Off", false] ] ]);

  name      What scripts call it: KAGOptionGet("shake"), KAGOptionSet("shake", false).
  label     Its row's title, in English; it shows through tr() in the language being played.
            Or a dictionary by language code, for names (%[ "en" => "Ai", "ja" => ... ]).
  kind      toggle (two buttons), choice (two to four), slider, button (one button that runs
            action), note (lines of text).
  prop      A property of kag the option reads and sets (kag.windowOpacity ...); or getValue
            and setValue, functions; or save:true, which keeps it in scflags["option:<name>"].
  apply     A method of kag called after a change (applyWindowOpacity).
  values    [ [label, value] ... ] for a toggle or a choice.
  min, max, step, ends   A slider's range and the words at its two ends.
  initial   The value Default and the first start give it.
  button, action, enabled   A button's label, what it does, whether it can be pressed now.
  lines, rows   A note's lines, and the rows an option takes (1).
  preview   A slider's function(event, value), called as the slider is pointed at ("enter"),
            moved while held ("drag"), let go or moved by a key ("change") and left ("leave"):
            a volume's sample (since 0.18.0).
  test      A function a Test button after the slider runs (the slider then starts at the
            row's left, without words at its ends; since 0.18.0).

  KAGOptionGet(name), KAGOptionSet(name, value)   Read and change one (the second runs apply
                         and the functions in KAGOptionHook, with name and value).
  KAGResetOptions(names) Puts them back to initial (all of them without names).
  KAGOptionPage(layer, [ [x, top, names] ... ])   Draws columns of rows on a message layer
                         whose frame is the screen, and puts its buttons and sliders there:
                         call it from a .ks screen, where [locate]/[button] would go.
  KAGOptionRefresh(layer)   Shows the values again (after Default, or a key that changed one).
  KAGOptionStyle         The rows' size, fonts and the buttons' images (config_choice<w>_normal
                         and _over, the slider's slidebar, slidebar_over and config_track).

The framework's own options: voiceCut, voiceFadeTime, voicePlacement, voiceSpeed,
autoVoiceWait, dramaticMode, continueOn, quickSaves (a note), askAgain (a button),
hideCursorIdle, readSpeed, autoSpeed, autoCharWait, textFade, readColor, readMark,
windowOpacity, afterauto, afterskip, enterSkip, reduceMotion, and since 0.18.0 the settings of a
classic first Config page: bgmVolume, seVolume and voiceVolume (with samples, below), textSpeed,
autoModeSpeed, noEffect and allSkip (these have no initial: a game's first start sets them), and
volumeSamples; Indicators.tjs adds chapterTitles, nowPlaying, modeMark and voiceBar, Movies.tjs
subtitles, movieSkipping, movieRightClick and movieQuality. The sample's Config has five pages
(config.ks *options, configPages in Override.tjs): the first as before, then Voices and Saves,
Reading, Screen and Extras, and each character's voice.

Hearing a setting while changing it (since 0.18.0):

  [slider previewfunc= previewfuncdata=]   A function (by name) called with (event, position,
                         data) as the slider is pointed at, moved, let go and left (the events
                         above); a screen drawn again moves its sliders without it
                         (LinkSliderLayer.setPositionQuietly). An option's slider with preview
                         gets it through KAGOptionPreview.
  KAGVolumeSamples       What the volumes' previews play: pointing at the music's slider or
                         moving it plays musicStorage, when the game plays no music, for
                         musicTime ms (5000) after the last move, then fades it (stop(fade) ends
                         it, as Config closes); letting go of the sound's plays soundStorage in
                         SE buffer soundBuffer; letting go of the voices' plays a character's
                         test line. A game sets musicStorage and soundStorage; the volumeSamples
                         option turns them all off.
  KAGDefineVoiceOptions(names)   For each character named, a slider "voice:<name>" for the
                         volume of its voiceName (kag.getVoiceVolume) with its nameAlias as the
                         label, a Test button and a test line as it's let go, and a toggle
                         "voiceOn:<voiceName>" (kag.getVoiceOn); returns the sliders' names, for
                         a page's column. Call it in AfterInit.tjs (the World is there by then).
                         A character's test lines are envinit.tjs's "testVoices" => [ files ];
                         KAGVoiceTest(name) plays one.

Undo and Revert (since 0.18.0): KAGOptionUndo.begin() as a Config screen opens notes every
option's value; each change after it through KAGOptionSet is a step (a slider's from where its
drag began); undo() takes back the newest, revert() puts everything back as it was at begin(),
end() as the screen closes. canUndo and changed say whether there's a step, and whether anything
differs from the start. mark() makes the changes until groupEnd() one step (the sample's Default).
Only options are covered: the sample's first page goes through them (its sliders call
KAGOptionSlide, its switches KAGOptionSet), but the screen mode and the language aren't options.

● On-screen Indicators

The game window's indicators (template/system/Indicators.tjs, kag.indicators) are drawn in the

● Movies

    [movie storage=opening alpha=0 song=bgm01 color=0x000000 skip=seen fit=true layer=]

plays a movie as commercial games do (since 0.17.0, template/system/Movies.tjs): over everything
but the prompts, centred on a KAG layer (the last one, or layer=), and waits for it to end.

    storage   The movie, without its extension (.webm on the SDL engine).
    alpha     As [image movie=]: 0 opaque, 1 alpha below, 2 alpha to the right.
    color     A colour that fills the screen behind it.
    song      Music it plays, unlocked in the music room (sf["bgm_<NAME>"]; several with commas).
    skip      seen (the default): a click skips it only once it has been seen; always: any time.
    subtitle  false: no subtitles; a file: those instead of <name>.vtt.
    fit       true (the default): zoomed to fill the screen, keeping its shape; false: shown at
              its own size (since 0.17.2).

It's noted as seen (sf["movie:<name>"], KAGMovieSeen(name)) when it ends or is skipped. Skip
mode stops before a movie not seen yet, and passes a seen one where Config says so
(movieSkipping); the right button skips a seen one where it says so (movieRightClick). A
movie with a smaller version, <name>_sd, plays that when Movie Quality says Smaller, and by
itself on the web, Android and iOS (Auto), zoomed to fill the screen like any movie of another
size (the sample's opening_sd is 960x540, half the screen each way). A movie that shows no picture in three seconds (no
decoder for it here), or whose picture stops for three seconds (since 0.17.2: the engine holds a
movie with sound at its first frame on a computer with no sound device, UPSTREAM.md 40), ends,
so the game goes on.

Subtitles: a movie on a layer whose [image] has subtitle=true ([movie] gives it that) shows the
cues of <name>.vtt (WebVTT: times and lines; a language's own in data/lang/<code>/ stands in for
it) at the bottom of the screen, timed from the movie, and screen readers get each one.
<name>_sd uses <name>.vtt when it has none of its own. Config's Subtitles turns them off.
[image movie=] takes fit=true too: the layers showing the movie are zoomed (affine layers) so its
frames fill the screen; [freeimage] puts the zoom back.



● Loudness

A table evens out the sounds' levels without re-recording them (since 0.18.0,
template/system/Loudness.tjs): loudness.csv has a gain in dB per kind of sound or per file, which
the engine applies as each Ogg Vorbis or Opus file is decoded (WaveSoundBuffer.
setGainQueryCallback), so a quiet voice can be raised past the volume's 100%:

    bgm            -4      every file in a bgm folder
    se             -2      in a sound (or se) folder
    voice          +1      in a voice folder
    voice:hiyori   +2.5    one speaker's voices (envinit.tjs's voiceFile patterns say whose)
    pip000009      +5      one file, with or without its extension: it wins over its kind

Lines starting with # are comments. KAGLoudness.set(key, dB) changes one while the game runs, for
the files opened after it, and KAGLoudness.gainOf(storage) says what a file gets. WAV files get
no gain. The sample's table (data/main/loudness.csv) brings its synthesized voices up to the
others (measured with EBU R128) and puts the music 4 dB under the voices.



● Interface Sounds

Every button, page turn, slider, prompt, choice and menu item can play its sound from one table
(since 0.18.0, template/system/InterfaceSounds.tjs), so changing the click for the whole game is
one line. uisounds.csv names a sound for each tag, <screen>.<part>.<event>:

    @click              ui_click     an alias: a file, and a system sound buffer if wanted
    *.click             @click       every click no other line names
    *.enter             ui_hover     the pointer, the keys or the pad reaching a button
    *.return.click      ui_cancel    every screen's Return button
    title.start.click   ui_ok
    config.config_*.click  ui_toggle  Config's switches
    dialog.open         none         a wildcard's sound taken back

Lines starting with # are comments; the columns are separated by tabs or spaces. A sound is a file
on the auto path (its extension may be left out), an @alias or none; a third column picks the
system sound buffer (0, the first, by default; numSysSEBuffers in Config.tjs). A * matches any
characters, dots too, and of the lines a tag matches the one with the most other characters wins
(of two as long, the later). A button's own sound (clickse=, enterse=, changese=, [selopt]'s and
the like) comes first: the table is asked only for parts without one. The tags:

    <screen>.<name>.click, .enter     [button] (its name=, else its picture's), [link] (name=,
                                      else link). <screen> is the scenario that made it, without
                                      its extension: title, config, save ...
    <screen>.<name>.change            a slider let go, a check box (their name=)
    message.<name>.click, .enter      [sysbutton]s
    dialog.open, dialog.<name>.click, .enter, dialog.skip.change
                                      Yes/No prompts (yes, no, and the "Don't ask again" box),
                                      About (close)
    choice.open, .enter, .click, .close   [select]'s choices
    backlog.open, .close, .prev.click, .next.click   the backlog
    menu.open, .enter, .click, .cancel    the menu bar's menus (in a window)
    controls.open, .close.click, .cancel  Help > Controls (an Elements screen's soundScreen)

KAGInterfaceSounds.play(tag) plays one from a script (KAGInterfaceSound(tag) is the same, and does
nothing in a framework without the table), soundOf(tag) says what it plays, set(tag, sound) and
alias(name, sound) change the table while the game runs (buttons made before keep what they had).
An .enter sound within enterQuiet (150) ms of another sound is left out: a click that redraws a
screen under the pointer, or a prompt that moves the pointer to its button, would play one. In
debug mode two sounds started within doubleTime (20) ms are logged, with where each came from:
that's usually one sound played twice. The sample's table is data/main/uisounds.csv, with sounds
from tools/assets/make_sounds.py.



● Reduce Motion

Config's Reduce Motion (the reduceMotion option, since 0.18.0; KAGReduceMotion() says whether it's
on) stops demanding animation, for slow machines, batteries and phones, and for players bothered
by motion:

    Effekseer effects    one played once ends at once (its efkdone goes, so a script waiting
                         goes on); a looping one shows nothing
    movies on layers     a looping one ([image movie=... loop]) pauses on its frame; one played
                         once, as [movie] plays them, plays as before
    alpha movies         a looping one stops on its frame
    the TV static        stops on its frame
    Live2D and 3D layers stop as they show, once a motion played once has ended

Turned on while they play, they stop where they are; turned off, they move on. An [image] or a
World layer can name a picture to show in place of its animation while Reduce Motion is on:

    [image layer=1 flip=sparkle.efk still=sparkle_still]
    [newlay name=petals efk=petals still=petals_still show]

The picture is loaded instead of starting the animation, as an image of its own size; it stays
until the layer is drawn again. The sample's Effects demo has stills for its petals, sparkles
and magic circle (tools/assets/make_effects.py stills), and Config's last page has the switch.
Transitions and actions are Screen Effects' (noeffect), not this option's.

● About Automatic Label Processing



◇ Overview



"Saving" in KAG is performed in units of "labels" explicitly attached by the user.



Reference:

  http://devdoc.kikyou.info/tvp/docs/kag3doc/contents/SaveLoad.html



In ADV type games, this restricts save points,

which is quite inconvenient for users.



In KAGEX, there is an "Automatic Label Mode", and enabling this allows saving

at every [p]. If line mode is enabled, this becomes effective at every

virtual [p].



Accordingly, read management is also not in units of normal simple labels,

but in units of labels + line count from the label, enabling fine-grained control.



Specify the following variables. Can be specified in Config.tjs.



 kag.autoLabelMode      Automatic Label Mode. Enabled with true.

 kag.autoLabelType      Specification of control type for Automatic Label Mode 0: call method 1: line number method

 

◇ call Method



　This is the autoLabelMode in old KAGEX.

  It is a method of labeling by calling call processing at every [p].



　Due to the process of returning from the call recorded in this mode, the check for

　restoration processing is strict, and restoration of saved data when scenario data

　is rewritten is harder to guarantee than with labels. Please be careful.



◇ Line Number Method



  This is a new method. By modifying KAG's load processing and execution system,

　information is recorded by the nearby label and the skip processing by line count

　from there.



　・Since it does not go through call, there is a high possibility of restoration even when information shifts.

　・Errors due to file modification during scripting work do not occur.

　

　It has such features. Basically, it is recommended to use this for new projects.



　Note that when using this mode, saving as a label is the same as when autoLabelMode = false,

  so by manually placing savable labels at key points in the scenario file,

　it is possible to use "Return to previous label" and "Proceed to next label"

　via the "Automatic Label Save" of the debug menu.



● About Voice Parse Function



◇ Overview



An application of line mode extension, this allows voice number assignment to be processed

according to the absolute position in the file rather than by the flow of the scenario.

It has the merit that the file number specification does not change even if there is branching in the scenario.



◇ Specification Method



[parse voice=1]



All commands after this instruction are parsed in advance,

and dedicated voice processing is embedded. The handling of voice differs.



・The character voice specification function is always overwritten, so it becomes meaningless.

・Use the following special voice specifications:



// Voice number specification

[voice name=CharName voice=123]



// Voice complete stop (specify a negative number)

[voice name=CharName voice=-1]



// Voice single-shot ignore

[voice name=CharName ignore]



// Voice single-shot ignore replacement

[voice name=CharName ignore replace]



// Voice single-shot interrupt

[voice name=CharName voice=VOICE123]



// Voice single-shot interrupt (in case of number)

[voice name=CharName voice=123 once]



// Voice single-shot replacement

[voice name=CharName voice=VOICE123 replace]



// Voice single-shot interrupt (in case of number)

[voice name=CharName voice=123 replace]
