Title: Compiled Scenarios



● Overview

A script can be played compiled: the compiler (template/system/SceneParser.tjs) turns it into
scenes, and the scene player (template/system/KAGEnvPlayer.tjs, the [scenestart] tag) plays
those instead of the script. A compiled scene holds its text, names and voices as a table, its
tags as steps, and the World's state at every save point, so the player can start at any line,
go back to an earlier choice, stop skipping exactly at unread text and draw a thumbnail of any
line.

This follows the plan at https://github.com/krkren/scnfile. A compiled scene is a .scn file,
M2's binary PSB format, which the scnfile plugin (SCNFile, from that repository; the player
also takes Wamsoft's PSBFile) reads and writes. A build without the plugin compiles to and
reads <script>.scn.json instead, through the json plugin every build has. kagex-release
compiles a game's listed scripts, encrypts the .scn files with the game's key and ships them
without the scripts (Releases, below). A compiled script plays without its .ks: the .ks of a
script in !scnlist.txt only has to be there to compile it. Still to come: the plugin on every
platform (only Linux builds it so far, and the engine packages don't have it yet).



● Using it

◇ Which scripts

!scnlist.txt (on the auto path; the sample's is data/scenario/!scnlist.txt) lists the scripts
to play compiled, one per line. A line starting with # is a comment. Scripts not listed (the
title screen, the system screens, macro files) are played as before.

◇ Compiling

The compiled file of a script goes next to it: data/scenario/char.ks is compiled into
data/scenario/char.ks.scn (or char.ks.scn.json without the plugin, or with format=json below;
writing one removes the other). The files are made from the scripts and aren't committed
(.gitignore). A script is compiled again when it has changed, or the macros, the options,
envinit.tjs, charinit.csv or the compiler have: each compiled file holds the key of what it
was compiled from (hash).

- In debug mode (the default; -debugwin=no turns it off), a listed script that changed is
  compiled when the game goes to it.
- -scncompile compiles every listed script that changed, writes what happened to the console
  and exits (with 1 if one failed); -scncompile=all compiles all of them. The game's window
  stays hidden.
- KAGCompileScenarios(force) does the same from a running game, and returns
  %[compiled, skipped, failed, errors, warnings].

The compiler writes only where the list is a local folder: not inside an archive, the web
build's files or a phone app's assets. A compiled file whose key doesn't match its script is
not used: the script is played instead.

◇ Macros and options

The compiler expands macros as KAG does. It takes them from parsermacro.ks, collecting the
macros it defines and those of the files it calls or jumps to (the sample's has
@call storage=macro.ks). Without parsermacro.ks it takes the game's macros as they are when it
compiles; -scncompile happens before first.ks, so it needs parsermacro.ks.

parseroption.txt (optional) holds name=value lines:

    linemode     the line mode a script starts in (none, page, line, vn, tex, free).
                 Default none. A script that sets its own ([linemode], or a macro that does,
                 like the sample's [initscene]) doesn't need it.
    craftername  whether a line with just a name carries it to the next line (true/false),
                 as [craftername mode=]. Default false.
    format       json writes .scn.json even with the plugin there, to read what was compiled.

◇ Playing

A listed script that has a compiled file plays compiled however the game goes to it: [jump],
a choice, kag.process(), loading a save. KAG reads a stand-in for the script, made of its
labels, each followed by [scenestart] for that scene (KAGWorldPlugin.onScenarioLoad), so the
conductor's current script is still the script's name.

To play every script from the script itself, start with -scnplay=no (-scnplay=yes plays them
compiled whatever the game has saved). The setting the game keeps is the World's
playerExecMode (scflags.playerExecMode), on unless turned off.

Saves made while playing compiled resume at the save point they were made at. A script
compiled again since then (its hash changed) resumes at the top of the scene instead. Saves
made with compiled play on and off don't mix: one made reading the script can't be loaded
into the compiled script, or the other way round.

◇ Going back

The player keeps the history of what it showed (KAGEnvPlayer.tjs, histories): each text, with
the game's flags as they were at it, and the choices taken. Going back goes to what a click
showed: a text that came after a wait for a click, with the texts after it up to the next wait.

For the last 100 of those the player keeps KAG's own state as the save point before them stored
it (pflags and pcflags, what a save holds), and going back to one restores that as a load does,
so KAG's layers, sounds and the like are as they were too. Before those, or after a load, it
restores the World's state at that save point and the game's flags only: a script that draws on
KAG's own layers (layer.ks) shows them as they are, not as they were. Either way the message
window starts empty, with the text gone back to (and its name), as after a load.

- player.rollback() goes back to what the click before the one on the screen showed (at a
  choice, to the text the choice came with); player.canRollback says whether there is one. The
  sample's BACK button (macro.ks, rollBack() in Override.tjs) is this.
- player.jumpFromHistory(pos) asks "Go back to this line?" and goes back to history position
  pos. The backlog gets a mark on the line each click's text starts on (the scnhistmark tag;
  history layers with markJump: the sample's MyHistoryLayer.tjs draws it left of the voice
  mark) that does this.
- After a jump or a load the backlog is written again from the history (rebuildBacklog), so it
  ends where the game is, marks and voices included. A choice is a line "Choice: <the one
  taken>".

The history goes on across compiled scripts that go to one another, and starts again when the
game plays a script that isn't compiled. Saves keep it.

◇ Replays: starting at a scene or a line

A compiled save point holds the World's state, so the player can start any scene there, but not
what the script put on KAG's own layers before it. player.seek(storage, label, text, replay)
starts the next compiled script KAG goes to ([scenestart]) from its beginning without showing
anything (KAG's hidden skip, running every tag but [endrecollection] and [s]) until the text in
that scene, then shows it: the screen is as playing gets there. The history starts at that
text. With replay, the end of that scene ends the recollection (KAGWindow.startRecollection),
which goes back to where it was started from.

The sample's Replay screen (Extras) is made from data/main/replaylist.csv: a tile a line, on up
to six tabs (the first column, which labels them), 16 tiles a page. A line's label * makes a
tile for every scene of a compiled script that has a title (*label|Title), in order. A tile
shows its scene's World at its first line (or the line's image, or a play tile where the World
shows nothing, as in layer.ks), with the title; it stays locked until its scene has been read
(the player's read marks; sf.trail_* for a script that isn't compiled). A tile plays its scene
on its own (replayTile in Override.tjs: a seek with replay) and comes back to Replay at its
end; EXIT comes back too.

◇ Search

player.searchTexts(text, readOnly, max) finds the texts of the compiled scripts in
!scnlist.txt that hold a string, or whose speaker's name does (letter case ignored), as they're
shown: without font commands, ruby and escapes. With readOnly only texts that have been read
count (the read marks), so a search gives nothing away. Each result is %[storage, label, scene,
title, idx, name, text]; player.seek(storage, label, idx, true) plays from it. doSearch,
getSearchData and goToSearch use the same search.

The sample's Search screen (Extras, searchmode.ks) takes a word in an [edit] field (Return
searches: [edit enter=], doc/kagex.txt), lists the lines read that hold it, 7 a page, with the
demo and scene each is in (replaylist.csv's titles), and plays from the one chosen to the end of
its scene, then comes back to Search. tf.allseen searches every line.

◇ Releases

kagex-release compiles the listed scripts as it builds (Scenarios > Compile, scenes.compile in
release.json; on by default when the game has a !scnlist.txt): after the media conversion it
runs this computer's engine on the game's files with -scncompile=all, then leaves out each
compiled script and the compiler's own parsermacro.ks and parseroption.txt. !scnlist.txt
stays: the game reads it to know which scripts are compiled. The compiled files the game
folder already has are left out and every script compiled again.

With the engine's scnfile plugin the files are .scn, and every platform's engine needs the
plugin to play them: a platform whose engine lacks it fails to build. Without the plugin
they're .scn.json, which every engine reads. The tool's check says which it will be. The
engines the tool downloads don't have the plugin yet: engine packages that do go in engines/
next to data/, which the tool uses before its downloads.

With Scenarios > Encrypt (scenes.encrypt) the .scn files are encrypted with the scenes key
of the game's keys file (Keys > keys file, keys.file, or the variable KAGEX_KEYS_FILE; Create
keys... in the window, or kagex-release --cli keygen <file>, makes one). The file holds a
key of its own for each kind of protection: the archive, the scenarios and signing. The build
writes the scenes key into each package's copy of the plugin (or of an engine with the plugin
built in), before signing and before the web build's id, so each game's engines open only
that game's files. The keys file can't be inside data/. Encrypting the same file with the
same key gives the same bytes, so a patch (output.patchFrom) holds only the scripts that
changed, and it has to be built with the key the game was: keep the keys file, and keep it out
of the game's repository. The format is
scnfile's docs/format.md (XChaCha20-Poly1305: a changed byte makes the file refuse to open).
The key is in the game, as any key a game reads its own files with has to be: this keeps the
scripts from being read with a text editor or a PSB viewer, not from someone determined.

In debug mode a release's compiled files are used as they are: there is no script to compile
them from.



● What the compiler does

A script is read the way KAGParser reads it (labels, comments, [iscript], line commands,
macros, tabs, [[), with one difference: [if]/[elsif]/[else]/[endif]/[ignore]/[endignore],
cond= and & entities aren't worked out while compiling, but when the game plays them.

◇ Scenes

Each label starts a scene: its label, its title (the label's page name, or the title before
it) and its first line. A scene that runs into the next label goes on to it. Text before the
first label is a scene of its own, labelled "", when it does anything.

◇ Text

Text is put together as KAG's line modes put it together ([linemode], [craftername], [nor],
[noer], 【name/display name】, [voice], [nextvoice], [parse], ruby, [r], [l], [p]), into
messages: a name, its display name, its voices and the text, ending at a wait for a click. In
page mode each line is a message; with no line mode, a message ends at [l] or [p].

A tag inside a message splits it: the part after the tag carries on the message window as it
is (no new name, no clearing).

Voices are worked out as KAG works them out: [ai voice=1] gives the next 【ai】 line voice 1,
the one after that voice 2, and so on.

◇ Save points

After every wait for a click there's a save point: the game can save, load and jump there.
Each holds the World's state then, worked out by running the World tags in a World of the
player's own that draws nothing (KAGEnvForParse). Loading a save point puts the World back as
it was and plays on from there, so the tags between it and the text play again. Each text
holds the state while it's shown, for thumbnails and for going back.

A script is compiled from an empty World. A script that carries on from what another one left
on the screen starts with an empty screen when played compiled.

◇ Tags

- World tags (characters, the stage, events, World layers, World BGM and SE, [allchar] and
  the like, [dellay], [delchar], [init]) are steps, and change the saved states.
- [clearlayers] clears the World's layers in the saved states too, as it does in the game.
- Every other tag is a step, run as KAG runs it. KAG's own layers, message windows and sounds
  aren't part of the saved states: a save restores them through KAG's own save data, but
  jumping to a line doesn't.
- cond= is checked when the step runs. A World tag with cond= doesn't change the saved states
  (the compiler says so).
- & entities are worked out when the step runs. For the saved states, a World tag's entities
  are worked out while compiling, from the values they have then (the compiler says so if it
  can't).
- A tag from a macro that uses mp (in an expression or an entity) brings the macro's
  arguments with it, and mp is those while it runs.
- [if]...[endif] become steps the player branches on. Each branch is compiled from the state
  at [if]; after [endif] the states follow the first branch that doesn't jump away (the
  compiler says when branches leave the World in different states). A choice made inside
  [if] is offered only when its branch would run.
- [jump] at the end of a scene is where the scene goes next; one with cond=, inside [if], or
  to a destination given by an entity is a step. What follows an unconditional [jump] or a
  [select] up to the next label can't be reached and is left out.
- [seladd]/[mseladd] and [select]/[mselect] end the scene with its choices. A choice's cond=
  becomes its eval= (checked when the choices are shown).
- [iscript] runs as a step; [emb] shows the text its expression gives when it's shown.
- [macro], [endmacro] and [erasemacro] work while compiling only.

Not supported in a compiled script (the compiler stops with an error): [call], [return],
[pmacro], a label inside [if]...[endif], [select] inside [if]...[endif], and [scenestart] and
the other player tags.

◇ When skipping without display

While KAG skips without showing anything, the player doesn't run World tags (the screen is
put back from the saved state when the skip ends) or most other tags. It still runs [next],
[exit], [eval], [cancelskip], [linemode], [craftername], [erafterpage], [autoindent],
[iscript] and [if].



● The compiled format

<script>.scn or <script>.scn.json, holding the same tree. The .scn is PSB, laid out as
https://github.com/krkren/scnfile describes in docs/format.md (Dictionaries are PSB objects,
Arrays lists, void null). The root:

    version     1
    storage     the script
    hash        the key of what it was compiled from
    scenes      the scenes, in order

A scene:

    label       its label ("*start"), or "" for the part before the first label
    title       its title
    firstLine   its label's line (lines count from 0, as KAG's do)
    startLine   the same
    lastLine    its last line
    spCount     the number of its last save point
    texts       its messages: [name, display name, text, voice, flag, state]
    lines       its steps, below
    nexts       where it goes when it ends, below (none: the story stops)

A text's display name is null unless the script gave one; its voice is null or a list of
%[name, voice, noplayvoice]; its state is the World's state (KAGEnvironment.onStore), or the
number of an earlier text in the scene with the same state. In the text, \\ is \, \% is %, \[
is [, \k waits for a click, a new line is [r], [ruby] goes before its character, %<number>
sets the font size and %r resets the font. The flag:

    0x01  ends with [l] (otherwise with [p])
    0x02  the page doesn't clear the message window ([noer])
    0x04  no wait: the message goes on after a tag
    0x08  an event picture is shown or changes
    0x10  the stage changes
    0x20  no text (a voice alone)
    0x40  carries on the message window as it is (no msgon, no name)

A line is one of:

    a number      shows that text
    a string      sets that read flag (bgm_, cg_, ...), as the World did there
    [point, state, text, force, line, flag, label]
                  a save point: its number, the World's state (or a text's number), the text
                  it leads to, whether it saves even while skipping without display, its line,
                  that text's flag, and a name to go to it by
    [tagname, flag attributes..., 0, name, value...]
                  a tag. Attributes without a value come before the 0, in order, the rest
                  after it. A value starting with & is an entity (an expression worked out
                  when the tag runs), one starting with ` has the ` taken off; *cond is a
                  condition and *mp the arguments of the macro the tag came from
    [*if/*elsif, 0, exp, expression], [*else], [*endif]
                  branches
    [*script, 0, script, code, storage, script, line, line]
                  an [iscript] block
    [*emb, 0, exp, expression]
                  text worked out when it's shown
    [*noer]       the next page doesn't clear the message window

nexts: one or more of

    type      0 goes on ([next]), below 0 leaves the player ([exit]), 1 a choice ([select]),
              2 a map choice ([mselect])
    storage   the script (none: the same one)
    target    the label
    exp       an expression run when it's taken
    eval      a condition
    text, onceflag, tag
              a choice's text and flags, as [seladd] takes them
