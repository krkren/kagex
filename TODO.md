# To do

Planned features. Each needs changes to the builds as well as work in this repository; krkrz_dev itself isn't changed (`CLAUDE.md`), and what its plugins can't do yet is in `UPSTREAM.md`. The last section lists the plugins and features looked at and left out, and why.

## Needing more than scripts

These change the builds too: native code for every platform, including the web, Android and iOS engines in kagex-release's engine packages (the web build links its plugins into `krkrz.wasm`).

- [ ] **Live2D: what's left** (`krkrlive2d`; the characters are in the framework: `doc/world.txt`, "Live2D Characters"; the plugin, its CI and the sample game packages: `tools/live2d/README.md`). (1) The web: Live2D's SDK for Native has no WebAssembly Core, so the browser build would need Live2D's Cubism SDK for Web and a bridge from the engine's wasm to its JavaScript Core (the framework reads and writes the Core's arrays directly, so the bridge would mirror them each frame); left for now (the user's call). (2) Android and iOS: a game makes its own engine package from a kit's build with the plugin (`build.py --kit`, then `android-engine.py`/`ios-engine.py --with-cubism-core` into `engines/`), which `tools/live2d/README.md` describes and `setup.py` explains, but which nothing has tried end to end. (3) The release packages: the zips hold `data/`, `template/` and `doc/` but not `tools/live2d` or `tools/assets/make_hiyori.py`, so a developer starting from a zip gets `setup.py` from the repository; the release workflow (`ci/windows-release`) should copy `tools/live2d` (and `make_hiyori.py`) in, and start `live2d.yml` with the release's tag (`gh workflow run live2d.yml -f release=<tag>`) to add the sample game packages. Later, Live2D on KAG layers too (`[image flip=model.l2d]`), as Effekseer's `efk` flip type.
- [ ] **krkr_richtext and Effekseer on iOS**: both are left out of the iOS build because CMake's Xcode generator stopped with "duplicate object ids not allowed". The likely cause is `UPSTREAM.md`'s 32 (tp_stub's `krkrz_plugin()` names a plugin's project after the plugin has added its own folders, so the Xcode generator lists them twice), which the Live2D driver works around with a `project()` of its own. For these two the fix is in krkrz_dev's plugins: the iOS job could give `richtext/` and `glad/` a `project()` in its CI checkout (as `web-plugins.py` edits krkrz_web's), then put both back in `ios-config.json`.
- [ ] **3D scenes and VRM characters** (`krkrthreepp`): threepp, a C++ port of three.js (scenes, cameras, lights, materials, glTF), and VRM avatars (VRoid and the like, 0.x and 1.0) with expressions, eye direction, VRMA animations, spring bones and MToon toon shading. It draws through the engine's `GLCompositor`, as krkreffekseer does, and the Windows, Linux and macOS packages already ship it. A `3d` flip type would render a scene into a layer, as `efk` plays effects; then World characters as VRM avatars, with faces as expressions, poses as VRMA animations and lip-sync as for Live2D: the mouth opening by `WaveSoundBuffer.getSoundLevel` or a lip track, whose vowels map straight onto VRM's own mouth expressions (`aa`, `ih`, `ou`, `ee`, `oh`; A, I, U, E and O in VRM 0.x). The sample can't include a VRM model (no third-party art), so it would show a 3D scene built in script, and a game brings its own model. The plugin's presets include Android but not iOS or the web, and iOS may hit the same Xcode error as krkreffekseer.
- [ ] **M2's E-mote characters** (`emoteplayer`): E-mote is M2's 2D animation format (a character's `.psb`, made in the E-mote editor, moving its face, eyes, mouth, hair and body from one illustration), used by many Kirikiri games. The plugin that plays it is M2's own, from M2's SDK (an indie plan is free, commercial titles pay; check M2's current terms), and krkrz_dev's public build doesn't have it, so as with Live2D the builds would need the SDK, every platform's engine (the web, Android and iOS too) would need it linked, and releasing a game can need M2's license, which the documentation should say. Then World characters whose poses, faces and timelines are an E-mote model's, blinking and lip-syncing by its own variables (fed from `WaveSoundBuffer.getSoundLevel` or the voice's lip track, as the layered characters are, with the track's vowel for a model that has mouths for them), drawn through an AffineLayer source (krkrz_dev's TODO describes one, `AffineSourceMotion.tjs` with `SimpleEmotePlayer` and `SwitchEmotePlayer`, which this framework doesn't have). That TODO also notes that there each player makes its own `Motion.ResourceManager`, so a character's `.psb` (tens of MB) is read again on every action, and that sharing one per window crashed the plugin at unlink: use one cache per model, or find out what the plugin allows. The sample can't include M2's sample models (no third-party art), so it would need a model of its own made in the editor, or show the feature only when a game brings one.

## Looked at, not planned

- `layerExAreaAverage`: shrinks by area averaging, which `shrinkCopy` already does, in half the time and without the glitches `stretchCopyAA` left in text.
- `layerExLongExposure`: averages frames into one image, an authoring tool for rule images, which `tools/assets/make_rules.py` makes.
- `lineParser`: `[].load()` already reads a file line by line, and the framework parses with KAGParserEx and csvParser.
- `expat`: XML parsing; nothing in kagex reads XML, and only the desktop builds have it.
- krkr_richtext's per-character timing (`StyledLayout`'s `<delay>`, `<wait>` and `calcShowCount`): it times a text laid out whole, while KAG's conductor gives the message window a character at a time with its own waits, skipping and auto mode, so KAG keeps timing the characters (krkr_richtext lays out and draws each line of them: `useStyledLayout`).
- `krkrgles` (Windows only): an OpenGL ES context through ANGLE, for engines without one. The SDL engine draws with OpenGL ES, and krkreffekseer, krkrthreepp and krkrlive2d use its context.
