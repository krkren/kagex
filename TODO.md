# To do

Planned features and fixes. The first section's need changes to the builds as well as work in this repository, and the second's wait on the engine: krkrz_dev itself isn't changed (`CLAUDE.md`), and what it and its plugins can't do yet is in `UPSTREAM.md`. Many entries came from moving a commercial game made with Wamsoft's framework to KAGEX's engines; they describe what such games do, for KAGEX to write again from scratch with its own names, formats and assets, taking none of that game's code, data or art. The last section lists the plugins and features looked at and left out, and why.

## Needing more than scripts

These change the builds too: native code for every platform, including the web, Android and iOS engines in kagex-release's engine packages (the web build links its plugins into `krkrz.wasm`).

- [ ] **Voice effects** (a plugin of KAGEX's own): an echo on memories and inner voices, a thin voice on the phone, a muffled one through a door, as commercial games have them. A writer sets an effect with a World tag, for one character or for all until it's cleared, and each effect's settings are in a small text file; the effect is kept in save data, so compiled scenes, saves and going back carry it. KAGEX has no sound filters besides the phase vocoder for voice speed, though `VoiceTrack` (`KAGEnvCharacter.tjs`) already keeps a `filters` chain, and 0.12.0's positional sound (`WaveSoundBuffer.use3D`, `KAGEnvSE.tjs`) pans and sets distance but doesn't filter, so a phone or a door still needs this. The plugin would be engine wave filters (`iTVPBasicWaveFilter` over a `tTVPSampleAndLabelSource`, float output, settings changed on the decoding thread): a delay, biquad and Butterworth filters, perhaps a reverb, with DSPFilters (MIT) for the filter designs, built into every engine as scnfile is (static on the web, Android and iOS); without it, voices play unchanged. The sample gets a demo line: Pip on the phone. The `WaveFilters` plugin written for a port already has a delay and DSP filters, but its delay was rebuilt from the disassembly of a Wamsoft DLL and its class names follow Wamsoft's, so shipping it as it is is the maintainer's decision; otherwise KAGEX writes its own, with its own names and API.
- [ ] **Glitch transitions** (a plugin of KAGEX's own): digital glitches (rows of noise, shifted blocks, split colours) as a transition in the story, and when menus open and close, pages turn or a game loads, as some of Wamsoft's games do; single glitched frames also give a "broken screen" inside a scene. KAGEX has extrans's and extNagano's transitions, with a crossfade when a plugin is missing (`KAGTransitionMethod`), which already covers a build without this one, and its system screens have no set transition. A transition plugin with its own glitch algorithm and parameters, built into every engine as scnfile is; a framework setting for the transitions its screens open, close and turn pages with; and a demo step in the sample's `transition.ks`. The `GlitchEffect` plugin written for a port reproduces a Wamsoft DLL from its disassembly, down to its random numbers, so it's better kept for that port, with a new design written for KAGEX: that's the maintainer's decision.
- [ ] **Opening web pages, folders and programs on every platform** (`ShellExecute`): a "Visit the website" menu item, a button that opens the screenshot folder, a link in the credits, and for developers a helper program whose output they read. The SDL engine has the code (`app.cpp`, through `SDL_OpenURL`) but binds no `System.shellExecute` for scripts, so a call throws, and KAGEX's own Help > Contents calls it (`onHelpIndexMenuItemClick`, `template/system/MainWindow.tjs`); krkrz_dev's `shellExecute` and `process` plugins are Windows-only and not in the engine packages. Either the engine binds it (a krkrz_dev change, for `UPSTREAM.md`), or KAGEX ships the `ShellExecute` plugin written for a port: krkrz_dev's plugin rebuilt for every platform from the public APIs (ShellExecuteEx and CreateProcess on Windows, posix_spawn with `open` or `xdg-open` on macOS and Linux, `SDL_OpenURL` on Android, iOS and the web, programs polled from the continuous event rather than by threads), tested on Windows, Linux and Android, and free to ship as it is; on the web, Android and iOS it has to be in the engine package (`tools/release/README.md`, "Your own plugins"). The sample shows it with a "website" item in the title or system menu, and the in-game manual, the screenshot folder and the debug helpers below use it.
- [ ] **Text to speech with the system's voices** (`SpeechSynth`): for players who can't or don't want to read, each line read aloud by one of the system's voices and played like a voice line (auto mode waits for it, and it follows the voice volume), with the voice, its speed and pitch chosen per kind of speaker, and a pronunciation dictionary. Since 0.12.0 each message goes to the system's screen reader (`KAGA11y`), which speaks with the reader's own voice and settings, not on the game's voice channel, and isn't there in the browser, Android and iOS builds. The `SpeechSynth` plugin written for a port speaks into a WAV file (SAPI on Windows, `say` on macOS, espeak-ng on Linux, Android's `TextToSpeech.synthesizeToFile` through JNI) from public APIs, so it can go to KAGEX as it is, with a small framework module that speaks each page into a file, plays it on a voice buffer and offers the voices of the language being played. iOS could do the same with `AVSpeechSynthesizer.write` (iOS 13), built on a Mac; the browser's `speechSynthesis` only speaks aloud, so there the module would use it directly, without the voice channel's volume and wait. Android needs a manifest query for the speech service (kagex-release, below). A Config switch picks the game's speech, and turns `kag.a11yReadText` off while it's on, so a line isn't read twice.

## Needing krkrz_dev

These wait on the engine, which kagex doesn't change (`CLAUDE.md`): each gets an `UPSTREAM.md` entry (where, what it costs, the fix) once it's confirmed at the engine `ENGINE_SHA` pins, and the framework works around it meanwhile where it can. The first two are features; the rest were found moving a commercial game to KAGEX's engines at `21d20e9`, and a few of them need only a note in `doc/`.

- [ ] **The game's own mouse cursors, and a jump to the default button**: the game can have its own cursor, a picture matching its art, and another over buttons, with a setting to go back to the system's; and when a Yes/No prompt opens, the cursor can jump to its default button (Yes or No, as the player chooses) or stay. KAG's `[cursor default= pointed= click=]` and `cursorPointed = crHandPoint` are there, but the SDL engine always shows the system arrow, not even the hand over buttons: `TVPGetCursor` returns 0, "not supported yet" (krkrz_dev `generic/visual/WindowImpl.cpp`), and `SetMouseCursor` does nothing (`generic/environ/WindowForm.h`). The engine would map the `cr*` cursors to `SDL_CreateSystemCursor` and load `.cur` or PNG cursors with `SDL_CreateColorCursor`; until then the framework can draw the cursor as a top layer that follows the mouse, with the system's hidden (`mouseCursorState`), switched by a Config setting. The jump needs no engine change: it's commented out in `template/system/YesNoDialog.tjs` (`-curmove`), and the engine can move the cursor (`SDL3WindowForm::SetCursorPos` warps it), so it comes back behind a `scflags` setting (Yes, No or off). Desktops and the browser; phones have no cursor.
- [ ] **Mute or pause in the background**: when the window loses focus the game keeps playing, mutes, or pauses (text, animation and auto mode wait, the sound is muted, and the screen dims with a "paused" mark until the player comes back); a playing movie isn't stopped. The SDL engine gives scripts no `onActivate` or `onDeactivate`, for the window or the application: nothing in krkrz_dev's `sdl3/` posts `AM_PAUSE`/`AM_RESUME` or calls `TVPPostApplicationActivateEvent`, and `SDL_EVENT_WILL_ENTER_BACKGROUND` only stops the drawing (`sdl3/environ/main.cpp`); `WaveSoundBuffer.globalFocusMode` (never, on minimize, on deactivate) depends on the same state. The engine would forward SDL's focus events (`SDL_EVENT_WINDOW_FOCUS_LOST` and `SDL_EVENT_WINDOW_FOCUS_GAINED`) and the move into the background to the activate events. Then a framework setting in `scflags`: mute through `WaveSoundBuffer.globalVolume`, or pause with `System.eventDisabled` (stopping auto mode, voices and the BGM) and dim the screen with an ordinary layer on top (the SDL engine has no `setOverlayBitmap`), and a Config row in the sample, "In the background: keep playing, mute or pause". The same events let the continue save (below) be written as a phone puts the game away. Desktops and the browser (switching tabs); phones stop apps in the background already.
- [ ] **Android: plugins opened at run time free into the wrong allocator**: `libkrkrz.so` defines and exports its own `operator new` and `delete`, and `libc++_shared.so`, loaded with it, uses them for what it allocates itself (a `std::string`'s buffer), but a plugin opened later with `dlopen` resolves its own `delete` to the C++ library's plain one, so the first `std::string` a plugin frees stops the game ("Scudo ERROR: corrupted chunk header", `SIGABRT`). A plugin can take the engine's `new` and `delete` itself (the `ShellExecute`, `SpeechSynth` and `WaveFilters` plugins each carry an `AndroidAllocator.cpp` for it). KAGEX's own Android builds link their plugins into the engine, which this doesn't touch; it's for a plugin loaded at run time (the APK entry below). The fix upstream: don't replace them on Android, or have the plugin loader hand them to plugins; until then, a note for plugin authors.
- [ ] **`user://` storage drops saves without an error**: the media splits `user://<domain>/<path>` at the first `/`, so a name with a doubled slash (a folder ending in `/`, then `/`, then a file, which `System.dataPath`, ending in `/`, invites) hands SDL's storage an absolute path, which it refuses; a write is held in memory and written when the stream closes, where a failure is only logged, so the save "succeeds" and the next read throws "Cannot open storage". That's the save folder on Android, iOS and the web. The fix: collapse repeated slashes in `SDLStorageMedia`, and let a failed write reach the script (or at least the log in a release build). The framework joins its save names as `saveDataLocation + "/" + ...` (`MainWindow.tjs`), so check whether a folder ending in `/` can reach them there.
- [ ] **The file pool deadlocks when it fills**: the allocator calls the storage cache's pressure handler while holding its own lock, and the handler frees into the same pool. A game with about 240 MB of embedded fonts filled the default 256 MB pool at start-up and hung; `filepoolsize=none` in the game's `krkrz.cf` avoids it (on Android, iOS and the web too since kagex-release writes it into their `config.cf`).
- [ ] **`Storages.copyFile` throws for a file that isn't there**: fstat's `copyFile`, which Wamsoft's and older KAG scripts were written against, returned false, so rotating saves that copy an empty slot fail on the first quick save. The fix: return false, or say it in `doc/` (the porting notes), and have the framework's own save rotation (below) check first.
- [ ] **Android and iOS: a desktop game's window logic misfires**: the engine draws on a fixed 1920x1080 surface scaled to the screen, its window is full screen from the start (so a switch to full screen does nothing), its inner size is always 1920x1080, and a primary layer bigger than that is shrunk to fit: a game that chose a zoom for a desktop window and had a 1920x1440 primary layer drew at three quarters, at the top of the phone. A section in `doc/` for anyone porting, and perhaps `System.platformTag` checks in the framework's own window code.
- [ ] **Android: the navigation bar's strip stays white**: the window stops above it (2400x1017 on a 2400x1080 screen) and the strip isn't drawn. The fix: draw edge to edge, or fill it black, in the Android project (krkrz_android's, or kagex-release's changes to it in `tools/release/scripts/android-engine.py`).
- [ ] **A multi-line text field for Elements screens**: ElementsDialog's `input_box` is one line, so a save comment, a note or anything longer needs one field per line.
- [ ] **Notes for plugin authors**: a global of an engine type (`ttstr`) at namespace scope is built when the library loads, before `V2Link` hands over the engine's functions, and the engine reports "A dynamic link library (DLL) initialization routine failed"; and a plugin opened at run time on Android needs the allocator fix above. A note in `tools/release/README.md`'s "Your own plugins", which a game's own plugins (0.13.0) make the place for; it could also say for every plugin what `tools/live2d/README.md` says for the Live2D one, that a Linux plugin needs the glibc it was built against (one built with GCC 13 on glibc 2.38 asked for `__isoc23_sscanf`), so build it in the Steam Runtime as `--steamrt` does.

## Fixes in kagex-release

Found building a game for every platform with kagex-release, and still there at 0.14.0.

- [ ] **A game's own plugins in the Android APK, without an engine package of its own**: since 0.13.0 a game's own plugins in `plugins/windows/`, `plugins/linux/` and `plugins/macos/` go into the desktop packages, and on the web, Android and iOS a plugin of the game's own means an engine package built with it (`tools/release/README.md`, "Your own plugins"), so `check` warns about a `plugins/android` folder. But the Android engine also loads a plugin it doesn't have built in as `lib<name>.so` from the app's libraries, so kagex-release could copy `plugins/android/<abi>/*.so` into the Gradle project's `app/src/main/jniLibs/<abi>/` and let a game add a plugin without building an engine (such a plugin must take the engine's `new` and `delete`: the allocator entry above). iOS and the web can't do this: they load no plugins at run time.
- [ ] **Additions to the Android manifest**: text to speech needs `<queries><intent><action android:name="android.intent.action.TTS_SERVICE" /></intent></queries>` (apps targeting Android 11 or later see no speech service without it), and the engine package's manifest has none. Put the query in the template (it costs nothing), or add a `release.json` field for manifest additions.

## Saving and moving through the story

- [ ] **Continue where you left off, emergency saves and rotating saves**: closing the game keeps the player's place, and so does a phone killing it, and the next start offers to skip the title and carry on; running out of memory, the game saves first and offers to restart, and on a script error it keeps the system variables, so read marks survive; quick and auto saves go round a ring of slots, so one wrong key can't overwrite the only save. Today there's one quick-save slot (`quicksaveAction` and `quickloadAction` in `data/main/Override.tjs`) that no key, button or menu item calls, the title's Continue opens the Load screen, and in a release build an uncaught error shows its message and ends the game (`System.exceptionHandler`, `template/system/Initialize.tjs`), losing read marks and the player's place. The framework gets a continue slot, the rotation and the error path; the sample the prompt on the title and a switch in Config. Until the engine reports going into the background (above), the continue slot is written when the game quits, at each scene start and every few clicks; on the web and phones saves go to `user://` through the temporary-file path `saveThumbnailAndData` already has. It matters most on Android and iOS, which kill apps in the background, and on the web, where tabs close.
- [ ] **Saves that survive script patches, and a report of what changed**: after a patch, players' saves still resume at the line they were made at. A save keeps its scene's hash and save point, and when the hash differs it starts at the top of its scene (`KAGEnvPlayer.onRestore`, `doc/scn.txt`); the hash covers the script's MD5, the macros, `envinit.tjs` and `charinit.csv` (`SceneParser.sourceKey`), so a patch that only changes `envinit.tjs` sends every save back to the top of its scene. kagex-release and `-scncompile` would write each build's save points beside its file list (`<exe>-<version>-points.json`: per scene, each point's text number and a hash of that text and its speaker), and a build with `output.patchFrom` lines the old texts up with the new by those hashes (as a diff does, since text numbers shift when lines are added) and writes a map from the old points to the new into each `.scn`, for the points that moved. `onRestore` then maps the save's point instead of resetting it, and keeps it when no point moved. For the developer, a `scndiff` tool beside `scn2ks` in scnfile reads the same JSON and PSB and prints the texts that changed, and those whose World state on screen differs (each shown object's image, filters, final properties and stacking); CI could run it on the sample. Data only, so every platform.
- [ ] **Rewind and scene-by-scene navigation**: back-skip rewinds quickly through read text to a choice or the start of a scene; other buttons jump to the previous choice, or the previous or next scene, each with an optional confirmation; and replaying a route already read, the game offers to skip the part read. BACK goes back one click (`player.rollback`), the backlog's marks jump to a line, and R1 skips to the next choice or unread text (`skipToNextStopByKey`); `MainWindow.tjs` has `enterSkipOnReadedLabel` for the last, but the sample doesn't offer it. The player gets a reverse play built on the history blocks and `storeKagState`, and previous and next scene from the scene labels, next to `rollback` in `KAGEnvPlayer.tjs`; the sample gets message-window buttons for them, a switch for `enterSkipOnReadedLabel`, and entries in the action table (below). Compiled scenes only, as BACK is; on a phone, a long press or a flick.

## The message window and text

- [ ] **Face windows that follow the speaker**: when a character speaks, their face appears by the message window in the outfit, pose, expression and lighting of their sprite, crossfades to the next speaker, and leaves for narration, CGs and when the window closes; a character who isn't on stage (a phone call, a voice off-screen) can be a face only, and Config can turn faces off. Scripts need no face commands, only a crop offset and zoom per character. The World can already draw the speaker's face into the message window when the name is shown (`faceLevelName`; `facewin`, `faceon`, `faceoff` and `KAGEnvImage.BOTH`/`BU`/`FACE` in `doc/world.txt`; `KAGEnvironment.redrawFace`), and layered characters take `facezoom`, `facexoff` and `faceyoff` from `charinit.csv`, but the sample turns it off (`"faceLevelName" => void` in `data/main/envinit.tjs`), and it's a drawing into the message layer: nothing changes between speakers, and the only hiding rule is "no name". First turn it on in the sample for Ai and Pip; then a framework plugin on top with the rules (follow the speaker; hide for narration, `msgoff` and CGs; crossfade; a crop table per character; a tag to change it per scene; a Config switch) as World state, so the compiler (`SceneParser.tjs`, `KAGEnvForParse`) carries it into compiled scenes, saves and Back, and a demo scene with a speaker off-screen. The backlog's face icons and favorite voices (below) reuse the crop table, and objects that follow others (below) would let the face follow the sprite without special code. Every platform.
- [ ] **A menu language of its own, and two languages at once**: since 0.10.0 the story's language switches while playing, translations are compiled into each `.scn`, and interface strings and stand-in files come from `data/lang/<code>/`, but the story and the interface share one language, and only one is shown at a time. What's left: a menu language apart from the story's (a second setting, with the story's `data/lang` folder taken off the search path for interface files); a second language under the first, for language learners or two players, which the compiled scenes already carry, so it's the message window's drawing, a font scaled to fit two, a key that swaps them, and perhaps both in the backlog; and checks for translators as the compiler matches texts (narration given a name, a speaker whose name differs, a count that doesn't match), with a per-language report from `-scncompile` of the texts still in the script's language. Chinese needs SC and TC fonts, too large for the web build's download, so they'd ship as language packs (`KAGMountPatchZip`).
- [ ] **Message window styles per scene, in colours the player picks**: the window changes its look for flashbacks or another character's viewpoint, and keeps it after a load or going back; the player picks each style's colour, and the colour of read text, on a colour wheel. For the writer, one style tag in a macro, plus macros for letterbox bars and frames laid over the scene. KAGEX has one message window style (`[initscene]` in `data/scenario/macro.ks`, drawn by `make_ui.py`), and the player can't choose colours. The framework gets a style tag kept in World saves (a KAG plugin that stores the style with the World's state); the sample a colour wheel in Config, a flashback demo with the bars, and a second frame from `make_ui.py`. Tint with `holdAlpha` set, since the web build writes alpha 0 with the `omPs*` modes (`CLAUDE.md`, `setCGImage`). Every platform.
- [ ] **Outline and shadow together, and gradient text**: message text, names and choices with an outline and a drop shadow at once, a look common in commercial games, and colours that shade from one to another down each line (the fill, the outline or the shadow), without putting text into images. Today an outline replaces the shadow: `MessageLayer.drawTextToLayer` draws either `edge` or `shadow`, and `RichTextFontApp.updateApp` (krkr_richtext's path, which `drawStyledRun` uses too) says "an edge replaces the shadow"; only `GdiPlusFontApp` draws both, with layerExDraw, which only the Windows-only engine has. When both are on, draw the shadow, then the edge, then the fill: krkr_richtext's `Appearance` takes all three (`addShadow`, `addStroke`, `addFill`), so lines drawn whole mostly need `updateApp` changed, while the paths that draw a character at a time (the browser, iOS, vertical text, `hasChFadeLayer`) need three `drawText` calls and the fill on a layer above the outlines, so a thick outline never covers the character before. Keep today's look behind a `Config.tjs` switch, since existing games may rely on the shadow going. Gradients: new `[font]` and `[deffont]` attributes (for example `gradcolor=`, `edgegradcolor=`, `shadowgradcolor=` and `graddir=`), kept in the message layer's store and restore and in the compiled font steps, and drawn through the glyphs' alpha (a gradient copied in with `holdAlpha`), because `Appearance` takes solid colours only, spanning the line height so every character shades alike. Names follow through `NameLayer`, choices through `SelectLayer.drawTextToLayer`; the sample gets a line in `layer.ks` and the demo menu's choices. Every platform.
- [ ] **The game's fonts, and one table of text styles**: the fonts a game ships listed once, with their licences and languages; a role for each font per language (message, interface, headings, numbers); and named styles in one table (font role, size, colour, alignment, outline, number of lines) that every screen draws its words through, so restyling or translating a screen is a table edit. Noto Sans JP ships in `template/system` and `Initialize.tjs` registers it, but a game has no list of its own fonts, and the sample sets faces and sizes in code (`"Yu Gothic Medium,Yu Gothic,Noto Sans JP,Roboto"` in `data/main/Config.tjs`, `MyHistoryLayer.tjs`, `about.ks` and five times in `Override.tjs`) and fits text by hand (the Replay tiles shrink the size in a loop, the save slots cut the scene's name). The framework gets a fonts file (file, face, caption, licence, languages) registered at start-up, with the licences shown in About; font roles resolved per language (`KAGLanguage`), so a Chinese language pack changes one entry; a style table in `Config.tjs` or JSON, with parents and wildcards; and a function that draws a text in a style within a rectangle (aligning, wrapping, fitting a number of lines, with the outline and shadow above), with button captions taking a style name. The sample's save slots, Replay tiles, Search rows and About move to styles. Every platform.
- [ ] **Text settings for the player, with a live preview**: on a Text tab of Config, the message font, the outline and shadow on or off with their colours, and a small message window that types sample lines at the chosen speed and pauses as auto mode would, in the chosen font, colours and window opacity; the message on screen takes the new look at once. The sample's Config has text and auto speed and nothing about how text looks. The framework's font choice is a menu item (`chChangeFontMenuItem`) whose `MainWindow.selectFont` calls `Font.doUserSelect`, which the engine doesn't have (`getFontFaceList` works), so replace the dialog with a list of the game's own fonts for `kag.chDefaultFace` (the web build has no system fonts, and the SDL engine draws an unknown face with an icon font); keep the outline and shadow settings in `scflags` as the message layer's defaults (`defaultEdge`, `defaultShadow`, `defaultEdgeColor`); and turn `MessageLayer.redrawTextEnabled` on when they change, so coming back from Config draws the message again. The preview is a message layer on the Config screen, fed lines (through `tr()`) by a timer the way KAG feeds the game's. It builds on the fonts list and the outline and shadow above, and on the Config tabs (below). Every platform.
- [ ] **Auto-mode speed, auto waits that grow with the line, and read-text speed in Config**: a text speed of its own for auto mode, auto waits longer after long lines by an amount per character the player sets, the auto wait shown in seconds in Config, a small mark at the click wait for a line read before, and the speed for read text offered in the sample. That speed exists (`userCh2ndSpeed`, `template/system/MainWindow.tjs`), set from the framework menu's "Read Text Speed", but the sample's own menu and Config leave it out; `waitAuto` waits `autoModePageWait` or `autoModeLineWait` whatever the line's length, and there's no auto-mode text speed. Framework: a per-character term in the auto wait (counted as the message layer draws, or taken from the compiled text's length) and an auto-mode speed, both in `scflags`. Sample: Config sliders for the read-text speed (with "same as unread") and the wait per character, with the auto wait in seconds, and a click glyph of its own for read text beside the indicators (below). Every platform.
- [ ] **A name box that fits, fades and follows the window**: a long name squeezed to fit its box instead of running out of it; the box fading in and out, and crossfading to the next speaker with the text's fade (not while skipping); and the box going more transparent with the window. `NameLayer` (`template/system/MessageLayer.tjs`) draws a frame image (`[position nameframe=]`) or a name image (`nameImageMap`), shows and hides at once, lets a long name run past the box, and ignores the window's `frameOpacity`. Add `[position namefit=squeeze|shrink]` (stretch the drawn name to the box, or use a smaller size), a `namefade=` for the fade and crossfade, a text area inside the frame, and the frame drawn at the owner's `frameOpacity`, so a window-opacity slider covers it, all kept in `store` and `restore`; and a long display name in a demo. Every platform.
- [ ] **A glossary of terms marked in the text**: a term in a line (a place, a gadget, a piece of slang) drawn in a colour, whose explanation a click or a tap opens in a panel without leaving the scene (hints don't show on the SDL engine), and a Glossary screen of the terms met so far, sorted by reading and grouped by first letter or kana row. For the developer, one table of terms, with aliases and ruby; scripts mark terms, or listed words are marked by themselves, chosen per term. KAG's `[link]` takes a `hint=` that nothing shows (the tooltips below), and nothing handles terms. A KAG plugin: a terms file per language (in `data/lang/<code>/`, which already stands in for files of the same name); a marking tag (for example `[term]...[endterm]`) or automatic marking, which the compiler understands (`SceneParser.tjs`, `KAGEnvPlayer.tjs`), so compiled scenes, translations, the backlog and Search keep the marks as they keep `[emb]`, and the backlog's terms stay coloured and clickable; and the terms seen recorded in `sf`. The sample gets a Glossary tab in Extras and two or three terms in the demos (KAGEX, World, Pip), unlocked when read. Every platform.
- [ ] **Naming the protagonist**: the player enters the hero's given and family names on a screen of their own; an empty field falls back to the default, words on a refusal list are refused, and the names appear in the text and in the name box. The parts exist: `[edit]` fields (the Search screen's, `data/main/searchmode.ks`), `[emb]` worked out when its text is shown in compiled scenes, a `nameAlias` starting with `&` as an expression (`KAGEnvironment.nameAliasOf`), and the hero's name in `kag.flags.name` and `family` against `kag.defaultName` and `kag.defaultFamily` (`KAGEnvironment.isDefaultName`): while the name is the default a numbered voice plays the take with `N` in its file name, and the plain take once the player changes it (`KAGEnvCharacter.getVoice`, whose comment says the reverse of the code), so a line that says the name can have a take that says it and one that doesn't. Engine 2.6.5 starts text input when a field has focus, which brings up a phone's keyboard. The sample gets a name screen before the first demo or from Config (defaults, trimming, a short refusal list), a demo line with `[emb exp="f.name"]` and a speaker whose `nameAlias` is `&f.name`; the framework a check hook for names, and Search and the backlog keeping the text as it was shown (Search matches the compiled text, where `[emb]` is still an expression, so it can't find the name today). `doc/world.txt` should explain the `N` takes, and `getVoice`'s comment should match the code. Every platform.

## Screens, menus and controls

- [ ] **Rebindable keys and buttons, gestures and a touch toolbar, from one action table**: on a phone the player swipes to skip, auto-play, rewind or open the log, and has a small toolbar whose icons, order, size and opacity they choose; on a desktop there are right-drag gestures and the mouse's side buttons; and the player can reassign keys and controller buttons. Since 0.12.0 the window's keys are `kag.keyBindings`, which a game adds to with `kag.bindKey`, the pad sends keys through `kag.padKeyMap`, and the controls list shows them, but the player can't change them, the mouse has no gestures, and touch is only taps. ## The World and staging

- [ ] **Shorthands for writers: depth presets and pose/face codes**: one word puts a character further back (smaller, and behind those at full size), another to the left, and a code like `102a` sets pose 1 and face 02a. If `KAGEnvImage` gains a pattern table (a regular expression that turns a word into a pose and a face) and positions that can set the level, reset the position and bring to the front at once, these are only entries in the sample's `envinit.tjs`; otherwise this is documentation only. The staging kit here would sit well beside them. Every platform.
- [ ] **CG variations from one layered file, and smaller packages for flat ones**: each event CG is one layered file from the artist, and a table names each variation (expression, lighting, clothing) as a set of visible layers, which scripts, the CG gallery and save thumbnails use as if they were images; flat variations are stored as only the part that differs from their base. Characters come from PSD and CLIP files since 0.11.0, and other images load one layer through `psd://` and `clip://`; `PSDLayer` (`template/system/psdlayer.tjs`) can show and hide a file's layers, but only characters use it; kagex-release already splits every PSD and CLIP file into a layer structure and a picture per layer; and nothing stores variations as differences. Sample: Pip's CG as one layered file with two or three variations.

Sample: a choice in a demo that gives Pip a different outfit in a later scene. Every platform.
- [ ] **Characters that make room for each other**: a character entering comes in at the right while everyone already on stage slides over, so that two, three or four stand evenly spaced; one leaving closes the gap, one cutting in takes the middle, and a tag pushes characters apart to make room at a spot. Every platform.
- [ ] **A credits roll timed to the music**: the staff list is a text file with headings, names, sizes and pictures that scrolls up over exactly the length of the ending song (or between two labels in it, adjusted by a few milliseconds), with CGs beside it at set points; it saves and loads mid-roll like any layer, and a click skips it only once it has been seen. Every platform.
- [ ] **Objects that move with others: attach, follow and mask**: a prop, a shadow, a sweat drop or a glow attached to a character moves, zooms and leaves with them; an overlay can be clipped to the character's outline; a copy can follow another object's picture as it changes (a reflection, a second view); and an object can be placed relative to another. `KAGEnvImage`'s commands (`template/system/KAGEnvImage.tjs`) include `clip`, `script` and the colour corrections, but no linking, and only characters' own emotion layers (`EmotionLayer`) attach. Framework: attributes on World objects for a parent, a mask taken from another object, an object to follow and a place relative to another (for example `parent=ai`, `follow=ai`, `relative=ai,100,-50`), kept in World state so compiled scenes, saves and Back carry them; a child takes its parent's position, zoom, rotation, camera and shift rules and is deleted with it unless told otherwise, and a mask copies the other object's alpha each time it redraws. The face windows (above) could then follow the sprite this way. Sample: a speech-bubble prop on Pip and a light clipped to Ai. Every platform.

## Sound, voices and movies

- [ ] **Movies handled as commercial games handle them**: an opening or ending can't be skipped the first time but can once seen; skip mode stops before an unseen movie, and can be set to pass seen ones; skipping with a right click can be turned off; Extras has a Movies tab, and a song heard in a movie unlocks in the music room; a smaller version plays when the window or screen is small, or when the player picks it; and one tag does the fades and colours around a movie. KAGEX has KAG's video tags (`template/system/Movie.tjs`) and movies on layers (`movie=`, `GFX_Movie.tjs`; `.webm` on the SDL engine), one file per movie, which the web build downloads whole, a movie volume, and music-room unlocks by `sf["bgm_"+NAME]` (`KAGEnvBGM.tjs`, `musicInit`); nothing records which movies were seen, picks a size or stops skip mode before a new movie, and Extras has no Movies tab. Framework: a `[movie]` tag over the video tags that records a seen flag, allows a skip only once seen, cancels skip mode before an unseen movie, takes `song=` to set the `bgm_` flag and fills colours before and after; two Config switches (skip movies while skipping, right click skips); and a name step that tries `<name>_<quality>` (for example `<name>_sd.webm`) by a setting: automatic by the window or screen size, smaller on the web and phones, or the player's choice. Sample: a Movies tab that lists movies from a CSV with unseen ones locked, and the test movie as a short opening. kagex-release could make the small versions once it converts video (the porting kit below). Every platform; phones and the web gain most from the small versions.
- [ ] **Subtitles for movies**: timed lines over a movie (translated lyrics, or dialogue for players who can't hear it) from a cue file beside each movie, one per language. `GFX_Movie.tjs` takes `loop` and `alpha`, KAG's video layer (`Movie.tjs`) has no subtitles, and the screen readers read messages, not movies. Framework: `[video subtitle=]` and an option on the World's movie flip; cues in a standard format (WebVTT or SRT), one file per language in `data/lang/<code>/`; drawn on a layer above the video in the message text's style, timed from the movie's position; a Config switch, and each cue announced to the screen reader. Sample: subtitles for `data/video/test.webm` in English and Japanese. kagex-release packs the cue files as they are (they're text). Every platform.
- [ ] **Voices that fade out when cut**: clicking past a voiced line fades the voice out over a moment instead of cutting it off mid-syllable; Config offers stop, fade or keep playing, and a slider for the fade's length. `KAGEnvCharacter.stopVoice` calls `soundBuffer.stop()`, so a click during `waitVoice`, `voicecut`, `voicecutpage` and `env.stopAllVoice` all stop at once, and each character has one `VoiceTrack`, so a fading voice and the next can't overlap. Framework: a fading stop on `VoiceTrack` built on the engine's `WaveSoundBuffer.fade` and `onFadeCompleted`, which sends the stop events, ends the waits and lifts the BGM-down at once, so the game goes on without waiting for the fade; a second track per character, so its next voice can start while the last one fades; skip mode, auto mode's page change and loading still stop at once. Sample: the setting on the second Config page. Every platform.
- [ ] **Loudness correction per file and per kind of sound**: a table evens out levels without re-recording (a quiet character's voices raised by 3 dB, one loud song lowered, every extra's voice turned down), applied as each file is decoded, so the files stay as they are. `doc/world_inst.txt` ("Regarding Track Gain Adjustment") says to fix levels in the files or with VorbisGain, and a character's voice can be scaled by an undocumented `init.voiceVolume` (`KAGEnvCharacter.resetVoiceVolume`); the engine already has `WaveSoundBuffer.setGainQueryCallback` for Ogg Vorbis and Opus (krkrz_dev `src/core/common/sound/WaveIntf.cpp`). Framework: two tables, a gain in dB per kind of sound (a speaker's voices, BGM, SE) and per file, which wins, and the callback that reads them. Tool: kagex-release, which turns WAV and FLAC into Opus, measures each sound's loudness as it converts it (EBU R128, for example with libebur128, MIT), writes the per-file table to bring each folder to a target, and lists the files far from it; WAV files kept as WAV get no gain, which it should say. Every platform.
- [ ] **Voices from where the speaker stands, and volume per line**: a character on the left is heard a little from the left and one at the back sounds further away, with a Config switch for players who prefer voices centred; and a writer can make one line quieter (a whisper) or pan it (`[ai voice=12 vol=60]`). Since 0.12.0 sound effects can be placed on the stage (`[se pos= xpos= level= char=]`, the engine's 3D sound through `KAGEnvironment.se3DPosition` and `KAGEnvSE.tjs`, with distances from envinit's `se3d`), but voices aren't placed: `KAGEnvCharacter.playVoice` and `resetVoiceVolume` only set the volume, and the voice tag takes no volume or pan. Framework: with a `voice3d` setting in envinit and the player's switch on, a character's `VoiceTrack` uses `use3D` at the character's place and follows moves as a looping placed SE does, with off-stage and face-only speakers centred; `vol=` and `pan=` on the voice tag, stored like `voice=` and cleared after the line. Sample: Ai and Pip at the two sides in the Character demo, and a switch on the second Config page. Every platform whose engine has 3D sound; elsewhere voices stay centred.
- [ ] **Voice files that find their speaker**: voice IDs from the recording script go straight into the scenario, and the game works out from the file name who is speaking; several can be listed for characters speaking together, and an unknown name is reported. Voices are numbered per character (`"voiceFile" => "pip%s%06d"` in the character's envinit entry, `[Tae voice=1000]`) and named with the character's tag (`doc/world.txt`, "Voice Specification"), and `nextvoice` plays two at once. Framework: a tag that takes voice files and finds each one's speaker by reading the characters' `voiceFile` patterns in reverse, in KAG and in the compiler (`SceneParser.tjs`), so `-voicelines` and kagex-lipsync see the same pairs; a file that matches no one is a compile warning. Every platform.

## Tools for developers

- [ ] **A playthrough tester and debug helpers for your own game**: run every route of a game unattended in skip mode, picking a given choice at each menu, and get the first script error with where it happened, or a "stuck" after too long in one place; one-line helpers that log every tag with its timing, the visible layer tree or the World's definitions; and a Debug menu for writers: restart the current script from its top (Reload Scenario reloads it where the player is), go back 100 lines or to a line number, open the script at the current line in an editor, pick an earlier point to go back to, view and change the game's flags from a commented list, copy the current voice's file name or a description of the scene, and write a bug report. `tools/smoketest.py` plays the sample's own steps through the REPL file channel and only starts the template, and nothing points at a developer's own routes; the sample's Debug menu has Load and Reload Scenario, the console, Controller, System Reset, the debug levels and window, Return to Previous Trace, the KAGEX log and voice speed. A `tools/playtest.py` on smoketest.py's REPL channel and engine handling (headless on Linux with the offscreen driver, in a window on Windows), with choices given as a list (`--choices 0,1,0`) or every branch in turn, its own `-datapath` and log per run, and a way past the single-instance lock for parallel runs (`createAppLock` is keyed by the executable's path, `template/system/Initialize.tjs`); framework helpers loaded only in debug mode (a route runner over the compiled scenes' choices, a tag trace, a layer dump, a World dump, and an `-allseen` switch that's never saved); and the Debug-menu items, in debug mode only: restart and go to a line (`player.seek` by text number in compiled scenes, the line of an automatic label in scripts KAG plays), open in an editor (an `-editor=` command with the file and line, which needs `System.shellExecute`, above), a flags screen from a list file (name, comment, value) as an Elements screen, copying through `Clipboard.asText` (which works on SDL), and a bug report (position, flags, the log's last lines and a screenshot in one folder). Desktops and CI; the scene data it plays is what every platform ships.
- [ ] **A porting kit for older Kirikiri games**: move an existing Windows Kirikiri or KAGEX game to KAGEX's engines without rewriting it. The README's "Not available on the SDL3 build" lists the missing Windows plugins; 0.12.0's menu bar draws a game's own `KAGWindow_createMenus` menu, which covers menu.dll for games on KAGEX's framework; a movie named without its extension finds its `.webm`; and kagex-release converts sounds and images but not video. A `doc/porting.txt`: the engine differences, the rules for stand-ins (overrides of native class methods installed before any instance exists; a stand-in takes every option its callers pass), and the notes for Android and iOS (the engine entries above: the fixed 1920x1080 surface, full screen from the start, the save folder's slashes, `Storages.copyFile`), with one more: the Android engine links its built-in plugins before any script runs (`TVPLoadStaticPluigins`), so a game that checks for a plugin's method to decide whether to link it skips the whole block, settings included (a voice script never set `WaveSoundBuffer.enableGetSample`, and every voiced line with a moving mouth stopped with 'Member "enableGetSample" does not exist'). KAGEX's own scripts already guard each link that way on purpose (`KAGLinkPlugin`, `CLAUDE.md`); the note is for games brought from elsewhere. An optional template helper that sends `Plugins.link` through a table, mapping each plugin to a KAGEX plugin (renamed or not), a script stand-in, something built into the engine, or "missing", so the game's own fallback runs, with stubs for Windows-only calls; and the stand-ins worth having for any old game, written from what scripts ask of each API: win32dialog.dll's dialog templates drawn as Elements panels (many games' config and save dialogs are built on it; the largest piece), the original engine's data packs (`Scripts.saveDataPack`, `loadDataPack`, `Storages.saveOctet`) and getLangName.dll's system language name. Stand-ins written for a port copy no plugin code and can be a start, but one for textrender.dll would follow a Wamsoft DLL's interface, so KAGEX would want its own design there. An optional video step in kagex-release (VP9 and Opus through ffmpeg, with a quality check), which could also make the small movie versions above, and the game's icon taken from its old `.exe` as `identity.icon`. The tools run on desktops; their output works on every platform.

## Looked at, not planned

- M2's E-mote characters (`emoteplayer`): E-mote's player comes only from M2, through an application and a contract for its SDK (even the plan for small developers), and no player for SDL3 Kirikiri Z is public: Wamsoft's krkrz plugin is private, and M2's Kirikiri one is a closed DirectX DLL for Kirikiri 2. A player of our own, written from the reverse-engineered format, would get around M2's licence (FreeMote, the work on that format, is noncommercial only). Live2D covers the same ground (`doc/world.txt`, "Live2D Characters"; the `l2d` flip). If M2's SDK is ever in hand, the plan is Live2D's: a krkrz plugin around its player library drawing through `GLCompositor`, World characters on `KAGEnvCharacterEyeLip.tjs`, an `emote` flip type, a stand-in for the smoke test, and the SDK in a private repository for CI.
- `layerExAreaAverage`: shrinks by area averaging, which `shrinkCopy` already does, in half the time and without the glitches `stretchCopyAA` left in text.
- `layerExLongExposure`: averages frames into one image, an authoring tool for rule images, which `tools/assets/make_rules.py` makes.
- `lineParser`: `[].load()` already reads a file line by line, and the framework parses with KAGParserEx and csvParser.
- `expat`: XML parsing; nothing in kagex reads XML, and only the desktop builds have it.
- krkr_richtext's per-character timing (`StyledLayout`'s `<delay>`, `<wait>` and `calcShowCount`): it times a text laid out whole, while KAG's conductor gives the message window a character at a time with its own waits, skipping and auto mode, so KAG keeps timing the characters (krkr_richtext lays out and draws each line of them: `useStyledLayout`).
- `krkrgles` (Windows only): an OpenGL ES context through ANGLE, for engines without one. The SDL engine draws with OpenGL ES, and krkreffekseer, krkrthreepp and krkrlive2d use its context.
- BISHAMON particles and Direct3D: another company's particle middleware, on Windows' Direct3D only; KAGEX has Effekseer for particles, and krkrthreepp's 3D on every engine since 0.14.0.
- Windows-only features of Wamsoft's games: stay on top, the taskbar preview, the panic key, the Windows display methods, full screen across several monitors, the mouse wheel through DirectInput, the movie display modes, the bitmap allocator, Win32 dialogs and launcher programs. They're tied to Windows, and KAGEX's engines run on seven platforms.
- Comments typed on saves: Wamsoft's games take them in a Win32 dialog, and Elements screens have no multi-line text field for them (above).
