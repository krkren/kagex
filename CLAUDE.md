# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this repository is

`kagex` (origin: https://github.com/krkren/kagex) is an English-translated, SDL3/Linux-ported fork of **KAGEX** — Wamsoft's extension of the Kirikiri **KAG3** visual-novel framework (affine layers, layer level ordering, automatic actions, and the "World" environment system). It is pure script and asset content: TJS2 (`.tjs`), KAG scenario (`.ks`), CSV, and images/audio. There is **no build step, no test suite, and no linter** here.

The engine that runs it is not part of this repo. `krkrz.exe`, `SDL3.dll`, `plugin/`, and `savedata/` are all gitignored local artifacts, built from the sibling `../krkrz_dev` umbrella repo (the SDL3 variant of 吉里吉里Z; see `../krkrz_dev/CLAUDE.md`). `extrans` used to come from https://github.com/krkren/SamplePlugin; `../krkrz_dev` now builds it too. `KAGEX Initial Setup.txt` still mentions a `setup.bat`; that script (and `setup.sh`) was removed in commit `f6d1767` — `git show f6d1767^:setup.bat` is the reference for which build outputs get copied where (`krkrz64.exe` → `krkrz.exe`, `core/plugins/*/*.dll` + `krmovie.dll` → `plugin/`). On Linux the outputs are `build/x64-linux/core/Release/krkrz` + `_deps/sdl3-build/Release/libSDL3.so*` → repo root and `core/plugins/*/Release/lib*.so` → `plugin/`. With Arch's CMake 4 / newer GCC, configure needs `-DCMAKE_POLICY_VERSION_MINIMUM=3.5` and the full build fails inside the `krkrthreepp` plugin, so build only the targets kagex uses: `cmake --build build/x64-linux --config Release --target krkrz KAGParserEx csvParser layerExBTOA layerExImage layerExRaster scriptsEx shrinkCopy extrans krkr_richtext`. On Linux `libkrkr_richtext.so` links but won't load (`undefined symbol: png_get_valid`): its link line repeats `libfreetype.a` after harfbuzz, past the png/zlib/bzip2/brotli archives. Relink it with those archives appended: take the command from `ninja -f build-Release.ninja -t commands core/plugins/krkr_richtext/Release/libkrkr_richtext.so | tail -1` (in `build/x64-linux`) and add `vcpkg_installed/x64-linux/lib/{libpng16,libz,libbz2,libbrotlidec,libbrotlicommon}.a -lm` at the end.

## Running

```bash
./krkrz.exe                   # Windows, from the repo root; project dir defaults to data/
./krkrz -datapath=savedata/   # Linux; current engines otherwise save to ~/.local/share/wamsoft/krkrz/
```

- The engine treats the first positional argument as the project directory, and looks for `startup.tjs` in it. With no argument it uses `data/` next to the exe. Engine options are `-name=value`; a bare word gets taken as the project path (a past run with a stray `usepseudo` token failed with "Cannot find storage startup.tjs").
- The only feedback loop is running the game and reading **`savedata/krkr.console.log`**. It is **UTF-16LE** and appended across runs — read it with `iconv -f UTF-16LE -t UTF-8 savedata/krkr.console.log | tail -n 200`, and look for `Script exception raised` / `An exception occured at <file>(<line>)`. Filenames in traces are lowercased.
- The game forces full-screen. To test without taking over the screen, run it headless: `SDL_VIDEO_DRIVER=offscreen SDL_AUDIO_DRIVER=dummy ./krkrz -datapath=savedata/ -replfile=<dir>`, and drive it through the engine's REPL file channel (`../krkrz_dev/src/core/doc/REPL.md`: write TJS to `<dir>/cmd.tmp`, rename to `cmd`, read and delete `<dir>/resp`). Under the offscreen driver `Agent.captureScreen` returns black with the default GL draw device, so render `kag.primaryLayer` into a new Layer with `piledCopy` and `saveLayerImage(path, "bmp")` (that BMP's header says the pixels start at byte 56, but they start at 54; BGRA, bottom-up). `piledCopy` reads the layer buffers, so it hides anything that never reached the screen (a missing `update()`). To see the real frame, add `-drawdevice=sdl`, then `kag.setZoom(1, 1), kag.setInnerSize(1920, 1080)` and `Agent.captureScreen(path)` (a PNG written on the next frame). `Agent.click` takes window coordinates: the offscreen window is 1024x768 with the 1920x1080 game letterboxed into it.
- `savedata/*.ksd` persists system/scenario variables (`sf.*`, `scflags`) between runs, including things like the saved full-screen preference. When a config change appears to have no effect, stale savedata is a likely cause.

## Layout and load order

- `template/` — the reusable KAGEX framework. `template/system/*.tjs` is the whole runtime (~60 files); the other `template/*` folders are empty placeholders for a new game.
- `data/` — the sample game. `data/startup.tjs` does **not** have its own `system/`; it adds `../template/system/` to the auto path and executes `../template/system/Initialize.tjs`. Shipping a real game means copying `template/system` + `template/startup.tjs` into `data/`.
- `doc/` — the KAGEX reference, in English: `kagex.txt` (new/changed tags vs. stock KAG3), `action.txt` (action system), `world.txt` / `world_inst.txt` / `world_use.txt` (World extension: `envinit.tjs` schema, character/stage/time tags). Read these before changing tag behavior; stock KAG3 knowledge alone is not enough.

`template/system/Initialize.tjs` drives everything, in this order:

1. Registers auto paths: `data/` then a fixed list of subfolders (`video, others, rule, sound, bgm, fgimage, bgimage, scenario, image, system, voice, face, init, sysscn, main, evimage, thum, uipsd`), each also accepted as a `<name>.xp3` archive. **Later-registered paths win**, so anything under `data/*` shadows the same filename in `template/system/`. Storage lookup is by bare filename across all auto paths — filenames must be globally unique unless shadowing is intended.
2. Runs `Storages.tjs` (`data/main/Storages.tjs`) — add nested asset folders there via `setupSubFolders([...])`; a new top-level folder outside the fixed list is not searched.
3. Links plugins (see below), then loads `AppConfig.tjs` (optional) and `Config.tjs`.
4. Loads the system classes, then `Override.tjs`, creates the `kag` window, attaches `KAGWorldPlugin` (`world.tjs` + `KAGEnv*.tjs`, configured by `envinit.tjs`), runs `AfterInit.tjs`, and finally `kag.process("first.ks")`.

In the sample, the game-side hooks all live in `data/main/`: `Config.tjs`, `Override.tjs` (class/function overrides, loads `MyHistoryLayer.tjs` / `MyYesNoDialog.tjs`), `AfterInit.tjs` (key bindings etc.), `envinit.tjs` (World definitions: times, stages, characters, poses), `first.ks` → `logo.ks` → `title.ks`, the system-menu scenarios (`config.ks`, `save.ks`, `load.ks`, `cgmode.ks`, `musicmode.ks`, `replay.ks`) and their CSV lists. Story/demo scripts are in `data/scenario/` (`s0001.ks` is the demo menu). Prefer these hooks over editing `template/system/` when a change is game-specific.

## Conventions and gotchas

- **Two `Config.tjs` files.** `data/main/Config.tjs` is the one in effect (it shadows `template/system/Config.tjs`). Recent commits keep both in sync for settings like `scWidth`/`scHeight` (currently 1920x1080); do the same. Setting lines use the `;name = value;` form, and the `//[start-...-additionals]` / `//[end-...]` markers must stay — `UpdateConfig.tjs` parses both when migrating configs. The `KAGWindow_config` etc. functions run `incontextof` the target object, so settings like `scWidth` become **members of `kag`**, not globals.
- **Plugin linking.** Plugins are linked by explicit relative path with a `.dll` name on every platform — `Plugins.link("plugin/foo.dll")` — wrapped in `try {} catch {}` and, where possible, guarded by a `typeof` check on a symbol the plugin provides (avoids double-loading on case-sensitive Linux, and tolerates plugins the SDL3 build provides natively or lacks). Follow this pattern; bare `Plugins.link("foo.dll")` was deliberately removed in `0710553` (the x64 Windows engine's own plugin folder is `plugin64/`). On non-Windows engines (`System.platformTag` present and not `"windows"`), the top of `Initialize.tjs` wraps `Plugins.link` to drop the `plugin/` prefix, because the SDL engine turns `plugin/Foo.dll` into `libplugin/Foo.so`; its own search already finds `plugin/libFoo.so`.
- **Linux compatibility.** Storage names in scripts must match file case exactly, and use `/` separators. `template/update_auto_copy_vars.bat` is a legacy Windows/perl helper; ignore it.
- **SDL3 port patches.** The end of `Initialize.tjs` forces the window inner size from `kag.scWidth/scHeight` unless full-screen, and `data/main/Config.tjs` shadows `getInitialFullScreenState` to always start full-screen. Be careful reordering anything around window creation and `kag.process("first.ks")`. `MainWindow.tjs` only takes its windowEx path (extended events, menu-bar hiding, registry cursors) when both `registerExEvent` and `exSystemMenu` exist. Newer engines build `registerExEvent` in on every platform, while `exSystemMenu` only comes from the windowEx plugin.
- **File encoding.** Most scripts are UTF-8 **with BOM**, but not all (e.g. `template/system/Config.tjs` has none); line endings and a doubled-blank-line artifact (left over from a CRLF conversion) vary by file. Preserve whatever the file already uses and keep diffs minimal — do not normalize whitespace, strip BOMs, or collapse the blank lines as a drive-by. `◆`/`●` markers and some Japanese comments are intentional.
- UI coordinates in `.ks` files (`title.ks`, `config.ks`, …) and the images in `data/image/` are authored for a specific resolution; a resolution change means touching both. `title.ks`/`title.png`, `config.ks` (with its `config_*`, `slidebar*` and `dialog_configini_base` images) and the extras screens `cgmode.ks`/`replay.ks`/`musicmode.ks` (`*mode_base`, `extra_*`, `cgmode_page*`, `cgmode_thum_*`, `musicmode_*`, `track*`) and `save.ks`/`load.ks` (`save_base`/`load_base` (semi-transparent so the scene shows through), `sl_win_base`, `*_win_over`, `page1-9`, `newdata`, `dialog_overwrite_base`/`dialog_load_base`; save thumbnails are 234 wide via `thumbnailWidth` in `data/main/Config.tjs`, and `fileDataButton` in `Override.tjs` lays out the slot) are at 1920x1080, as is the choice menu that opens on START (`[selopt]` in `first.ks` sets its area and `size=36`; bars are `select_normal`/`select_over`, and `SelectLayer` spaces the choices evenly within the area). The demo scenes are 1920x1080 too:
  - Art: `bg01_01` and `event1` were upscaled from the 800x600 originals and trimmed to 16:9 (`bg01_01` with a light median filter first). `black`/`white` are 1920x1080. Character sprites (`fgimage/ch_*`), `star`, the `msg_*` system buttons, the history-log controls and the `LineBreak`/`PageBreak` glyphs (cells 43px, see their `.asd`) are 1.8x. `test.webm` is 1.8x (2880x1080, side-by-side alpha).
  - Message window: `[initscene]` in `macro.ks` sets it to 1800x330, with the `msg_*` buttons right-aligned along its top. The sample `Config.tjs` text is 39 (line spacing 5, ruby 15/-3).
  - World (`envinit.tjs`): `yoffset` and vertical motion are x1.8. Horizontal positions and moves are x2.4, so `posleft`/`outleft` etc. sit at the same fractions of the wider screen.
  - Hardcoded scenario offsets (`layer.ks` character/rotation origin, `char.ks` walk-off, `envlayer.ks` star paths) were scaled the same way.
  - History log (`MyHistoryLayer.tjs`): full-screen `log_base`, controls placed for 1920 wide, text 36/42, wide right margin so lines stop before the controls.
  Still at 800x600: `dialog_title_base`, and `effect.ks` is untested (its fire effect needs the `gfxEffect` plugin, which isn't built). The extras thumbnails are 16:9, sized for 1920x1080 CGs, so today's 800x600 CGs look stretched in them and show at native size in the CG viewer until they are converted. `setCGImage` in `Override.tjs` fits any source size into the frame. Everything is being moved to 1920x1080, so shared assets get converted even if that breaks things still at 800x600.
- **Alpha movies in layers** (`[image movie=... alpha=1|2]`) go through `GFX_Movie.tjs`, which copies each frame with `assignImages`. That doesn't carry the layer type, so `start()` sets the target layers to `ltAlpha` before the first frame arrives (the `[image]` tag shows the layer immediately, and an opaque empty layer flashed white), and `onFrameUpdate` keeps alpha movies at `ltAlpha`. Otherwise the clear parts render solid white, across the whole screen for KAGEX's affine layers.
- **English text in scenarios.** In normal mode (`[linemode]` with no mode, `ignoreCR` on), a new line in the `.ks` adds nothing, so text split by tags (`[wact]`, `[emb]`, …) runs together. End such segments with punctuation and a trailing space (trailing spaces are kept). Plain text lines get word wrap from this fork's `needsToBeWrapped()` in `MainWindow.tjs`, which breaks before a word that won't fit. The space at the break is dropped through `wrapDropSpace`/`wrapDropSpaceHist`, which the `ch` handler checks; assigning `text = ""` inside that function had no effect. Lines it skips (any line containing `[r]`, or starting with a tag or tab) fall back to KAG's character wrap, which can split words. There, `MessageLayer.processCh` and the history layers drop a space that would start a wrapped line. Break long English lines yourself with `[r]` at a sentence boundary when they contain tags. `[initscene]` uses `[linemode mode=page]`, where every scenario line stands alone.
- **【name】 tags must use the character's key** from `envinit.tjs` (the same name as its tag, e.g. `【ai】` for `[ai ...]`). Keys are case-sensitive. Voices set with `[ai voice=N]` are looked up by that key, and so are faces and the character link. The translation had written `【Ai】`, which silently dropped the voice. The displayed name comes from the character's `nameAlias` ("Ai"), or from `【ai/Display】` for one line.
- **Never test a string as a boolean** (`if (s)`, `s ? a : b`). The current engine converts it to a number, so `"event1"` is false, and an empty string segfaults it (`tTJSVariantString::ToInteger`). Compare instead: `if (s != "")`. This crashed the Replay screen whenever an unlocked entry had no thumbnail.
- **Font faces on the SDL engine.** A face name the engine has not registered (e.g. `MS Gothic` on Linux, and on some machines plain `Noto Sans CJK JP` when only the Light weight is registered) is drawn with its `elements_basic` icon font, so text shows as `←←←`. The engine's own default face (an empty face) has the same problem here. So `userFace` and the history `fontName` in both `Config.tjs` files, plus the explicit faces in `about.ks` and `Override.tjs`, are face lists with the Windows font first: `"MS Gothic,Noto Sans CJK JP,Noto Sans CJK JP DemiLight,Noto Sans CJK JP Light,Roboto"` (the template keeps a Mincho-first variant). Unknown names in a list are skipped. Plain `Noto Sans CJK JP` fails on Arch because the Light file also claims the Regular style, while the weight-suffixed names resolve. Roboto ships with the engine, so it is always available for Latin text. `kag.chDefaultFace` is saved into the system variables (`*sc.ksd`, `scflags`) and wins over `Config.tjs`. When a saved value is a single old-style name (e.g. `MS Gothic`), the restore code in `MainWindow.tjs` keeps it first and appends the configured list. Without `-datapath` the engine keeps that data in `~/.local/share/wamsoft/krkrz/`, not `savedata/`. Use the face lists for any new text too.
- **krkr_richtext.** With `useRichText` (MessageLayer_config, on in both `Config.tjs` files) and the plugin loaded, `drawTextToLayer` in `MessageLayer.tjs` draws message text, ruby and the name box through `RichTextFontApp`: vector edges/shadows built from the layer's edge/shadow settings, fake bold, and in `processCh` kerned advances (the exact width of the line's run, rounded per character). Vertical text and bitmap fonts keep the normal path, as does anything when the plugin or the fonts are missing; the history log and the `[select]` choices are still drawn by the engine. `SelectLayer` borrows `MessageLayer.drawTextToLayer` `incontextof` a style dictionary, so that function may only touch members the dictionary has (a call to a MessageLayer method there broke every `[select]`). The baseline comes from the engine's `getGlyphDrawRect("H")`, so lines sit where `drawText` put them. `drawTextEx` only calls `update()` on the glyphs' ink box, which leaves shadows and edges off the screen until something else repaints there (text looked clipped while typing, then changed when the line was committed), so `RichTextFontApp.drawText` updates the whole padded cell itself. **Never pass `RichText.registerFont` (or `Font.getFontInfo`/`Font.queryFonts`) a face name the engine can't resolve:** the engine then opens every system font to search their names, and its pooled file allocator deadlocks (it runs the storage-cache pressure callback while holding its own mutex, at 75% of `-filepoolsize`, default 256 MB). A hung engine ignores SIGTERM; use `kill -9`. `RichTextFontApp.getFonts` only registers names that `Font.getVarAxes` resolves (it uses the same lookup as `drawText`, without the search) and that the engine actually draws; plain `Noto Sans CJK JP` passes the first test on Arch but draws nothing, so the chain here is DemiLight → Light → Roboto.
- **Engine BMP bug.** The current engine's BMP writer puts `bfOffBits = 56` in the header but writes the pixels at byte 54, and its reader trusts the header. So anything saved with `saveLayerImage(..., "bmp")` comes back color-shifted. This is a krkrz bug. To avoid it, bookmarks (`MainWindow.tjs`) now save their thumbnail as PNG: the save files are `dataN.png`, the save data starts at `calcThumbnailSize().size` (sized for an uncompressed RGBA PNG), and the thumbnail is forced opaque because PNG keeps the snapshot's meaningless alpha. `thumbnailDepth` is unused, and old `.bmp` saves are no longer picked up. The engine picks image decoders by file extension, so PNG data in a `.bmp`-named file won't load.
- Never commit `krkrz.exe`, DLLs/`.so`, `plugin/`, or `savedata/` (all in `.gitignore`).
