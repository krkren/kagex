# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this repository is

`kagex` (origin: https://github.com/krkren/kagex) is an English-translated, SDL3/Linux-ported fork of **KAGEX** — Wamsoft's extension of the Kirikiri **KAG3** visual-novel framework (affine layers, layer level ordering, automatic actions, and the "World" environment system). It is pure script and asset content: TJS2 (`.tjs`), KAG scenario (`.ks`), CSV, and images/audio. There is **no build step and no linter**; `tools/smoketest.py` is the test (see Running).

The engine that runs it is not part of this repo. `krkrz.exe`, `SDL3.dll`, `plugin/`, and `savedata/` are all gitignored local artifacts, built from the sibling `../krkrz_dev` umbrella repo (the SDL3 variant of 吉里吉里Z; see `../krkrz_dev/CLAUDE.md`). `extrans` used to come from https://github.com/krkren/SamplePlugin; `../krkrz_dev` now builds it too. `setup.bat` and `setup.sh` were removed in commit `f6d1767` — `git show f6d1767^:setup.bat` is the reference for which build outputs get copied where (`krkrz64.exe` → `krkrz.exe`, `core/plugins/*/*.dll` + `krmovie.dll` → `plugin/`). On Linux the outputs are `build/x64-linux/core/Release/krkrz` + `_deps/sdl3-build/Release/libSDL3.so*` → repo root and `core/plugins/*/Release/lib*.so` → `plugin/`. With Arch's CMake 4 / newer GCC, configure needs `-DCMAKE_POLICY_VERSION_MINIMUM=3.5` and the full build fails inside the `krkrthreepp` plugin, so build only the targets kagex uses: `cmake --build build/x64-linux --config Release --target krkrz KAGParserEx csvParser layerExBTOA layerExImage layerExRaster scriptsEx shrinkCopy extrans krkr_richtext saveStruct getSample psdfile layerExSave AlphaMovie` (the release Linux packages ship these and more: every portable plugin krkrz_dev builds). Never modify `../krkrz_dev` or its submodules: work around engine bugs in the scripts, and list the ones that can't be worked around in `UPSTREAM.md` (what they cost and what would fix them upstream, most important first). The 0.0.4 to 0.8.0 packages run engine 2.6.5 (`System.versionString` is `2.6.5.0`, krkrz_dev master `21d20e9` of 2026-10-20). A release package also needs `krkrz.cf` (repo root) next to the engine. On Linux `libkrkr_richtext.so` links but won't load (`undefined symbol: png_get_valid`): its link line repeats `libfreetype.a` after harfbuzz, past the png/zlib/bzip2/brotli archives. Relink it with those archives appended: take the command from `ninja -f build-Release.ninja -t commands core/plugins/krkr_richtext/Release/libkrkr_richtext.so | tail -1` (in `build/x64-linux`) and add `vcpkg_installed/x64-linux/lib/{libpng16,libz,libbz2,libbrotlidec,libbrotlicommon}.a -lm` at the end.

## Running

```bash
./krkrz.exe                   # Windows, from the repo root; project dir defaults to data/
./krkrz -datapath=savedata/   # Linux; otherwise saves go to ~/.local/share/krkren/kagex/ (krkrz.cf)
python3 tools/smoketest.py    # headless smoke test of the sample and the template (needs the engine here)
```

- `krkrz.cf` next to the engine is read as extra command-line options (one `name=value` per line, no `-`, `;` comments; `<exe name>.cf`, so `krkrz.cf` for both `krkrz` and `krkrz.exe`). It sets `orgname=krkren`/`appname=kagex`, which name the Linux/macOS save folder (`~/.local/share/<orgname>/<appname>/`); the engine's defaults are `wamsoft`/`krkrz`, shared by every game on the stock engine. `-datapath` still wins. With a `savedata*` folder next to the exe and no `-datapath`, the engine logs a "Legacy save data found" warning.
- **`tools/smoketest.py`** runs the sample (`data/`) and then `template/` as a project of its own (the template is a runnable game: `template/startup.tjs`, `system/`, `scenario/first.ks`), each with a temporary `-datapath`, and drives them through the REPL file channel (below). It plays the seven demos with a clicking `Timer`, checks the animated character's blinking and lip-sync, that the demo menu's choices measure as text (not the icon font) and that the first CG and Replay tiles are opaque, saves and loads, opens and closes the system and Extras screens, the Yes/No prompt, About and the controller buttons, then fails on an uncaught script error in the log (`Script exception raised` / `スクリプトで例外が発生しました` / `! trace :`) or a native dialog (REPL `modal`). Don't match `An exception occured at ...`: the engine logs that VM dump for **every** thrown exception, including the ones the scripts catch on purpose (plugins the SDL engine lacks, the time-of-day background fallback in `KAGEnvStage.drawLayer`). `.github/workflows/smoke.yml` runs it with `krkrz`, `libSDL3.so.0` and `plugin/` from the newest release that has `kagex_sdl3_linux_release.zip` (all releases are pre-releases, so there is no "latest"). The newest release's Linux package is a quick way to get an engine here: `gh api -H "Accept: application/octet-stream" repos/krkren/kagex/releases/assets/<id>` (from `gh api repos/krkren/kagex/releases`), then copy those three next to `data/`.

- The engine treats the first positional argument as the project directory, and looks for `startup.tjs` in it. With no argument it uses `data/` next to the exe. Engine options are `-name=value`; a bare word gets taken as the project path (a past run with a stray `usepseudo` token failed with "Cannot find storage startup.tjs").
- The feedback loop is running the game (or the smoke test) and reading the log: **`savedata/krkr.console.log`**, or the engine's stdout, which has the same lines as they happen. The file is **UTF-16LE** and appended across runs — read it with `iconv -f UTF-16LE -t UTF-8 savedata/krkr.console.log | tail -n 200`, and look for `Script exception raised` (`スクリプトで例外が発生しました` on a Japanese system) and the `! trace :` after it; an `An exception occured at <file>(<line>)` dump on its own may be an exception the scripts caught. Filenames in traces are lowercased.
- The game forces full-screen. To test without taking over the screen, run it headless: `SDL_VIDEO_DRIVER=offscreen SDL_AUDIO_DRIVER=dummy ./krkrz -datapath=savedata/ -replfile=<dir>`, and drive it through the engine's REPL file channel (`../krkrz_dev/src/core/doc/REPL.md`: write TJS to `<dir>/cmd.tmp`, rename to `cmd`, read and delete `<dir>/resp`). REPL commands are evaluated as one expression: wrap statements in `(function() { ...; return x; })()`, or only the first one runs; TJS has no closures (an inner function can't see the outer locals) and no `finally`. Injected keys don't change `System.getKeyState`, and KAG checks Return/Space with `getKeyState` (`checkProceedingKey`), so a `keyDown`+`keyUp` in one command does nothing: press with `keyDown`, wait a frame, then `keyUp` (the smoke test's `key()`), or click with `Agent.click`. Holding a key (Ctrl, R2) can't be simulated. Under the offscreen driver `Agent.captureScreen` returns black with the default GL draw device, so render `kag.primaryLayer` into a new Layer with `piledCopy` and `saveLayerImage(path, "bmp")` (that BMP's header says the pixels start at byte 56, but they start at 54; BGRA, bottom-up). `piledCopy` reads the layer buffers, so it hides anything that never reached the screen (a missing `update()`). To see the real frame, add `-drawdevice=sdl`, then `kag.setZoom(1, 1), kag.setInnerSize(1920, 1080)` and `Agent.captureScreen(path)` (a PNG written on the next frame). `Agent.click` takes window coordinates: the offscreen window is 1024x768 with the 1920x1080 game letterboxed into it.
- `savedata/*.ksd` persists system/scenario variables (`sf.*`, `scflags`) between runs, including things like the saved full-screen preference. When a config change appears to have no effect, stale savedata is a likely cause.

## Layout and load order

- `template/` — the reusable KAGEX framework. `template/system/*.tjs` is the whole runtime (~60 files); the other `template/*` folders are empty placeholders for a new game.
- `data/` — the sample game. In this repository it has no `system/` of its own: `data/startup.tjs` runs `data/system/Initialize.tjs` when there is one, and otherwise adds `../template/system/` to the auto path and executes `../template/system/Initialize.tjs`. The platform builds copy `template/system` into the package as `data/system` (a browser or phone build has nothing outside `data/`); the zip packages keep `template/` next to `data/`. Shipping a real game means copying `template/system` + `template/startup.tjs` into `data/`.
- `doc/` — the KAGEX reference, in English: `kagex.txt` (new/changed tags vs. stock KAG3), `action.txt` (action system), `world.txt` / `world_inst.txt` / `world_use.txt` (World extension: `envinit.tjs` schema, character/stage/time tags). Read these before changing tag behavior; stock KAG3 knowledge alone is not enough.

`template/system/Initialize.tjs` drives everything, in this order:

1. Registers auto paths: `data/` then a fixed list of subfolders (`video, others, rule, sound, bgm, fgimage, bgimage, scenario, image, system, voice, face, init, sysscn, main, evimage, thum, uipsd, effect`), each also accepted as a `<name>.xp3` archive. **Later-registered paths win**, so anything under `data/*` shadows the same filename in `template/system/`. Storage lookup is by bare filename across all auto paths — filenames must be globally unique unless shadowing is intended.
2. Runs `Storages.tjs` (`data/main/Storages.tjs`) — add nested asset folders there via `setupSubFolders([...])`; a new top-level folder outside the fixed list is not searched.
3. Links plugins (see below), then loads `AppConfig.tjs` (optional) and `Config.tjs`.
4. Loads the system classes, then `Override.tjs`, creates the `kag` window, attaches `KAGWorldPlugin` (`world.tjs` + `KAGEnv*.tjs`, configured by `envinit.tjs`), runs `AfterInit.tjs`, and finally `kag.process("first.ks")`.

In the sample, the game-side hooks all live in `data/main/`: `Config.tjs`, `Override.tjs` (class/function overrides, loads `MyHistoryLayer.tjs`), `AfterInit.tjs` (key bindings etc.), `envinit.tjs` (World definitions: times, stages, characters, poses), `first.ks` → `logo.ks` → `title.ks`, the system-menu scenarios (`config.ks`, `save.ks`, `load.ks`, `cgmode.ks`, `musicmode.ks`, `replay.ks`) and their CSV lists. Story/demo scripts are in `data/scenario/` (`s0001.ks` is the demo menu). Prefer these hooks over editing `template/system/` when a change is game-specific.

## Platform builds

The Windows and Linux zips come from the release workflow, which builds krkrz_dev itself. The other packages come from Wamsoft's platform kits, which build krkrz_dev without changing it, from configs at the repository root: `linux-config.json` (krkrz_linux: a Linux folder built in Valve's Steam Linux Runtime 3.0 "sniper" container), `web-config.json` (krkrz_web), `app-config.json` (krkrz_android) and `ios-config.json` (krkrz_ios), with this repository as `PROJECT_DIR` and `KRKRZ_BASE` the folder that holds `krkrz_dev` and the kit. macOS uses krkrz_dev's own `arm64-osx` preset. `.github/workflows/platforms.yml` builds and smoke-tests all five, with the engine (`21d20e9`, as for the zips) and the kits pinned in its `env`. It runs on pushes to `platforms/**` branches (`[platforms: linux web]` in the commit message builds only those, `[platforms: none]` nothing) and from the release workflow (`workflow_call` with the release commit as `ref`). Each job uploads its build before the smoke test (`kagex-linux`, `kagex-web`, `kagex-android` (release) and `kagex-android-debug`, `kagex-ios-simulator`, `kagex-macos`) and force-pushes its logs, screenshots, an `<log>.errors` digest of each log and, on macOS, the engine's crash reports (`.ips`; a native crash's output is lost from the buffered log) to branch `ci/platform-results-<job>`; job logs themselves can't be read from this environment. `.github/workflows/pages.yml` puts a release's `kagex_sdl3_web.zip` on GitHub Pages (the release workflow starts it). The packages hold `data/` with `template/system` copied in as `data/system`, which `data/startup.tjs` prefers.

- **Plugin order.** List a krkrz_dev plugin first in a config's `plugins`: tp_stub's `krkrz.cmake` caches `NCBIND_DIR` relative to the first plugin folder that includes it, and with the kit's `virtualpad` first that was the kit's folder, which has no ncbind.
- **Linux.** `cmake.options` sets `CMAKE_CXX_STANDARD_LIBRARIES` to freetype's archives (png, zlib, bzip2, brotli) so they end every C++ link: the same krkr_richtext fix as the relink above. The smoke test runs the package on the runner itself, with Mesa's EGL installed.
- **Web.** krkr_richtext doesn't compile for wasm32 at engine 2.6.5 (its `main.cpp` casts a `tTJSVariant` to `tjs_intptr_t`, which tp_stub only converts to on Apple or where `intptr_t` is `int64_t`), so the web build draws text with `drawText`. `.github/platforms/web-plugins.py` edits krkrz_web's built-in plugin list in the CI checkout, dropping the plugins from Wamsoft's private repositories and adding krkreffekseer, with `krkreffekseer-kit.cmake` at the end (the same EGL and UTF-helper workarounds as Android, below). Effekseer's GLES 3 renderer maps its vertex buffers with `GL_MAP_UNSYNCHRONIZED_BIT`, which WebGL can't do: Emscripten's `glMapBufferRange` returned 0, Effekseer `memcpy`'d into it, so nothing drew and the engine's low memory got overwritten (later steps of the smoke test hung). `krkreffekseer-webgl.cpp` swaps the bit for `GL_MAP_INVALIDATE_RANGE_BIT` through `glad_glMapBufferRange`, renamed for `efk_renderer_gl` only. The site downloads files on demand (`web://`), and the save folder (`user://`) is SDL storage rather than local files (see the bookmark notes under the BMP bug). `lowercase` puts the files in lower case for case-sensitive hosts such as GitHub Pages, and `coi-serviceworker.js` supplies the COOP/COEP headers there. `.github/platforms/web-static-host.py` readies the site for a static host, in the staging step and again in `pages.yml` (0.2.0's zip lacks both changes): the engine reads the `web://` file list from `gamedata/krkrz_files.json`, which the kit writes to `gamedata.krkrz_files.json` and only its `serve.py` answers with, so it copies the file there (without it Pages stopped at `Config.tjs not found`); and coi-serviceworker reloads the page on `updatefound`, before its worker is active, so on Pages the reloaded page was sometimes left uncontrolled and not `crossOriginIsolated` (`SharedArrayBuffer transfer requires self.crossOriginIsolated`, nothing starts until the visitor reloads), so it sets `window.coi.doReload` to wait for `navigator.serviceWorker.ready`. It also adds the home-screen setup: iPhone browsers have no element full screen (the engine's request just fails there), so `apple-mobile-web-app-capable` makes the page open without Safari's bars from the Home Screen, and `manifest.webmanifest` (full screen, landscape) does the same for Android's Add to Home screen; the icons are `platform/web` (`make_ui.py icons`), the names `linux-config.json`'s `name` and `ios-config.json`'s `displayName`, which also replace the kit's `<title>krkrz</title>`. Its head tags sit between `<!--kagex-head-->` and `<!--/kagex-head-->` (older sites' tags without the markers are removed), so it can run again: `pages.yml` reruns it on the release zip with `--url` (from `actions/configure-pages`) for the link previews (Open Graph and Twitter card: name, description, `platform/web/preview.jpg` from `make_ui.py preview`; Discord and the like need absolute image URLs). **Updates** (since 0.3.1): the engine caches every `web://` file in OPFS under a key made from its relative URL alone (`krkrzOpfsKey`: SHA-256 of `gamedata/...`), never checks it again, and shares that cache with every krkrz game on the origin (all of itch.io's HTML5 games share one), so an updated site kept serving players the old files. `web-static-host.py` gives the site a build id (a hash of its files) in `kagex-build.json` and `<meta name=kagex-build>`, with `?v=<id>` on `kagex-web.js`, `webconfig.js` and `krkrz.js` (krkrz.js's pthread workers load the same URL). `platform/web/kagex-web.js` (loaded before `webconfig.js`) adds a `Module.preRun` run dependency that reads `kagex-build.json` with `cache: no-store`, reloads a stale page once (`sessionStorage` guard), and empties the OPFS cache entries (`/^[0-9a-f]{40}_/`) when the build differs from the `.kagex-build` marker there; it also wraps `window.fetch` so same-origin fetches without `?v=` revalidate (`cache: no-cache`); the engine fetches on the main thread (Asyncify). The same file shows the **Add to Home Screen** bar on phones and tablets outside the installed app: `beforeinstallprompt`'s prompt behind an Add button where the browser fires it (Chrome, Edge, Samsung Internet, Opera), the Share steps on every iOS browser, the menu steps on other Android browsers (after 2.5 s without the event); closing it hides it for 30 days (`localStorage`), and it goes 10 s after the game starts; English or Japanese by `KRKRZ_LANG`. On Android and iPad, full screen from Config works, but the engine makes the request from its own loop, so the browser defers it to the next tap. The web smoke test serves the site with `python3 -m http.server`, as Pages does, rather than `serve.py`, and `pages.yml` runs it on the live site after each deploy (`ci/platform-results-pages`). Headless Chromium lets the page go full screen without a click, and the full-screen canvas covers the loading screen, so a first visit screenshots black there; a real browser refuses that and shows "Click / tap to start" (add an init script that rejects `requestFullscreen` to see it). The build has no `Agent` class: the smoke test posts keys with `kag.postInputEvent` and runs every command from a `Timer`, because a scenario load started inside a `krkrz_repl_eval` call crashed the page.
- **Android.** `platform/android-res` (the `resOverride`) names the app in `values`, `values-ja`, `values-zh-rCN` and `values-zh-rTW`: the kit names it "krkrz" in all four. The kit asks Gradle for the SDK's CMake 3.22.1, but with krkr_richtext the engine downloads ICU with an option CMake 3.24 added (`DOWNLOAD_EXTRACT_TIMESTAMP`): CI installs the newest SDK CMake 3.x and changes `version` in the kit's `app/build.gradle`. There's no `a11y` plugin: it turns on `KRKRZ_USE_A11Y`, and at engine 2.6.5 the engine's AccessKit setup can't find its Android library (`find_library` in the NDK cross-compile), so `libkrkrz.so` didn't link. The x86_64 libvpx (for the emulator) needs `nasm`. krkreffekseer (Effekseer effects) is built in, with three CI-only workarounds that leave krkrz_dev as it is: `kit-vcpkg.py` adds minizip-ng to the kit's fixed vcpkg manifest (the kit doesn't merge plugin manifests); `krkreffekseer-kit.cmake`, appended to the kit's `CMakeLists.txt`, defines `<EGL/egl.h>`'s include guard for `efk_renderer_gl` (its `eglGetProcAddress` clashed with the plugin's GLES hook macro) and renames the plugin's own `TVPUtf8ToUtf16`/`TVPUtf16ToUtf8` (duplicates of the engine's once linked in); and `krkreffekseer-odr.cpp` defines Effekseer's in-class `static const` members, which the unoptimized debug APK odr-uses. The release workflow's Linux Debug build needs it too (a shared object links with them undefined, so 0.3.1's debug `libkrkreffekseer.so` didn't load): `release-build/krkreffekseer-odr.cmake` on `ci/windows-release` adds it to `efk_core` through `CMAKE_PROJECT_INCLUDE`. Since 0.4.0 the release stops when `libkrkreffekseer.so` doesn't load or a zip lacks krkreffekseer, and the zips' smoke test (`run-kagex.ps1 -Plan smoke`) plays the Effects demo and fails unless the effects drew. The smoke test drives the debug build through its REPL socket (`<applicationId>.repl`, forwarded with adb); the package is the kit's `release-debug` build (optimized, signed with the debug key).
- **iOS.** A Simulator build (a device build needs an Apple Developer team), Debug, without krkr_richtext (with it, CMake's Xcode generator stops with "duplicate object ids not allowed"; a bisect pinned it to that plugin) or krkreffekseer (the same error), so effects show nothing there, and with `a11y` off. krkrz_ios builds only the browser REPL (`-replweb`), which the smoke test drives through `POST /pad/exec`. Screenshots of the Simulator come out black on the CI runners, even through `Agent.captureScreen`, so there the smoke test checks the game's state only.
- **macOS.** The macOS runners' CMake 4 needs `CMAKE_POLICY_VERSION_MINIMUM=3.5` (set for every job). Effekseer's GLES 3 renderer on Apple returns a null `glMapBufferRange` unless `GL_ARB_map_buffer_range` is defined, and copied into it, so the first effect drawn crashed the engine: the configure step passes `.github/platforms/krkreffekseer-apple.cmake` as `CMAKE_PROJECT_INCLUDE`, which defers (`cmake_language(DEFER)`) defining that macro for `efk_renderer_gl` until the targets exist. The job renames the app to `KAGEX.app`, copies the game into `Contents/Resources/data`, sets the name, bundle id, version and icon, and signs it ad hoc again: adding the files broke the build's own signature, which macOS reports as a damaged app. Its smoke test runs with SDL's cocoa driver; the offscreen one has no OpenGL ES there.
- **Smoke test on the platforms.** `--target android|ios-sim|web` runs the sample's steps; clicks go through `kag.onPrimaryClick` because `Agent.click` takes window coordinates, which differ on every platform. A save failure leaves the save-failed message open, which then swallows Return, the arrows and the pad buttons in later steps.

## The release tool (tools/release)

`kagex-release` packages a game for every platform (`tools/release/README.md` is the user-facing description). It is an appserve app like krkrz_tools' tools (a local HTTP server and a browser app window; `web/` is the screen, embedded in the exe) and a CLI (`--cli init|check|plan|build`). It links krkrz_tools' libraries (`krt_app`, `krt_xp3`, `krt_audio`, `krt_image`, `krt_loop`, `krt_release` on Windows) through `add_subdirectory(KRKRZ_TOOLS_DIR ... EXCLUDE_FROM_ALL)`, by default `../krkrz_dev/src/tools/krkrz_tools`; CI clones the krkrz_tools commit `ENGINE_SHA` pins. Its vcpkg manifest is `tools/release/vcpkg.json` (krkrz_tools' dependencies plus `drlibs` for dr_flac). The libraries' own error messages are in Japanese.

- **Source.** `main.cpp` (CLI, the window's API: `/api/release/state|open|check|host|save|build|reveal`, builds as a `JobRunner` job), `Settings` (release.json: defaults from `first.ks`'s `sf.software_*` and `krkrz.cf`, `withDefaults` merging, `validate`), `Project` (finds the folder with `data/startup.tjs`, from the path given, the current folder or the exe's parent), `Host` (per-platform requirements: a Mac, Xcode via `xcrun --find actool`, signing identities via `security find-identity`, Java 17 from `JAVA_HOME`/PATH, the Android SDK), `Plan`, `Build`, `Media`, `Engine`, `Archive` (zip with ZIP64/Unix modes/symlinks, tar.gz with pax headers, SHA-256), `Icons` (area-averaged sizes, `.ico` with PNG entries, `.icns`), `Subprocess`. Not `Process.h`: on Windows that name shadowed the C runtime's `<process.h>` (`_beginthreadex` not found). Don't name a function `linux` (a GCC macro).
- **Engine packages.** `kagex_engine_<platform>[_debug].zip` (debug for Windows and Linux only), downloaded from the release tagged with the tool's version (`KAGEX_RELEASE_ENGINE_URL` overrides) into the cache (`%LOCALAPPDATA%`, `~/Library/Caches`, `$XDG_CACHE_HOME` or `~/.cache`, then `kagex-release`; `KAGEX_RELEASE_CACHE` overrides), or taken from `--engines`/`KAGEX_RELEASE_ENGINES`. Each has an `engine.json`. `scripts/engine-package.py` makes the desktop and web ones from the release packages (without the game; symlinks dereferenced; the macOS app without signature, `data/` or `.cf`; the web site without `gamedata/` and its lists); `scripts/android-engine.py` makes Android's from the kit checkout and the release APK; `scripts/ios-engine.py` makes iOS's from an unsigned device build and the Simulator app. `platforms.yml`'s Android and iOS jobs upload `kagex-engine-android`/`kagex-engine-ios`.
- **Build.** The game's files are staged in `<output>/.work/data` as hard links (copies where links fail), so nothing may write to a staged file: replace it (remove, then write). Media conversion runs there (`Media.cpp`: parallel, cached by content hash plus settings in `<cache>/media`; images are decoded to tell opaque from transparent; FLAC through dr_flac; `.sli` rescaled to 48 kHz for Opus; names written with an extension in `.ks/.tjs/.csv/.txt/.asd/.json/.func` scripts, printf patterns like `ai%s%06d.wav` included, keep their files unless rewriting is on; scripts are matched as UTF-8, UTF-16LE or Shift_JIS without matching inside a double-byte character), then `data.xp3` is packed once. The `.cf` next to the engine is the developer's `krkrz.cf` minus `orgname`/`appname`/`debugwin`, plus those. Binding appends the xp3 at a 16-byte boundary after the executable (the SDL engine looks after the image end, after `data.xp3` and before `data/`). On the Windows host `krt::release::run` sets the icon and version strings (it shrinks the exe: the PNG icons are smaller). The macOS app's `.cf` is `Contents/MacOS/krkrz.cf`, its data in `Contents/Resources`; `Info.plist` is XML there. Web: the page as `web-static-host.py` makes it (the same head block, with the game's title, `platforms.web.description`, `preview` (default `platform/web/preview.jpg`; the icon without one) and `url` for the previews, the manifest, `kagex-web.js` built into the tool from `platform/web` by `CMakeLists.txt` (`KagexWebJs.h`), the build id); `gamedata/` in lower case with `gamedata.krkrz_files.json` (also as `gamedata/krkrz_files.json`) and `krkrz_prefetch.json`; `krkrz.data` is the engine's preloaded `/data.xp3` and its size is written into `krkrz.js` (`files:[{filename:"/data.xp3",start:0,end:N}],remote_package_size:N`): emptied for the files mode, the game's xp3 in the xp3 mode (`KRKRZ_WEB_DATA_XP3`, no webbase). Android: the Gradle project in `.work/android` gets the game's `app-config.json` (assets: `engine-assets/` plus the data), a `res-override` (app name in `values`, `values-ja`, `values-zh-rCN`, `values-zh-rTW`; the icon as an `<inset>` of a bitmap for the adaptive icon's foreground and monochrome), `local.properties`, and `gradlew :app:{assemble,bundle}{Release,ReleaseDebugSigned}` with `PROJECT_DIR`, `JAVA_HOME`, and `RELEASE_STORE_*` from the window's password prompt or `KAGEX_ANDROID_*_PASSWORD`. iOS: `Info.plist` through `plutil` (binary in the bundle), the icon through `actool` and PlistBuddy's Merge, the profile's entitlements via `security cms -D` (an unsigned plist profile is taken as it is, for tests), nested code signed first.
- **File lists and patches.** After the media conversion every build writes `<output>/<exe>-<version>-files.json` (the staged files, `/`-separated, with SHA-256s; `fileList` in `Build.cpp`). With `output.patchFrom` (a list, relative to the project) it also writes `<output>/<exe>-<version>-patch/patch.zip` of the staged files that are new or changed (hard-linked into `.work/patch`, zipped with `zipFolder`), reported as an output with platform `patch`; then no platform has to be enabled (`validate`, `execute`), though compiling the scripts still takes the host's engine. `collectGameFiles` (`Plan.cpp`) puts back a `.clip`/`.psd` an exclusion matched when a script names it after `clip://`/`psd://` (`layeredFilesNamed`; UTF-16LE scripts converted, others read as bytes). `test/smoke.py`'s `patch_tests` builds a patch from an empty list, then from that list after changing the project, without engines (and so with `compileScripts` off).
- **Compiled scripts** (`Scripts.cpp`, `contents.compileScripts`, on by default). After the media conversion every staged `.tjs` is replaced by TJS2 bytecode (`TJS2100\0`), which the engine's `TVPExecuteStorage` tells by its header (`startup.tjs` too; checked on the Linux and web engines). The host's engine package (on macOS a copy of its app, signed ad hoc: unsigned it doesn't start) runs headless with `.work/` as `-datapath`, `-forcelog=clear`, the project's `readencoding` from `krkrz.cf`, and a generated `compile/startup.tjs` that reads `compile/list.txt` (`@set` lines, then `<id>\t<script>\t<probe>\t<marked>\t.`) and writes `compile/result.txt` (UTF-16LE); the engine's output goes to `<output>/compile-scripts.log`, and the `... at line N` after each `kagex-compile <id>` marker gives a compile error's line (the exception has none). Bytecode keeps the mode it was compiled in, and `evalStorage` of source is `return <text>;`, so a script that is one expression is compiled as one: the probe, `(` + the script with its trailing `;`s blanked (not cut off, so nothing the scan misread is left out) + `)`, compiles only then (a named function declaration isn't an expression; `envinit.tjs` ends with `];`, so it also compiles as statements, with a void result). Files are compiled in the order the game reads them (`startup.tjs`, `Initialize.tjs`, `Storages.tjs`, `AppConfig.tjs`, `Config.tjs`, the rest by name) after `@set (PACKED=1)` (and `DEBUG=1` with `engine.debug`), so their `@set` lines carry over as at run time. Engine bugs (`UPSTREAM.md`): debug information makes the engine dump core when it reports an exception, so there is none (traces say line 1); LP64 engines cut integer constants beyond 32 bits (`0xff000000` loads as -16777216). A canary (`0x123456789`) shows whether this engine does; then each script with such literals is compiled again with marker numbers in their place (from `0x4B580000`, unlike any literal in it or its cut value; `-M` stands for `-v`), and `fixWideConstants` moves each marked slot to the LONG table after checking the two compiles match everywhere else, so a scanner mistake (say, inside a string) shows as a difference and keeps the script source rather than changing it. Constants the compiler folds (`literal op literal`, a literal in `@"${...}"`, which becomes part of the string) can't be marked, so those scripts stay source there. `tjs::scan` follows tjsLex.cpp: block comments nest, `@` directives are skipped, a regex (after a non-operand) ends at the first unescaped `/`, `<%...%>` octets, Shift_JIS second bytes (`\` is one). The bytecode's indexes are int16 (`tooLarge`). Compiling is deterministic, so a patch holds only the scripts that changed. `test/smoke.py`'s `script_tests` builds a game whose scripts check the constants, expression scripts and UTF-16LE/Shift_JIS scripts as it runs, then a patch.
- **Test run.** The host's build runs with `-datapath` and `-replfile` in `.work/test` and `SDL_AUDIO_DRIVER=dummy` (plus `SDL_VIDEO_DRIVER=offscreen` on Linux without a display); the REPL is asked whether `kag` exists, then it runs 5 more seconds; script errors are read from `krkr.console.log` (UTF-16LE; outside Windows the engine names it `\krkr.console.log`, appending a backslash to the folder, so the engine's output is read there). A missing GLES context ("GLES context is unavailable", a VM) makes it inconclusive, not failed.
- **CI.** `.github/workflows/release-tool.yml` builds the tool on Windows, Linux (glibc 2.34+, libstdc++ linked in) and macOS (arm64, 12.0+) and runs `tools/release/test/smoke.py` (`--browser` on Linux: the screen in Chromium, light and dark; `--engines`: builds of every platform the runner can make, including the web in Chromium through smoketest.py's `WebEngine`, an APK and an app bundle, iOS for the Simulator (started there) and a device `.ipa` signed ad hoc). The engine packages come from the newest release that has `kagex_engine_linux.zip` (looked up as `smoke.yml` looks up its engine); a tool newer than its engines only notes it. The scripts that make them run in the release workflow (its `tool-check` job builds the sample with the new packages before publishing) and in `platforms.yml`'s Android and iOS jobs, not here. The Windows runner gets GLES from Edge's ANGLE in PATH. Results go to `ci/platform-results-release-tool-<os>[-<branch>]`; the Linux job also pushes its vcpkg libraries and clipparse's sqlite source to `ci/dev-libs-linux` (in this environment vcpkg's GitHub archive downloads and sqlite.org are refused, and artifact downloads go through blob storage that is refused too). To build the tool here: clone `wamsoft/krkrz_tools` at the commit `ENGINE_SHA` pins (with submodules), unpack that branch's `x64-linux.tar.gz`, and configure without vcpkg's toolchain: `cmake -S tools/release -B <dir> -G Ninja -DCMAKE_BUILD_TYPE=Release -DKRKRZ_TOOLS_DIR=<krkrz_tools> -DCMAKE_PREFIX_PATH=<libs>/vcpkg_installed/x64-linux -DFETCHCONTENT_SOURCE_DIR_SQLITE3_AMALG=<libs>/_deps/sqlite3_amalg-src -DFETCHCONTENT_FULLY_DISCONNECTED=ON -DCMAKE_POLICY_VERSION_MINIMUM=3.5`. For `--engines`, a folder `kagex_engine_linux/` with the repo root's `krkrz`, `libSDL3.so.0`, `plugin/` and an `engine.json` (`{"format": 1, "platform": "linux", "version": "<tool version>", "debug": false}`) will do.
- **Versions.** The tool downloads its engines from the release tagged with its own version, `project(kagex_release VERSION ...)` in `tools/release/CMakeLists.txt` (also `version` in `tools/release/vcpkg.json`), so a release raises both along with the other version numbers (`first.ks`, `app-config.json`'s `versionName`/`versionCode`, `ios-config.json`'s `version`/`build`, `linux-config.json`, `CHANGELOG.md`). A forgotten bump would make the new release's tool download the previous release's engines, so the release workflow (`.github/workflows/release.yml` on branch `ci/windows-release`, pushed to start a release) stops in `tool-check` unless `kagex-release --version` prints `kagex-release <RELEASE_TAG>` (since 0.3.1).

## Conventions and gotchas

- **Two `Config.tjs` files.** `data/main/Config.tjs` is the one in effect (it shadows `template/system/Config.tjs`). Recent commits keep both in sync for settings like `scWidth`/`scHeight` (currently 1920x1080); do the same. Setting lines use the `;name = value;` form, and the `//[start-...-additionals]` / `//[end-...]` markers must stay — `UpdateConfig.tjs` parses both when migrating configs. The `KAGWindow_config` etc. functions run `incontextof` the target object, so settings like `scWidth` become **members of `kag`**, not globals.
- **Plugin linking.** Plugins are linked by explicit relative path with a `.dll` name on every platform — `Plugins.link("plugin/foo.dll")` — wrapped in `try {} catch {}` and, where possible, guarded by a `typeof` check on a symbol the plugin provides (avoids double-loading on case-sensitive Linux, and tolerates plugins the SDL3 build provides natively or lacks). `Initialize.tjs` does this through `KAGLinkPlugin(name)`, which logs a failure to the console instead of swallowing it. Follow this pattern; bare `Plugins.link("foo.dll")` was deliberately removed in `0710553` (the x64 Windows engine's own plugin folder is `plugin64/`). On non-Windows engines (`System.platformTag` present and not `"windows"`), the top of `Initialize.tjs` wraps `Plugins.link` to drop the `plugin/` prefix, because the SDL engine turns `plugin/Foo.dll` into `libplugin/Foo.so`; its own search already finds `plugin/libFoo.so`.
- **Linux compatibility.** Storage names in scripts must match file case exactly, and use `/` separators. Plugin names too: the packages ship `libsaveStruct.so`, so `Plugins.link("plugin/savestruct.dll")` only worked on Windows. That includes data files such as `musiclist.csv` (it listed `BGM01` for `bgm01.ogg`, which played on Windows only).
- **SDL3 port patches.** The end of `Initialize.tjs` re-applies the window size with `kag.setZoom(kag.zoomNumer, kag.zoomDenom)` unless full-screen, so a windowed start keeps the zoom the constructor picked for a display smaller than 1920x1080 (it used to force `setInnerSize(scWidth, scHeight)`). Both `Config.tjs` files shadow `getInitialFullScreenState`: full-screen on the first launch, then the saved `scflags.fullScreen`. The SDL engine switches full screen asynchronously, so `kag.fullScreen` (which reads the window back) still reports the old mode right after a switch: `changeFullScreenOrWindow` records the requested mode in `kag.fullScreened`, and anything deciding by the current mode (the Config screen's buttons, the size at the end of `Initialize.tjs`, the saved preference) should read `fullScreened`. Be careful reordering anything around window creation and `kag.process("first.ks")`. The SDL engine's `Window` has no `menu`: `KAGWindow_createMenus` (`Menus.tjs`, and the sample's copy in `Override.tjs`) builds the menu items on the stand-in `Menu` class `Menus.tjs` defines, and the framework's version marks that with `kag.menuBarStandIn`; without it a game made from the template stopped at start-up (`Member "menu" does not exist`). The Debug menu is unreachable there, so KAG's debug mode (`debugWindowEnabled`: on unless `-debugwin=no`, which a release should set) gets Shift+F12 (debug window) and Shift+F11 (debug level) in `processKeys`. The sample's `KAGWindow_createMenus` copy sets `menuBarStandIn` too. The SDL engine has no `Pad` class either: `initLogPad` returns early and `UpdateConfig.tjs` writes `Config.tjs.merged` instead of showing a Pad. `MainWindow.tjs` only takes its windowEx path (extended events, menu-bar hiding, registry cursors) when both `registerExEvent` and `exSystemMenu` exist. Newer engines build `registerExEvent` in on every platform, while `exSystemMenu` only comes from the windowEx plugin. Likewise `Window.minimize` is built in, but the `MenuItem.bi*` icons are windowEx's, so `SetWindowControlMenu` (`Menus.tjs`) returns early without them; it used to throw `Member "biMinimize" does not exist` on every switch between full screen and a window, which skipped the rest of the `fullScreen` setter (the `afterChangeScreenMode` hook, the menu-bar update).
- **File encoding.** Most scripts are UTF-8 **with BOM**, but not all (e.g. `template/system/Config.tjs` has none); line endings and a doubled-blank-line artifact (left over from a CRLF conversion) vary by file. Preserve whatever the file already uses and keep diffs minimal — do not normalize whitespace, strip BOMs, or collapse the blank lines as a drive-by. `◆`/`●` markers and some Japanese comments are intentional.
- **The sample's images are generated** by `tools/assets/` (README there): `make_ui.py` draws everything in `data/image` plus `template/system/LineBreak*`/`PageBreak*`, `fgimage/star.png` and `thum_replay_char` in one theme (the Yes/No dialog's: lavender panel (166,144,255), violet (80,37,255) borders and hard shadows, white buttons that go violet when hovered or selected, white labels with a navy (1,0,98) outline, light dotted screen backgrounds), with labels from the Noto Sans CJK JP subsets in `tools/assets/fonts`. `make_ui.py preview` crops `title.png` to the web build's 1200x630 link-preview image (`platform/web/preview.jpg`). `upscale.py` rebuilds `fgimage/ch_*`, `bg01_01`, `event1` and `thum_event1` from the original art in `tools/assets/src` with Real-ESRGAN in NumPy (anime model for sprites, x4plus for the photos; 4x, then down to 1.8x, or 2.4x and the middle 1080 lines). `make_effects.py` makes `data/effect` (see the Effekseer note below), `make_rules.py` the transitions' rule images in `data/rule` (see the transitions note), `make_vector.py` the layer demo's SVG emblem and its PNG twin in `data/fgimage`, `make_clip.py` the same emblem as `emblem.clip` (needs the engine), `make_pip.py` the Animated Character demo's Pip (`data/fgimage/pip`, `charinit.csv`, `charanim.csv`, and with `voice` its babble lines `data/voice/pip*.ogg`, through ffmpeg's libvorbis). Change the scripts and rerun them instead of editing the PNGs; `title.png` and `thum_replay_char` are drawn from the upscaled `bg01_01` and `ch_0_0_1`, so run `upscale.py` first. A panel's hard shadow (`Canvas.panel`) is drawn only outside the panel, so translucent panels (the message window, the choices) stay evenly see-through; anything drawn inside a rounded panel has to stay inside its border's rounded inner edge (the message window's top highlight is clipped to it).
- UI coordinates in `.ks` files (`title.ks`, `config.ks`, …) and the images in `data/image/` are authored for a specific resolution; a resolution change means touching both. The screens share a grid: content from x 290 to 1630, a header title at 290 with a rule at y 170, and 180x64 nav buttons (`return`, the Extras tabs, `config_title`/`config_initial`) right-aligned at y 78. `title.ks`/`title.png`, `config.ks` (with its `config_*` and `slidebar*` images) and the extras screens `cgmode.ks`/`replay.ks`/`musicmode.ks` (`*mode_base`, `extra_*`, `cgmode_page*`, `cgmode_thum_*`, `musicmode_*`, `track*`) and `save.ks`/`load.ks` (`save_base`/`load_base` (semi-transparent so the scene shows through), `sl_win_base`, `*_win_over`, `page1-9`, `newdata`; save thumbnails are 234 wide via `thumbnailWidth` in `data/main/Config.tjs`, and `fileDataButton` in `Override.tjs` lays out the slot: it draws the thumbnail, badge and text into each of the button's three states, so `sl_win_base` is the normal look and `save_win_over`/`load_win_over` the hovered one) are at 1920x1080, as is the choice menu that opens on START (`[selopt]` in `first.ks` sets its area and `size=36`; bars are `select_normal`/`select_over`, and `SelectLayer` spaces the choices evenly within the area). The demo scenes are 1920x1080 too:

The `LineBreak`/`PageBreak` glyphs are 43px cells, 16 frames that the `.asd` plays forwards and back. `test.webm` is 1.8x (2880x1080, side-by-side alpha).

The name has no brackets: the sample's `dispNameFilter` is gone, and `MyHistoryLayer.storeName` brackets it in the history. The sample `Config.tjs` text is 39 (line spacing 5, ruby 15/-3).

  - Hardcoded scenario offsets (`layer.ks` character/rotation origin, `char.ks` walk-off, `envlayer.ks` star paths) were scaled the same way.

  - Yes/No prompts (`template/system/YesNoDialogLayer.tjs`, which `YesNoDialog.tjs` loads; the framework's since 0.0.5, so games made from the template get them too), designed at 1920x1080 (the old box's lavender and purple, square with 14px corners and a hard offset shadow): every `askYesNo` uses `dialog_base` (760x300 panel) or, for a message longer than two lines, `dialog_wide_base` (1080x400). So no prompt reaches the stock `YesNoDialogWindow` (it's `askYesNoWindow` now, used only before the game window exists). The images are in `template/system/` (a game can shadow them from `data/image`). `yesnoFrames` holds each frame's text area and button row. `YesNoDialogLayer` overrides `close()`: closing it without an answer runs the No path, because Esc (`DialogLayer.onKeyDown`), a right-click on the panel or a button (`DialogLayer`/`DialogButtonLayer.onMouseUp`) and outside it (`rightClickHook`) all just call `close()`, which skipped `noFunc`/`doneFunc`; `answered` keeps it to one answer. The focus starts on No. Before the game window exists, `askYesNo` uses `System.confirm` (the SDL engine can't `showModal` a window when it's the only one).

- **Effekseer effects** (`template/system/GFX_Effekseer.tjs`, since 0.4.0) are the `efk` flip type: `[newlay name=fx efk=sparkle show]` on World layers, `[image flip=sparkle.efk]` on KAG layers, options `efkmag` (pixels per unit, 50), `efkwidth`/`efkheight` (canvas), `efkframe` (start frame), `efkx`/`efky`, `efkrot`/`efkrotx`/`efkroty`, `efkzoom`, `efkspeed`, `efkcolor`, `efkinput`, `efktrigger`, `efkstop`, `loop` (`doc/world.txt`, `doc/kagex.txt`; World layers change them with `[name flipupdate ...]`, KAG layers with `[layopt]`). The trigger `efkdone` goes when every effect has ended. `KAGEffekseerOf(kag)` makes the window's `KAGEffekseer` on first use: a KAG plugin (so the window releases the GL objects while its context exists) holding one `GLCompositor` and one `EffekseerDevice`, sharing loaded effects by path and magnification; it links `plugin/krkreffekseer.dll` then, and without the plugin, `GLCompositor` or a GL context (`GLGetProcAddress` 0 on a GPU draw device) it logs why once, and every effect ends at once showing nothing. Each `EffekseerFlip` is a hidden layer the size of its canvas (the screen's unless `efkwidth`/`efkheight`) with its own player: every 15 ms it `progress()`es, `capture()`s and assigns the frame to its layers. `getMainPixel` returns RGB only: read alpha with `getMaskPixel` (a demo once concluded the capture had no alpha from that). The capture keeps Effekseer's alpha, but it's no coverage mask (Effekseer blends alpha with GL_MAX; with `premultipliedAlpha` additive nodes leave it 0), and the engine's ltAddAlpha leaves pixels whose alpha is 0 alone, so premultiplied display can't add light: the layers are drawn ltAdditive (ltAlpha/ltOpaque are switched; other types kept), and normally blended nodes don't darken what's behind them. `KAGEnvLayer.drawLayer` used to stop and restart a layer's flip on every redraw (`[env grayscale=...]`, `resetcolor`, gamma, `forceredraw`), so effects started over; a flip type registered with `keepOnRedraw` (the `efk` entry) now plays on unless the file was just given (`flipNew`, set by `setFlipFile`). A time-of-day change doesn't redraw layers at all. The flip keeps a reference to the options it started with (a World layer's own `flipInfo`): `efkstop` stays in them, and a non-looping effect that ends sets it there, so a later redraw or a load doesn't play it again. Triggers are deleted from the options once sent. `play()` resets an effect's dynamic inputs, so the options are applied after every `play()` (start and loop). Save data keeps the file, options and frame (`play(startFrame)`, capped at 600 frames since the runtime replays them all); an effect fading out after `efkstop` isn't kept. Effects resolve textures relative to the effect file, then by bare name on the auto path, so `data/effect` (on the auto path) holds the effects and `effect/Texture` their textures. **The sample's effects are generated**: `tools/assets/make_effects.py` draws the textures (NumPy) and writes the effects (`sparkle`, `petals`, `fireworks`, `shockwave`, `magiccircle`) as `.efk` with `tools/assets/efkformat.py`, a Python codec for Effekseer's runtime format written from the C++ loader at the commit krkreffekseer builds (b6035eb): it reads 1500, 1600-1610 and 1700-1710 and writes 1610, and `--selftest <folder of .efkefc>` checks it against real files (EffekseerForGodot4's MIT samples were the test vectors; the user wants no third-party effects in the sample). Units: 1 unit = `efkmag` px, frames at 60 a second, rotations in radians. Effekseer's `Circle` spawn picks among `division` points (8 by default: particles came out on 8 rays); the effects are additive, so they need a dark scene (the demo runs at night) and the fireworks sit at World `level=0`, behind the character. Ending: `stopRoot` (`efkstop`) stops the root's spawning; nodes that live for ever (`remove_when_life_ends=False`, the magic circle) need `remove_when_parent_removed` up to the root to go, with `FADEOUT_AFTER_REMOVED` to fade. kagex-release keeps the files `.efk`/`.efkefc` effects name in their format (`effectResources` in `Media.cpp`: the path lists at the start of the binary, matched by leaf), since an effect can't be rewritten.
- **Transitions from plugins** (since 0.5.0): `Initialize.tjs` links extrans and extNagano with `KAGLinkTransitionPlugin`, which records each transition name in `KAGPluginTransitions` ("linked" or "missing"), and `KAGTransitionMethod` (called by `KAGLayer.beginTransition` and `TransLayer`) runs a missing one as a crossfade, logging it once. The World already knew extNagano's names and attributes (`transitionName`/`transitionParam` in `world.tjs`: `trans=` takes a method name directly, with its attributes in the tag). KAG lower-cases attribute names, so `world.tjs` aliases `delayr` to rgbfade's `delayR` and the like, and `KAGLayer.beginTransition` does the same for `[trans method=rgbfade]`. extNagano is krkrz_dev's reconstruction of the 2006 DLL (`src/plugins/extNagano`, `manual.tjs`); honeyturn was unfinished even then. **rgbfade** blends alpha too and takes a pixel of alpha 0 as transparent (a branch that multiplies colours), and the picture of a layer composited with its children for a transition has no meaningful alpha (in the World's scenes rgbfade took that branch all over), so on a whole scene it shows solid black, green and blue (`UPSTREAM.md`): `transition.ks` runs it on KAG layer 0 between two whole pictures with `children=false`, after swapping the event picture for layer 0 under it. **morphing** takes arrays (`before`, `after`: six numbers a triangle, the same grid in both, edges fixed so the triangles keep covering the screen), which a tag can't hold, so the sample registers `swirl` in `envinit.tjs` (built by a function inside the dictionary). The rule images are generated (`tools/assets/make_rules.py`): `rule_shatter` for 3duniversal (red = start time 0-255 over the transition, green = speed, blue = direction: 0 right, 64 down, 128 left, 192 up; Voronoi shards moving out from the centre, the middle ones first) and `wipe_brush` for imagewipe (each row's edge is its rightmost pixel over alpha 0xf0; the picture is drawn just behind it). kagex-release converts `rule/` only to lossless formats. krkrz_web's built-in plugin list already has extNagano; `app-config.json` and `ios-config.json` list it. `smoketest.py` fails when any of the transitions isn't linked.
- **Alpha movies in layers** (`[image movie=... alpha=1|2]`) go through `GFX_Movie.tjs`, which copies each frame with `assignImages`. That doesn't carry the layer type, so `start()` sets the target layers to `ltAlpha` before the first frame arrives (the `[image]` tag shows the layer immediately, and an opaque empty layer flashed white), and `onFrameUpdate` keeps alpha movies at `ltAlpha`. Otherwise the clear parts render solid white, across the whole screen for KAGEX's affine layers.
- **Vector images** (since 0.6.0): `AffineLayer.tjs` links layerExVector (and, failing that, layerExDraw for the Windows-only engine) and, when `GdiPlus.Image` exists (`affineVectorImages`), adds `svg` to the end of `Layer.SupportedExtensions`, so bitmaps of the same name come first. `AffineLayer.loadImages` gives `.svg` (or a name without an extension that `getExistImageName` resolves to one) to `VectorAffineSourceLayer`. layerExVector (`affineVectorThorVG`: its `Image` has no `GetHorizontalResolution`, so the resolution is 100%) has two bugs, both worked around there. (1) `Image.load` hands a loose file's local path to ThorVG, which it builds with `TVG_FILE_IO` off, so a file in `data/` never loaded (archives, `web://` and assets go through a stream and load): `affineVectorStorage` copies such a file once per run to `user://./vector-<leaf>` (SDL storage, never a local path; `user://` subfolders can't be made or read back), which leaves those copies in the save folder. (2) `drawImageAffine` draws a picture with x' = A x + B y + E but clips and updates by x' = A x + C y + E, so a turned picture came out cut off or empty: `drawThorVG` draws axis-aligned transforms with `drawImageStretch` and otherwise rasterizes the picture at its transformed size into a hidden layer (`_raster`, kept while the size and source rectangle stay the same, so a turning picture isn't redrawn every frame) and `affineCopy`s that. SVG `<text>` draws nothing (no font loader). An AffineLayer's `width`, `getMainPixel` and the like are its source image's (empty for a vector source): the smoke test's SVG step reads what the layer drew by `assignImages` into a plain Layer. The sample's emblem (`data/fgimage/emblem.svg`, `emblem_bitmap.png`) is generated by `tools/assets/make_vector.py`.
- **Characters drawn from layers** (Wamsoft's exstand: `KAGEnvCharacterEx.tjs` with `psdlayer.tjs`; `doc/world.txt`, "Characters Drawn from Layers"; the Animated Character demo `anim.ks`): `world.tjs` loads it when `charinit.csv` exists, and its `_getCharacter` makes a character listed there whose envinit.tjs entry has no `poses` one of them. A pose is `<files>_info.txt` (outfits, diffs, faces, by layer name) plus, per World level, `<files>_<level name>.txt` (psdlayer's tab-separated layer structure, top layer first; type 13 is psdfile's ltPsNormal, drawn as ltAlpha) and a picture per layer, `<files>_<level name>_<layer_id>`, loaded without an extension so kagex-release's TLG conversion works. The World puts the canvas centre (moved by charinit's x/yoffset) where it puts a character's anchor, `yoffset` below the screen centre: envinit's 1260 (for Ai's 1620-tall sprites) put Pip's whole canvas below the screen, so Pip's entry sets `"yoffset" => 0` and `make_pip.py` draws it standing 172 below its canvas centre. With blinking or lip-sync off, a group's top layer shows (`defaultEye`/`defaultLip` is `group.layers[0]`), so Pip's eye groups have Open Eyes on top and its mouths Closed Mouth. Lip-sync reads the engine's `WaveSoundBuffer.getSoundLevel` (2.6.5 has it on every platform; the getSample plugin is linked only where it's missing), half a `lipFlipTime` ahead, with the RMS thresholds `lipSyncHalfLevel`/`lipSyncOpenLevel`: `useVisBuffer` has to be on before the voice plays (the visualization buffer is filled as the voice is decoded, and a short voice is decoded at once, so turning it on with the first `getSoundLevel` left nothing to read for most of the first voice: `playVoice` sets it now), and the mouth closes when the voice stops (it used to keep its last level). The timing globals (`eyeFlipTime`, `eyeFlipFreq`, `lipFlipTime` 120, was 180) can be changed in `Override.tjs`. Neither layerExSubImage (linked only when a layer saved in pieces, `.siz`, is drawn) nor layerExSave and saveStruct (psdlayer's export, `saveImages`) are needed by a game. `PSDLayer.updateImage` composites the visible layers bottom-up with `holdAlpha` set after the first, but `operateRect` onto an ltAlpha layer blends alpha all the same (checked), so parts outside the bottom layer's shape still show. The smoke test sets `eyeFlipFreq = 1.0` to see a blink straight away and has a `Timer` in the game note `lipLevel` every 20 ms while the first voice plays (polling through the REPL got 3 readings a line on the macOS runner); it skips that check where the voice doesn't advance.
- **Zip patches and DLC** (minizip): after the plugins, `Initialize.tjs` mounts `patch.zip`, `patch2.zip`... (consecutive, like the `.xp3` patches) from `System.exePath`, then from `System.dataPath` (the save folder; with `-datapath` that folder, which isn't `user://`: SDL's `user://` is always the pref path, `~/.local/share/<orgname>/<appname>/`), through `KAGMountPatchZip(storage)`, which a game also calls for DLC. It lists the zip with `Unzip` (the zip media's listing has files only), mounts it as `zip://kagexpatch<n>/` and adds the root and every folder to the auto path, since unlike `patch.xp3>` a `zip://` auto path isn't flattened. `KAGPatchZips` lists what's mounted. The smoke test writes `patch.zip`/`patch2.zip` into the desktop sample's save folder before starting (`write_boot_patches`), and on every target writes a zip with minizip's `Zip` class and mounts it while running.
- **`clip://` images** (clipfile, linked at start): the plugin serves each CLIP STUDIO PAINT layer as a BMP, and outside `_WIN32` it declares the BMP file header struct unpacked (16 bytes), so the engine's reader fails with "Non-supported header version" on every SDL platform but Windows (psdfile's `psd://` has the same code). `affineLoadClipLayer` (`AffineLayer.tjs`, from `BitmapAffineSourceLayer.loadImages`) parses `clip://<file>/root/<path>.bmp` or `/id/<LayerId>.bmp` and draws the layer with `CLIP.getLayerData` into a temporary Layer, then `assignImages`; it keeps up to 8 `CLIP` objects with their path-to-index maps (names lower-cased, `/` as `_`, a later layer winning, as the plugin's storage does). It returns `%[]` as the image info: callers of `loadImages` expect a dictionary. So `clip://` works on KAG and World layers, not where a plain `Layer.loadImages` reads it (message frames, buttons). The sample's `emblem.clip` is made by `tools/assets/make_clip.py`, which edits clipparse's `samples/emptyimage.clip` with `CLIPWriter` through the engine's REPL (a `.clip` holds a database CLIPWriter can't create) with a fixed `setSeed`, so it rebuilds byte for byte; its layers are `badge` (LayerId 3) and `star` (5). In a REPL test, wait for the title screen before loading into `kag.fore.layers`: the logo's transitions swap the pages under it.
- **English text in scenarios.** In normal mode (`[linemode]` with no mode, `ignoreCR` on), a new line in the `.ks` adds nothing, so text split by tags (`[wact]`, `[emb]`, …) runs together. End such segments with punctuation and a trailing space (trailing spaces are kept). Plain text lines get word wrap from this fork's `needsToBeWrapped()` in `MainWindow.tjs`, which breaks before a word that won't fit. The space at the break is dropped through `wrapDropSpace`/`wrapDropSpaceHist`, which the `ch` handler checks; assigning `text = ""` inside that function had no effect. Its state belongs to one scenario line, keyed by `conductor.curStorage:curLine` (not by content, so identical lines in a row each wrap), and `internalRestoreFlags` resets it. The `ch` handler calls it after its early returns, because a handler that returns -3 or -5 gets the same tag run again (`Conductor.waitAndBreak` re-queues it): a page break the wrap returns sets `wrapResume`, and the re-run measures from the new page and drops the space instead of counting it as another word. The `wrapNewPage` flag that did this before was never cleared, so after one wrap overflowed a page every later wrap became a page break. Lines it skips (any line containing `[r]`, or starting with a tag or tab) fall back to KAG's character wrap, which can split words. There, `MessageLayer.processCh` and the history layers drop a space that would start a wrapped line. Break long English lines yourself with `[r]` at a sentence boundary when they contain tags. `[initscene]` uses `[linemode mode=page]`, where every scenario line stands alone.
- **Sound extensions.** Where a script names a sound without its extension, `BGM.tjs` (`KAGSoundBuffer.SupportedExtensions`), `SE.tjs`, `KAGEnvCharacter.getVoicename` and `KAGEnvironment`'s voice list try `.wav`, `.ogg`, then `.opus` (since 0.3.0; the engine plays all three). A game with an older `data/system` doesn't find `.opus` files, and kagex-release refuses Opus for it.
- **Image extensions.** Look for an image with `getExistImageName(name)` (`Utils.tjs`, every format in `Layer.SupportedExtensions`), never `Storages.isExistentStorage(name + ".png")`: kagex-release converts images to `.tlg` (or `.jpg`), and the loaders (`loadImages`) find those by themselves while such a check doesn't. `MessageLayer.getExistName`, which finds a button's `_over`/`_on`/`_focus` images, tried `.png`, `.tlg5`, `.tlg6` and `.bmp` only up to 0.3.0, so in converted builds no button highlighted; it uses that list since 0.3.1, and kagex-release refuses TLG and JPEG for an older framework (`frameworkFindsConvertedImages`). The sample's `setCGImage` (`Override.tjs`) had the same `.png` check for `thum_<name>`. `tools/release/test/smoke.py` runs the converted Linux build and hovers the title's Start button.
- **【name】 tags must use the character's key** from `envinit.tjs` (the same name as its tag, e.g. `【ai】` for `[ai ...]`). Keys are case-sensitive. Voices set with `[ai voice=N]` are looked up by that key, and so are faces and the character link. The translation had written `【Ai】`, which silently dropped the voice. The displayed name comes from the character's `nameAlias` ("Ai"), or from `【ai/Display】` for one line.
- **Never test a string as a boolean** (`if (s)`, `s ? a : b`). The current engine converts it to a number, so `"event1"` is false, and an empty string segfaults it (`tTJSVariantString::ToInteger`). Compare instead: `if (s != "")`. This crashed the Replay screen whenever an unlocked entry had no thumbnail.
- **Font faces on the SDL engine.** A face name the engine has not registered (e.g. `MS Gothic` on Linux, and on some machines plain `Noto Sans CJK JP` when only the Light weight is registered) is drawn with its `elements_basic` icon font, so text shows as `←←←`. The engine's own default face (an empty face) has the same problem here. So `userFace` and the history `fontName` in both `Config.tjs` files, plus the explicit faces in `about.ks`, `Override.tjs` and the history classes' defaults, are face lists with Yu Gothic first: `"Yu Gothic Medium,Yu Gothic,Noto Sans JP,Roboto"` (the template uses the same list). **Noto Sans JP ships in `template/system/notosansjp-regular.otf`** (the engine's own `resource/notosansjp-regular.otf`, SIL OFL, `notosansjp-OFL.txt`): since engine 2.5.0 the engine embeds only Roboto, so Japanese depended on system fonts and drew as U+FFFD boxes without them. `Initialize.tjs` registers it with `Font.registerFontFile(path, "Noto Sans JP")` after the plugins, which records the name without opening the file; `Font.getVarAxes` then resolves it and krkr_richtext draws it. Where the engine already has a font of that name (the browser build bundles Noto Sans JP in its `resource/`), it loads the file with `Font.addFont` instead: the engine finds a bundled font only in the exact style asked for, and its rasterizer keeps one face chain, rebuilt only when the first face of the list changes, so the first text drawn in a face list being bold (the `[select]` choices) left that chain on the icon font (`elements_basic`, which its fallback means to skip): every text came out as arrows measuring 0 wide. A loaded font is found in any style. To check rendering without system fonts, run with `FONTCONFIG_FILE` pointing at a config whose only `<dir>` is empty. Up to 0.0.4 the list was `"Yu Gothic Medium,Yu Gothic,MS Gothic,Noto Sans CJK JP,Noto Sans CJK JP DemiLight,Noto Sans CJK JP Light,Roboto"`, which is now in `previousDefaultFaces`; the notes below about system Noto CJK names explain why that list looked like that. Unknown names in a list are skipped, and both the engine and krkr_richtext pick a font per character from the list. Yu Gothic leads on Windows because its Latin letters are proportional and kerned: MS Gothic's are fixed-width, which made English look gappy (`over lap`) and left krkr_richtext nothing to kern. Yu Gothic Medium is the readable weight on screen; plain Yu Gothic is the fallback where Medium is missing. Don't pick a font that isn't the first in its `.ttc` (MS PGothic, MS UI Gothic, Yu Gothic UI, MS PMincho): the engine's `drawText` gets those right, but krkr_richtext draws the collection's first font instead (MS Gothic, Yu Gothic, MS Mincho), so MS PGothic comes out monospaced again. That's an upstream bug (plugin or engine), seen on Windows; the template used `MS PMincho` until 0.0.4 and was affected. Plain `Noto Sans CJK JP` fails on Arch because the Light file also claims the Regular style, while the weight-suffixed names resolve. Roboto ships with the engine, so it is always available for Latin text. `kag.chDefaultFace` is saved into the system variables (`*sc.ksd`, `scflags`) and wins over `Config.tjs`. When a saved value is a single old-style name (e.g. `MS Gothic`), the restore code in `MainWindow.tjs` keeps it first and appends the configured list. A saved value equal to a default some earlier release shipped (`previousDefaultFaces` in `MainWindow.tjs`, which now lists `ＭＳ ゴシック`, `MS Gothic`, the 0.0.2 list and the template's old values) is replaced by the configured default instead, so a changed default reaches existing saves; add the old value there whenever a default changes. Without `-datapath` the engine keeps that data in `~/.local/share/wamsoft/krkrz/`, not `savedata/`. Use the face lists for any new text too.
- **krkr_richtext.** With `useRichText` (MessageLayer_config, on in both `Config.tjs` files) and the plugin loaded, `drawTextToLayer` in `MessageLayer.tjs` draws message text, ruby and the name box through `RichTextFontApp`: vector edges/shadows built from the layer's edge/shadow settings, fake bold, and in `processCh` kerned advances (the exact width of the line's run, rounded per character). Vertical text and bitmap fonts keep the normal path, as does anything when the plugin or the fonts are missing. The `[select]` choices and the history log (both `data/main/MyHistoryLayer.tjs` and `template/system/HistoryLayer.tjs`) follow the message layers' `useRichText` with `RichTextFontApp` instances of their own: `SelectLayer` puts its app into the style dictionary as `richTextApp`, and the history draws whole lines through `drawHistoryText` (no edge or shadow, as before). `SelectLayer` borrows `MessageLayer.drawTextToLayer` `incontextof` that style dictionary, so that function may only touch members the dictionary has (a call to a MessageLayer method there broke every `[select]`). Text widths must come from the path that draws the text, or English lines break in the middle of a word once the font is proportional: `MessageLayer.measureText`, `SelectLayer.measureText` (choice centering) and `HistoryLayer.textWidth` (wrapping, action marks, indent) measure with krkr_richtext when it draws, and the word wrap in `MainWindow.tjs` (`needsToBeWrapped`) measures words through `msgTextWidth`/`histTextWidth`. Edges and shadows: `Layer.drawText` draws both as a blurred copy of the glyphs. The edge becomes a stroke reaching `edgeExtent` past the glyphs, fully opaque from `edgeEmphasis` 255 up (the default 512) and fainter below; a shadow with `shadowWidth` (blur) > 0 gets three widening translucent strokes around the offset copy. The sample's settings (shadow, offset 2, no blur) render the same either way. The baseline comes from the engine's `getGlyphDrawRect("H")`, so lines sit where `drawText` put them. The line layer only reaches `lineLayerPadding` (4) below the text cell, and krkr_richtext's descenders (g, y) plus the shadow reach further, so they were cut off at the bottom of each line: `MessageLayer.updateLineLayerPadding` (from `initLineLayer`) widens the padding per line from `RichTextFontApp.bottomOverhang`, and without krkr_richtext (the browser and iOS builds) from the engine's `getGlyphDrawRect("gjpqy")` plus the shadow or edge, where the 4 px cut 2 px off every descender; it's symmetric and every offset uses it, so nothing moves. `drawTextEx` only calls `update()` on the glyphs' ink box, which leaves shadows and edges off the screen until something else repaints there (text looked clipped while typing, then changed when the line was committed), so `RichTextFontApp.drawText` updates the whole padded cell itself. **Never pass `RichText.registerFont` (or `Font.getFontInfo`/`Font.queryFonts`) a face name the engine can't resolve:** the engine then opens every system font to search their names, and its pooled file allocator deadlocks (it runs the storage-cache pressure callback while holding its own mutex, at 75% of `-filepoolsize`, default 256 MB). A hung engine ignores SIGTERM; use `kill -9`. `RichTextFontApp.getFonts` only registers names that `Font.getVarAxes` resolves (it uses the same lookup as `drawText`, without the search) and that the engine actually draws; plain `Noto Sans CJK JP` passes the first test on Arch but draws nothing, so the chain here is DemiLight → Light → Roboto.
- **Engine BMP bug.** The current engine's BMP writer puts `bfOffBits = 56` in the header but writes the pixels at byte 54, and its reader trusts the header. The cause is in the engine's `common/visual/GraphicsLoaderIntf.h`: `#pragma pack(push, 1)` around `TVP_WIN_BITMAPFILEHEADER` is only applied under `_WIN32`, so on Linux (and macOS) the 14-byte header struct is padded to 16 and `sizeof` gives 56; Windows builds write correct BMPs. Don't patch the engine (krkrz_dev is off-limits). So anything saved with `saveLayerImage(..., "bmp")` comes back color-shifted. This is a krkrz bug. To avoid it, bookmarks (`MainWindow.tjs`) now save their thumbnail as PNG: the save files are `dataN.png`, the save data starts at `calcThumbnailSize().size` (sized for an uncompressed RGBA PNG), and the thumbnail is forced opaque because PNG keeps the snapshot's meaningless alpha. `thumbnailDepth` is unused, and old `.bmp` saves are no longer picked up (only 0.0.1, the 800x600 Windows package, wrote them: PNG thumbnails came in 0.0.2). The engine picks image decoders by file extension, so PNG data in a `.bmp`-named file won't load. The PNG is shorter than that offset, and seeking past the end of a file fails on some storage ("Seek error" in the browser), so `saveThumbnailAndData` (used by `saveBookMarkToFile` and `rewriteBookMarkToFile`) grows the file to the offset with `Storages.truncateFile` first. Where the save folder isn't a local file (`user://` in the browser, Android and iOS builds), `truncateFile` throws "Cannot get local name": the file is then put together in `Storages.getTemporaryName()` (a native path, made a storage name by `localStorageName`) and copied over with `Storages.copyFile`. Before this, every save there failed and showed the save-failed message, which blocked the title screen's anchor save.
