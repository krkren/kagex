# Upstream issues

kagex never changes krkrz_dev, its submodules or its plugins (`CLAUDE.md`). This file lists the problems in them, and in Wamsoft's platform kits, that kagex can't work around: each one costs a feature or a platform until it's fixed upstream. They're sorted by importance, most important first. Bugs the scripts or the CI work around aren't listed here; `CLAUDE.md` describes them next to their workarounds.

These were found against engine 2.6.5 (krkrz_dev `21d20e9` of 2026-10-20, krkrz-core `7d91ba5`), the plugins it pins (krkr_richtext `52bbb5c`, krkreffekseer `f8197fa` with Effekseer `b6035eb`, extNagano `4b403e2`, krkrthreepp `78138f4` with threepp `870d620`, krkrlive2d `dbdb29f` and its newest commit `8edeb8e`, with the Live2D driver at `58c4c66` and tp_stub `35ef31a` and ncbind `256502b` for building it on its own), and the kits `platforms.yml` pins (krkrz_android `eff2b17`, krkrz_ios `003abad`). When one is fixed upstream, use the fix and delete the entry.

## 1. The REPL handles TJS values on its own thread

- **Where:** `tTVPReplFileChannel::Execute` (`common/utils/ReplFileChannel.cpp`) runs a command on the main thread through `TVPReplMainQueue::Submit`, then pretty-prints the result (`TVPPrettyPrint`) and releases it on the channel's own thread; the console REPL does the same (`REPL.cpp`). TJS strings and objects have reference counts that aren't atomic (`tTJSVariantString::RefCount`), and the main thread keeps copies of a returned value in its VM registers after the call (`tTJSVariantArrayStack::Deallocate` doesn't clear them), so both threads change the same counts.
- **What it costs:** an engine driven through the REPL aborts now and then: "double free or corruption", "free(): corrupted unsorted chunks", Windows' 0xC0000374. The busier the main thread, the likelier: about one run in five of the release smoke test on GitHub's runners, mostly during the Animated Character demo, and never on a 2-CPU development machine. Under gdb the aborts were in `tTJSVariantString::Release` (on the main thread or the channel's) and in `TVPPrettyPrint` on the channel's thread. kagex's desktop tests (`run-kagex.ps1`, `smoketest.py`'s file channel) make every command return 0 and have the main thread write the value to a file; the Android, iOS and web tests still read their channels' results. The iOS REPL (`HandlePadExec` in `common/utils/ReplWebServer.cpp`, `-replweb`'s `POST /pad/exec`) does the same on its HTTP thread: `TVPReplMainQueue::Submit` assigns the script into `g_req_script` and copies and clears `g_resp_result` there, and the result is pretty-printed and released there; 0.18.1's second release run lost the Simulator's game to it (SIGABRT, `pointer being freed was not allocated` in `TJSDeallocStringHeap` as the main thread freed an array during a `kag.process` the REPL had queued). (The web's `krkrz_repl_eval` runs on the main thread, so it doesn't race.)
- **Fix:** pretty-print the result on the main thread, inside the queued task, and hand the channel's thread only a `std::string`.

## 2. In the Linux kit build an exception that crosses a plugin aborts the game

- **Where:** krkrz_linux's engine and plugins each carry a static copy of libgcc's unwinder (in the backtrace below `_Unwind_RaiseException_Phase2` is the engine's and `_Unwind_SetGR` the plugin's). A C++ exception the engine throws that unwinds through a plugin's frame runs the plugin's personality routine, which calls its own copy's `_Unwind_SetGR`, whose register table only that copy's unwinder fills in: it's empty, and `_Unwind_SetGR` aborts. Seen in the json plugin's `V2Unlink`, which looks up `Scripts` (`TVPExecuteExpression`) inside `TVPDoTryBlock` when the engine unlinks its plugins on the way out (`TVPSystemUninit`, `TVPDestroyPluginVector`): by then the lookup throws, and the engine would catch it, but the unwinding never gets there (gdb: `abort` ← `_Unwind_SetGR.cold` ← `__gxx_personality_v0` in `libjson.so` ← `_Unwind_RaiseException_Phase2` in `krkrz`). The zip packages and macOS catch it, as they should.
- **What it costs:** every exit of the kit's Linux build (the Steam package) dumped core while the json plugin was linked: `-scncompile`, `System.exit`, and a player closing the game. krkrthreepp (3D) did the same once linked: its `V2Unlink` takes its web API off `WebServer` with `TVPExecuteExpression` (`unregisterThreeppWebApi`, an ncbind pre-unregister callback, inside its own `try`/`catch (...)`), which throws once the script engine is gone, and its own catch aborted the same way (gdb: `abort` ← `_Unwind_SetGR.cold` ← `__gxx_personality_v0` in `libkrkrthreepp.so` ← `_Unwind_Resume` in `krkrz` ← `TVPExecuteExpression` ← `unregisterThreeppWebApi`). kagex unlinks both plugins while TJS is still there (`KAGUnlinkPluginsBeforeExit` in `Initialize.tjs`, before the framework's exits and from `KAGWindow.finalize`, after the window's KAG plugins have released their 3D objects; the engine keeps a plugin linked while any of its objects live), and `smoketest.py` checks that the game quits with exit code 0. Any other exception that unwinds through a plugin's frame (a script error in a callback a plugin makes into TJS) can still abort the kit build where the other builds show the error.
- **Fix:** link the engine and the plugins against one shared libgcc_s (and libstdc++), as the Steam Linux Runtime provides, or catch exceptions at every plugin boundary (tp_stub's entry points and ncbind's thunks) so none unwinds through another copy's frames; and in the json plugin and krkrthreepp, run no TJS in `V2Unlink` once the engine is shutting down.

## 3. The web build's prefetch makes cache entries before it writes them

- **Where:** krkrz_web's `pre.js` prefetch (`runPrefetch` in `krkrz.js`) creates each OPFS entry with `getFileHandle(key, {create: true})`, an empty file, and only then writes and closes it; the engine's `krkrz_web_fetch` (`HttpStorageMedia.cpp`) opens any entry it finds and takes its contents as the file, with no size or completeness check. And `TVPExecuteStorage` (`ScriptMgnIntf.cpp`) opens a script twice: as bytecode (`LoadByteCode`, which reads the 8-byte tag without checking how much it got) and, when that isn't bytecode, again as text.
- **What it costs:** a file the engine read while the prefetch was writing it came back empty. A compiled script then read empty as bytecode and whole as text: `Syntax error at line 1`, and the error dialog stopped the page (`RuntimeError: unreachable`). Three of five runs of kagex-release's web (files) test on the Linux runner; any web build with a prefetch list could also get an empty image or script. `kagex-web.js` makes a lookup of an entry being written wait for the write (and removes an entry a failed write left).
- **Fix:** write each prefetched file under a temporary name and move it into place (or create it only once its data is ready), and treat an empty entry as a miss; open a script once and look at its first bytes.

## 4. iOS can't build krkr_richtext or krkreffekseer

- **Where:** the plugins' CMake projects under CMake's Xcode generator (CMake 4.4, Xcode 16.4), which stops with "duplicate object ids not allowed". A bisect of the iOS build's plugin list pinned it to krkr_richtext, and krkreffekseer fails the same way.
- **What it costs:** the iOS build has neither plugin. Text is drawn with the engine's `drawText` (no kerning, no vector edges or shadows), and Effekseer effects show nothing (the console says why).
- **Fix:** not found yet. The error usually means a source file or object library is added to a target twice, or that two targets share an object library in a way the Xcode generator can't represent.

## 5. krkr_richtext doesn't compile for the web (wasm32)

- **Where:** krkr_richtext's `src/main.cpp` casts a `tTJSVariant` to `tjs_intptr_t` to get a layer's image buffer (`static_cast<tjs_intptr_t>(val)` at lines 448, 636 and 1574). tp_stub's `tTJSVariant` only has `operator tjs_intptr_t` on Apple (`#ifdef __APPLE__` in `tjsVariant.h`) or where `intptr_t` is `int64_t`. On wasm32 it's 32 bits, so no conversion exists.
- **What it costs:** the web build has no krkr_richtext, so its text is drawn with `drawText`, as on iOS.
- **Fix:** convert through `tjs_int64` (`(tjs_intptr_t)(tjs_int64)v`), or give tp_stub's `tTJSVariant` the `tjs_intptr_t` conversion on every platform.

## 6. Effects can only add light

- **Where:** two places together. Effekseer blends alpha with `GL_MAX`, so the alpha in a `GLCompositor.capture` of an effect is no coverage mask, and with `premultipliedAlpha` additive nodes leave it at 0. And the engine's `ltAddAlpha`/`omAddAlpha` blend leaves a source pixel whose alpha is 0 alone, instead of adding its colour, so even correctly premultiplied output can't add light where it's transparent.
- **What it costs:** layers that show an effect have to be drawn `ltAdditive` (`GFX_Effekseer.tjs`). Additive effects look as they do in Effekseer's editor, but normally blended nodes can't darken what's behind them: smoke, shadows and dark particles don't work. The same engine behaviour limits any premultiplied image with glows.
- **Fix:** a capture that writes coverage (a separate alpha blend: `glBlendFuncSeparate` with `ONE, ONE_MINUS_SRC_ALPHA` for alpha), together with `ltAddAlpha` adding the colour whatever the alpha, as premultiplied blending does (or a new layer type that does).

## 7. Every frame of every effect is read back from the GPU

- **Where:** `GLCompositor.capture` renders into an offscreen buffer and copies it into a layer's main memory, and each `EffekseerFlip` captures its whole canvas about every 15 ms.
- **What it costs:** the cost grows with the canvas size and the number of effects on screen, which matters most on phones and in the browser. The sample keeps its canvases small (`efkwidth`/`efkheight`).
- **Fix:** let a layer show a GL texture without copying it back (composited by the GL draw device), or render effects directly in the draw device.

## 8. Android can't link the engine with accessibility

- **Where:** with `KRKRZ_USE_A11Y` (the `a11y` plugin), the engine's AccessKit setup can't find its Android library: `find_library` runs inside the NDK's find root. `libkrkrz.so` then doesn't link.
- **What it costs:** the Android build has no screen reader support, which the desktop builds have (since 0.12.0).
- **Fix:** find AccessKit's Android library outside the NDK's find root (an imported target or an explicit path).

## 9. Errors in compiled scripts have no line numbers

- **Where:** `Scripts.compileStorage` with its debug information on (`outputdebug`) writes each function's source positions in `tTJSInterCodeContext::ExportByteCode` (`tjsInterCodeGen.cpp`) with the table's size in bytes (`SourcePosArraySize * 8`) as the count, and then that many entries of each of its two arrays, reading past the end of `SourcePosArray`. An engine that runs such bytecode dumped core as soon as it reported an exception, while it printed the disassembly of the failing function.
- **What it costs:** kagex-release compiles without debug information, so an error in a compiled script names the script and the function at line 1 (`MainWindow.tjs(1)[(function) onKeyDown]`), and players' error reports lose the line.
- **Fix:** write `SourcePosArraySize` as the count, and check that an exception report works for bytecode, which has no source text to show.

## 10. Bytecode compiled on Linux and macOS cuts integer constants to 32 bits

- **Where:** `tjsConstArrayData::GetType` (`tjsConstArrayData.cpp`) puts an integer constant into the 32-bit table when `val >= LONG_MIN && val <= LONG_MAX`. `long` is 32 bits on Windows but 64 on Linux and macOS, so there every constant goes into the 32-bit table, cut (`PutInteger(static_cast<tjs_int32>(...))`): `0xff000000` loads as -16777216, `4294967296` as 0. The loader reads the 64-bit table correctly. `tTJSBinarySerializer::PutInteger` (`tjsBinarySerializer.h`) has the same test for negative numbers.
- **What it costs:** kagex-release compiles each script with such literals a second time to put them right (`tools/release/src/Scripts.h`), but it can't follow a constant the compiler works out from others (`0xff << 24`, a number in `@"${...}"`), so on Linux and macOS a script with one stays source.
- **Fix:** test against `tjs_int32`'s range (`INT32_MIN`, `INT32_MAX`) in both.

## 11. Effects need the GL draw device

- **Where:** `GLCompositor`'s `GLGetProcAddress` (`common/visual/opengl/GLCompositorIntf.cpp`) is 0 on the GPU draw device.
- **What it costs:** krkreffekseer can't draw with the GPU draw device; every effect ends at once there and the console says why.
- **Fix:** expose the GPU device's GL function lookup to `GLCompositor`, or document that it needs the GL draw device.

## 12. Live2D: the driver builds only for Windows, Android and iOS, and krkrz_dev doesn't build krkrlive2d

- **Where:** krkrlive2d's CMake fetches its driver, wtnbgo/live2d, at `main` (`58c4c66` of 2026-10-26), whose `CMakeLists.txt` defines the `live2ddriver` target only under `WIN32`, `ANDROID` and `IOS` (its own notes say the Android and iOS builds are untested since its move to Cubism 5 R5). krkrz_dev lists krkrlive2d among its plugins with the line commented out (`CMakeLists.txt`: a driver at another commit wanted `find_package(minizip)`, which its vcpkg manifest lacks), so none of its builds has it. And Live2D's Cubism SDK for Native has no WebAssembly Core (its Core folder has Windows, Linux, macOS, Android and iOS libraries), so a web build would need Live2D's Cubism Core for Web bridged into the engine.
- **What it costs:** Live2D characters (`KAGEnvCharacterLive2D.tjs`) need the plugin, which a game builds with its own Cubism SDK (Live2D's licence keeps the Core out of kagex's engines in any case). kagex builds it with `tools/live2d/build.py`, which on Linux and macOS builds the driver through its own CMake (`tools/live2d/driver`: GLAD's GLES 2 loader and the Core's static library, as on Android); the web has no plugin. The smoke test checks the framework with a stand-in for the plugin (`tools/live2d-standin.tjs`) where there's no SDK.
- **Fix:** build the driver for Linux and macOS as for Android (GLAD's GLES 2 loader, the Core's `lib/linux/x86_64` and `lib/macos/arm64` static libraries), pin the driver's commit in krkrlive2d's CMake, and build krkrlive2d in krkrz_dev when `CUBISM_SDK_CORE` is set.

## 13. krkrlive2d plays a motion given by number from the start of its group, and a model's Idle group as differences

- **Where:** `startMotion` (`src/Live2D_common.cpp`) passes `params[0]->AsInteger()`, the group's name, as the motion's number when its second argument is a number, instead of `params[1]`. And the driver makes an `Idle` group of difference motions (`AddMotionGroup("Idle", 1)` in `LAppModel.cpp`) before the model's own groups, so a model3.json `Idle` group (Live2D's sample models have one) loads as differences added to the main motion rather than as the motion itself.
- **What it costs:** `startMotion("Idle", 3)` plays Idle's first motion, added on. `KAGEnvCharacterLive2D.tjs` plays every motion by its name (`getMotionName`) as the main motion, which the driver loads from the model's `motions/` folder: a model has to keep its motions there, as Cubism Editor's export does.
- **Fix:** `params[1]->AsInteger()`; make the driver's own groups only for a model that has no group of that name.

## 14. rgbfade can't change a whole scene

- **Where:** extNagano's `rgbfade.cpp` (`Process`): where either picture's alpha is 0, it takes a branch meant for transparent pixels that multiplies the colours (`(s1b * opaB) & 0xff`), and it ignores the layer type `StartTransition` is given. The picture the engine composites for a transition with children (a layer with what's on it) has no meaningful alpha: in the World's scenes rgbfade took the transparent branch all over the screen.
- **What it costs:** on a whole scene (any World transition, or KAG's base layer with characters on it) rgbfade shows solid black, green and blue. It only works between two whole pictures on one layer with `children=false`, which is how the sample's `transition.ks` shows it.
- **Fix:** blend the channels as usual for an opaque layer type (`ltOpaque`), and blend rather than multiply the colours in the transparent-pixel branches.

## 15. Plugins KAGEX uses that krkrz_dev doesn't build

Script features that need these log the missing plugin and carry on without the feature.

- `gfxEffect`: the fire effect (`GFX_Fire.tjs`).
- `windowEx`: the extended window events, hiding the menu bar, and the window-control menu icons (`MenuItem.bi*`). `MainWindow.tjs` and `Menus.tjs` skip those paths.
- `flashPlayer`: Flash movies (`GFX_Flash.tjs`). Flash itself is long gone, so this matters only to old games being ported.

## 16. StyledLayout's ruby can't be sized or placed

- **Where:** krkr_richtext's `TextRenderer::drawStyledLayout` (`richtext/src/TextRenderer.cpp`) draws a `<ruby>`'s text at `parserOptions.rubyScale` (0.5) times the size of the text under it, with its descent on the text's ascent, centred over it. `TagParser::ParseOptions` (`rubyScale` and the rest) can't be set from TJS: the `StyledLayout` binding (`src/main.cpp`) has no options, and there is no gap or offset at all.
- **What it costs:** KAG sizes and places ruby with `rubySize` and `rubyOffset` (the sample's 15 px, 3 px down, over 39 px text, between lines 5 px apart). StyledLayout's would be 19.5 px and reach into the line above, so where the message window draws a line's characters together (`useStyledLayout`, `MessageLayer.drawStyledRun`) a character with ruby is a run of its own and KAG draws its ruby as before; krkr_richtext doesn't lay out the ruby with the text.
- **Fix:** bind the parse options (at least `rubyScale`) to `StyledLayout`, and give ruby an offset from the text (or a style of its own: `<ruby text='...' style='name'>`).

## 17. krkr_richtext's Japanese line breaking is only for vertical text, which TJS can't reach

- **Where:** krkr_richtext's JLReq typesetting (`richtext/src/vertical/`: `CharClass`, `LineBreaker`, `LineItemBuilder`, `VerticalParagraphLayout`, `BlockLayout`: kinsoku as penalties, hanging punctuation, punctuation spacing, ruby that widens its text, tate-chu-yoko) lays out vertical text only, and `src/main.cpp` binds none of it. Horizontal text goes through minikin (`ParagraphLayout`), whose line breaker follows UAX #14 with ICU's tailoring for the language: a closing bracket, a full stop or a small kana doesn't start a line, but nothing hangs into the margin and nothing is spaced or squeezed.
- **What it costs:** vertical messages keep KAG's own drawing and its character wrap with kinsoku. Horizontal Japanese and Chinese lines break where `ParagraphLayout` says (`needsToBeWrapped`), so they end before `relinexpos`: the margin KAG keeps for hanging punctuation (`marginRCh`) stays empty, and a character that can't start a line takes the one before it to the next line, where KAG let it hang.
- **Fix:** bind the vertical layout (a `VerticalStyledLayout` with `drawStyledLayout` and per-line results), and offer the JLReq line breaker (with hanging) for horizontal text too.

## 18. A Yes/No prompt during an overlay movie can open under the movie

- **Where:** the SDL engine's `Window.setMaskRegion` throws "not implemented", so `YesNoFrameDialogWindow`, the shaped window KAG shows over a playing movie, can't be used.
- **What it costs:** on the SDL engine every prompt is a layer of the game window (`YesNoDialogLayer`), which an overlay movie can cover.
- **Fix:** implement `setMaskRegion` (SDL3 has shaped windows: `SDL_SetWindowShape`).

## 19. Full screen in the browser waits for the next tap

- **Where:** the browser build requests full screen from its own main loop rather than from a user event, and browsers only allow it during one.
- **What it costs:** on Android and iPad, choosing full screen in the Config screen takes effect only on the next tap.
- **Fix:** make the request from the input event that triggers it, or queue it to the next pointer event in JavaScript.

## 20. Tests can't hold a key down

- **Where:** keys injected through `Agent` or the REPL don't change `System.getKeyState`.
- **What it costs:** the smoke tests press and release keys over two frames, but can't test anything that needs a key held: skipping while Ctrl or the controller's R2 is held.
- **Fix:** have the injected key events update the key state that `getKeyState` reads.

## 21. The sigcheck plugin keeps file sizes and offsets in 32-bit ints

- **Where:** `src/plugins/sigcheck/main.cpp` (`SigChecker::CheckSignatureOfFile` and `CheckKrkrExecutable`) holds the file size, the running byte count and the mark offsets in `int`/`tjs_uint32`. krkrz_tools' `krt::sig` (the signing side) uses 64-bit offsets, so it signs any size correctly; only the engine-side verifier is 32-bit.
- **What it costs:** signatures (`sigcheck`, used by `template/system/SignatureCheck.tjs`) can only be checked on files below 2 GB. From 2 GB the progress byte count overflows (odd or missing progress events, but the hash still verifies); past 4 GB the size is truncated to 32 bits (thousands of spurious progress events); and at an exact multiple of 4 GiB the size reads as 0 and the per-cent calculation divides by it. kagex-release works around it by keeping every signed archive under 2 GB — splitting a large game's media into separate archives (`Build.cpp`, `splitIfNeeded`) — and refusing a single folder of 2 GB or more. Confirmed on the 0.8.0 Linux engine: a 1 GB file verifies in ~12 s; 2.3 GB and 4.1 GB verify but with the byte-count problems above.
- **Fix:** use `tjs_int64` for the size, the running offset and the mark offsets in the plugin, matching `krt::sig`.

## 22. The sigcheck plugin reads each file several times per check

- **Where:** `SigChecker::CheckSignature` calls `CheckKrkrExecutable` three times (searching for the `XOPT_EMBED_AREA_`, `XRELEASE_SIG____` and XP3 marks), each a full scan from the start of the file, before `CheckSignatureOfFile` reads the whole file once more to hash it.
- **What it costs:** start-up of a signed build (`SignatureCheck.tjs`) reads the game archive and every engine file about four times over. For a large archive that is seconds of disk I/O before the game appears; splitting (above) spreads it across several files but doesn't reduce the total. The mark search also has no business running on a plain data file (only an executable carries the marks), but the plugin runs it on everything.
- **Fix:** scan for all three marks in one pass, skip the executable-mark search for a file that isn't an executable, and reuse that read for the hash.

## 23. Bytecode indexes are 16 bits

- **Where:** `ExportByteCode` writes each function's code words and each constant's table index as 16-bit numbers (`Add2ByteToVector`, `(tjs_int16)constarray.PutVariant(...)`), and `tTJSByteCodeLoader` reads them back signed.
- **What it costs:** a script with a function of more than 32767 code words, or with more than 32767 different strings or numbers, would load wrong, so kagex-release leaves one as source. KAGEX's largest, `MainWindow.tjs`, has 2259 strings and at most 3469 code words in a function.
- **Fix:** 32-bit code words and indexes, in a new version of the bytecode format.

## 24. A playing voice's position and level come from the wrong part of it now and then

- **Where:** `tTJSNI_QueueSoundBuffer::GetSamplePosition`, `GetCurrentPlayingPosition` and `GetVisBuffer` (`common/sound/QueueSoundBufferImpl.cpp`), behind `position`, `samplePosition`, `getVisBuffer`, `getSoundLevel` and `getVowel`, take the samples the stream has played modulo the sample count of the first buffer still in `Samples`, and read that buffer at that offset. That's right only while the first buffer in `Samples` is the one playing and every buffer before it had the same count. A played buffer leaves `Samples` when the stream's callback releases it (`ReleasePlayedSample`), so for a while after the stream moves on, the offset into the new buffer is read in the old one (the likely cause; the jumps seen go both ways). Measured with a voice playing: `samplePosition` is within about 30 ms of the time since `play()` three quarters of the time and half a second (one buffer) ahead the rest, and reading 8192 samples from it with `getVisBuffer` shows the samples past the end of the half-second buffer it falls in are often from half a second earlier, not the next part.
- **What it costs:** lip-sync by level read the wrong part of the voice. In the Animated Character demo under auto mode, a 3-second voice line reported positions of 469, 1097, 1460 and 1066 ms within 600 ms of play, and Pip's mouth stayed shut through most of it. Measured in the engine on synthesized lines in eight voices, the mouth was open or shut as the voice called for 68-69% of the time, against 77-81% with the right readings. kagex works around it (`readVoice` in `KAGEnvCharacterEx.tjs`): what the engine reads is at `samplePosition` plus the offset given, so it asks for the part the clock since the voice started says is playing, only within the half-second buffer `samplePosition` is in, and keeps readings of the next frames for when the engine is a buffer ahead and that part is gone: 72-73% on the same lines. Lip tracks (`<voice>.lip`) are timed by the clock alone.
- **Fix:** count the samples of the buffers released so far (or note the stream's played count where each buffer starts) and take the offset from that rather than modulo the first buffer's count, and release a buffer under the same lock the played count is read with; and have `GetVisBuffer` go on into the buffer that really follows in the voice (past the first one it can return an older part).

## 25. getVowel hears a voice's pitch more than its vowels

- **Where:** `tTJSNI_QueueSoundBuffer::GetVowel` (`common/sound/QueueSoundBufferImpl.cpp`) scores each vowel by the energy of a 1024-point FFT within ±15% + 50 Hz of fixed first and second formants (a 800/1200, i 300/2300, u 350/1200, e 500/1900, o 500/900 Hz, a man's Japanese vowels) and divides by the total. A voice's energy is at its harmonics, its pitch apart, most of it in the lowest few, so the fundamental and the second harmonic land in one vowel's bands whatever the vowel is (i's and u's, 205 to 452 Hz, for a pitch of 200 to 250 Hz; o's and u's above about 300 Hz), and the formants, between harmonics, barely count; e almost never wins.
- **What it costs:** mouths by vowel can't come from a voice as it plays: on synthesized lines in four Japanese and four English voices (women's and men's), getVowel named the vowel being said 22% and 39% of the time; a woman's voice (pitch around 200 to 250 Hz, in i's and u's first-formant bands) mostly reads as i, a higher one as o (Pip's babble, at about 440 Hz, 190 of 199 times). So kagex leaves it off (`lipEngineVowels`), and a voice's vowels come from a lip track made before (`<voice>.lip`, kagex-lipsync: 86% and 87% on the same lines), for the voices a game picks; the rest move the mouth by loudness only.
- **Fix:** estimate the formants from the spectral envelope rather than the raw spectrum (cepstral smoothing or LPC), and place them relative to the voice's own range (or scale the table with its pitch), with wider bands.

## 26. krkrlive2d and its driver don't compile outside Windows

- **Where:** krkrlive2d's `src/utils.cpp` and `src/Live2D.cpp` use `strlen` and `memset` without `<cstring>`, and `Live2D.cpp`'s `setStrProp` takes a `ttstr &` that `Live2D_common.cpp` passes temporaries to, which only MSVC accepts. The driver's `src/LAppModel.cpp` uses `va_start` without `<cstdarg>`. And a plugin built on its own (not in krkrz_dev's tree) gets the Windows declarations of `tp_stub.h` (`IStream`, `WPARAM`) unless it's configured with `KRKRZ_VARIANT=SDL`, which `krkrz.cmake` needs to define `__GENERIC__`.
- **What it costs:** GCC and Clang stop on them. kagex's build (`tools/live2d/build.py`) applies `tools/live2d/patches/` and passes `KRKRZ_VARIANT=SDL`.
- **Fix:** include `<cstring>` and `<cstdarg>`, take `const ttstr &`, and have `krkrz.cmake` define `__GENERIC__` whenever the target isn't Windows.

## 27. krkrlive2d can't read a model without a .vmotion3.json

- **Where:** the driver asks the plugin for files that may not be there and expects no stream back: `LoadVariableMotion` opens `<model>.vmotion3.json` for every model, and for a model in a folder `exists()` opens files to test them. krkrlive2d's `PReadStream::OpenFile` (`src/Live2D.cpp`) calls `TVPCreateStream`, which throws when there's no such storage (engine 2.6.5), and nothing catches it.

## 28. krkrlive2d reads a zipped model only by a bare name, named as its model3.json

- **Where:** `LInfoModel::LoadAssets` (the driver's `LAppModel.cpp`) opens the zip it's given, then looks in it for `basenamex(filename) + ".model3.json"`, where `basenamex` drops only the extension. - **Fix:** look for the model3.json by the file's name without its folder, or take the zip's only `*.model3.json`.

## 29. A parameter can't be set over a motion

- **Where:** krkrlive2d's extra values (`setDiffParameterValue`) are added to what the main motion sets, or multiply it (`setParameterType(p, 1)`), in `MyCubismModel::SaveParameters`; `setParameterValue` sets a value the motion then overwrites. There's no way to make a parameter a given value whatever the motion does (as a Cubism expression's `Overwrite` blend does).
- **What it costs:** a model whose idle motions blink, smile and talk (Hiyori's) can't hold a face the script gives it, nor keep its mouth shut while it isn't speaking. `KAGEnvCharacterLive2D.tjs` keeps a copy of the model (`Live2DModel.clone`) playing the same motions, moved on first each frame, and adds the face's value less what the motion sets in that frame, which updates every Live2D character's model twice a frame.
- **Fix:** a parameter type that overwrites (`setParameterType(p, 2)`: `SaveParameters` sets the extra value as the parameter's).

## 30. A .bmp the Linux engine saves says its pixels start 2 bytes late

- **Where:** `TVPSaveAsBMP` (`common/visual/GraphicsLoaderIntf.cpp`) writes `bfSize` and `bfOffBits` from `sizeof(TVP_WIN_BITMAPFILEHEADER)`, which is 16 where the struct isn't packed (`GraphicsLoaderIntf.h` packs it only under `_WIN32`), not the file header's 14 bytes, and then writes the pixels right after the 54 bytes of headers.
- **What it costs:** `Layer.saveLayerImage(file, "bmp")` writes files whose header points 2 bytes into the pixels: other programs read them with the colour channels shifted (ffmpeg and Pillow see a truncated file), and so would the engine's own loader, which seeks to `bfOffBits`. kagex saves screenshots as PNG; recording frames as .bmp means reading the pixels from the end of the file.
- **Fix:** use 14 (or pack the struct) for the file header's size.

## 32. A plugin's own subfolders go into the iOS Xcode project twice

## 33. Android's loading screen can copy the game files twice at once

- **Where:** krkrz_android's `BootstrapActivity.onCreate` (at `eff2b17`) calls `setRequestedOrientation` and then starts a `BootstrapCopy` thread that rebuilds `<filesDir>/assets/` (`ensureAssetsCached`: delete it, list the APK's assets with `AssetManager.list`, copy them). ## 34. threepp's lit materials share one set of light values

- **Where:** threepp's `GLPrograms::getUniforms` (`renderers/gl/GLPrograms.cpp`) hands every built-in material (`MeshStandardMaterial`, `MeshPhongMaterial`, `MeshLambertMaterial` ..., and the materials `GLTFLoader` makes) the uniform map of its shader in `ShaderLib`, one map per shader for the whole process, where three.js gives each material a copy (`UniformsUtils.clone`). `GLRenderer` writes a scene's light state into that map (`directionalLights`, `hemisphereLights`, `directionalShadowMatrix` ...) only when a material's program is made or its light state changes, and uploads from it on every draw.
- **What it costs:** two scenes with lit materials and different lights, drawn by different renderers (two 3D layers on the screen at once), upload each other's light values. When the counts differ the engine crashes (a shadow-casting light in one: `PureArrayUniform` reads a `directionalShadowMatrix` array of the size its program has from a vector the other scene left empty, SIGSEGV) or throws `unordered_map::at` from `StructuredUniform::setValue` (a light array shorter than the program's), which stops the other 3D layer; freeing one 3D layer while another is drawn did the latter too. - **Fix:** clone the `ShaderLib` uniforms per material in `getUniforms` (and keep the clone in the material's properties), as three.js does.

## 35. krkrthreepp's MSAA draws nothing into the engine's offscreen buffer

## 39. shrinkCopy reads a row past the bottom of the picture it shrinks

- **Where:** krkrz_dev's `src/plugins/shrinkCopy` (wamsoft/shrinkCopy at 007fbba), `ShrinkCopy::copy`: each output pixel adds its block, the rows above and below it and the columns beside it, each weighed by `makeAvgTable`'s fractions (`ta`/`tc`, `ba`/`bc`), and reads the row below (`addHorz(sum, r + oy, ...)`) whenever its weight isn't 0. ## 42. extNagano's book, multiripple, rgbfade, zoomfade, spin and 3duniversal don't do what they say

- **Where:** krkrz_dev's `src/plugins/extNagano` (wamsoft/extNagano at 4b403e2, rebuilt from the 2006 DLL). `book.cpp`: the page's progress `Phase` runs to `Width / 2` with a quadratic ease, and the fold sits at `Width - 1.5 * Phase`, so it ends at a quarter of the width, three quarters of the way across; `MakeFinalImage` then shows the new picture. `multiripple.cpp`: each ripple adds `765 / count` to a pixel's `blend`, and `Process` takes `blend & 0xff` as the mix and bit `0x100` to swap the two pictures, so a pixel two or three ripples have passed shows the old picture again. `rgbfade.cpp`: each colour's fade lasts `(255 - the largest delay) / 255` of the time (`EffDuration`), so with delays 0, 96 and 192 red is done at a quarter of the time and green at 62%, though its own comment says they all end together; and a pixel of alpha 0 takes another branch, so a scene composited for a transition (alpha meaningless) came out in solid colours. `zoomfade.cpp`: it samples the nearest pixel (jagged steps as the picture grows), and its default `zoom1` of 100 leaves a picture that goes unzoomed. `spin.cpp`: the turning's formulas were lost in the decompile and rebuilt (its own comment says with low confidence); the new picture shows as a flat panel growing from the middle, with a gap of the old picture in it, and the old one doesn't turn. `3duniversal.cpp`: with every speed and acceleration 0 (its defaults) the pieces stay put and the opacity tables (`OpaTableA`/`OpaTableB`) run the wrong way, so the new picture fades out over the old one and comes back at the end.

The sample's transitions demo leaves book, multiripple, rgbfade, zoomfade and spin out, and its 3duniversal gives the old picture a speed (`accel1=0.4`), where the pieces fly and the opacity doesn't show; a game that uses the five gets them as the plugin draws them. (From 0.18.0 to 0.26.1 kagex drew those five itself, in scripts, under the plugin's names; that was taken out in 0.27.0.)
- **Fix:** book: run `Phase` to `Width * 2 / 3` (the fold at `Width - 1.5 * Phase` reaches 0) or move the fold to `Width - 2 * Phase`; multiripple: clamp `blend` to 255 instead of wrapping into bit `0x100`; rgbfade: give each colour `Time - its delay` (start at its delay, end at the end); zoomfade: sample bilinearly; spin: project each face of the turning box (or door) in perspective, as kagex's `KAGSpinTransition` does; 3duniversal: swap the opacity tables (or index them by `255 - phase`) when a picture doesn't move.

## 43. A stretched blit with stNearest or stFastLinear silently skips most blend modes

- **Where:** `tTVPBaseBitmap::StretchBlt` (`common/visual/LayerBitmapIntf.cpp`) passes `stNearest` and `stFastLinear` to `AffineBlt`, whose switch (`InternalAffineBlt`) has only the copy, alpha and additive-alpha methods; for any other (`bmAdd`, `bmSub`, `bmMul`, `bmDarken`, `bmLighten`, `bmScreen`, the Photoshop modes) it draws nothing and throws nothing. `stLinear` and `stCubic` go through `TVPResampleImage`, which does them. - **What it costs:** `operateStretch(..., omAdditive, ...)` with the default `stNearest` or with `stFastLinear` leaves the layer as it was, with no error: a script that stretches with another mode has to ask for `stLinear` (found while kagex drew its own wave rings, up to 0.26.1).
- **Fix:** add the remaining methods to `InternalAffineBlt` (its line functions can take any `TVP_BLEND_4` routine), or send `StretchBlt` to `TVPResampleImage` for them, and keep the alpha byte in the `_o` blends as the plain ones do.

## 44. Music with labels can deadlock the sound threads

- **Where:** `tTJSNI_QueueSoundBuffer::PushPlaySample` (`common/sound/QueueSoundBufferImpl.cpp`) holds the buffer's `BufferCS` and, when the samples it pushes carry labels (a `.sli`'s `Label` lines), calls `TVPSoundBuffers.ReschedulePendingLabelEvent`, which takes the buffer list's critical section (`SoundEventThread.cpp`). The event thread (`tTVPSoundEventThread::Execute`) takes the list's critical section first and then calls each buffer's `Update()`, which takes its `BufferCS`. - **What it costs:** the game freezes with no error, now and then, whenever music with labels plays: with 0.18.0's first `bgm01.ogg.sli`, which had two labels for the credits roll, the sample hung in about one run of the smoke test in three (a restore that restarted the music), here and on the Android emulator; a loop of the same step hung on its 27th round, and gdb showed the three threads above. Labels are also what `[wl]` and `onLabel` wait for. kagex's credits roll takes times instead (`rollfrom=6000`), and the sample's music has no labels.
- **Fix:** in `PushPlaySample`, collect the next event step under `BufferCS` and call `ReschedulePendingLabelEvent` after releasing it (or take the list's critical section first, as the event thread does).

## 45. Android plays movies without their sound

- **Where:** krkrz-core's Android movie player (`external/movie-player`, wamsoft/movie-player at `b01a5f6`, `src/android/AudioTrackPlayer.cpp`) and the generic `tTVPMoviePlayer::Play` (`generic/app/movie.cpp`). `Play()` on a movie just opened (`STATE_PRELOADING`, no frame delivered yet) calls `Seek(0)`, whose `MSG_SEEK` runs `AMediaCodec_flush` on the audio decoder right after `AMediaCodec_start`, before its first output buffer or format change. Android's `MediaCodec` documents that a codec flushed that early needs its codec-specific data again, and the player doesn't queue it: an Opus decoder (WebM's `csd-0`, `csd-1`, `csd-2`) then has no header. Separately, `EnsureSinkSetup` reads `AMEDIAFORMAT_KEY_PCM_ENCODING` into `mEncoding`, which `Init()` never sets, so a format without the key leaves it as whatever was in memory (`enc=1296387378` in 0.20.0's emulator log; the switch's default happens to take it as 16-bit).
- **What it costs:** on an Android phone the sample's opening (VP9 and Opus) played silently, reported by the user in 0.20.0; the emulator's software decoder (Codec2's `c2.android.opus.decoder`, which keeps its configuration across a flush) played it. Every movie a game plays on Android may be silent, depending on the phone's decoder. Since 0.21.0 kagex plays a movie's sound from a file of its own on Android where the game has one (`<name>.opus`/`.ogg` beside the movie, `KAGMovieSoundFile` in `Movies.tjs`; the sample's `opening.opus` comes from `make_opening.py`), with the movie muted; a movie without such a file still depends on the decoder.
- **Fix:** don't flush a decoder that hasn't produced output yet (skip `Seek(0)` in `Play()` while nothing has been decoded, or skip the audio track's flush), or queue the format's `csd-*` buffers again after a flush; and set `mEncoding` to `kAudioEncodingPcm16bit` in `Init()`.

## 46. Android's Back reaches the engine as a key it has no name for

The same object's next movie then drops every frame as not yet taken, and `Update`, finding no bitmap, never clears the flag, so `prepare()` never sends `perPrepare` and `play()` shows nothing.
- **What it costs:** a commercial game moved to KAGEX's engines hung at its ending: it skipped a movie and prepared the next one in the same slot (`[preparevideo]`, `[wp for=prepare]`). Since 0.21.0 the framework gives a slot that played and stopped a new `Movie` with the old one's settings before it opens or plays the next movie (`KAGWindow.renewMovie`); a game that keeps its own `VideoOverlay` objects still meets it.
- **Fix, tested:** clear `updateSurface`, `currentSurface` and `surfaceFrame` in `Close()`, under `surfaceLock`. A ten-line `startup.tjs` (one object: open, prepare, play+stop+close, open, prepare, play) gets one prepare event from an engine built at krkrz_dev `21d20e9` and two, with the movie playing, from the same build with the change.

## 48. Android and iOS draw every game on a 1920x1080 surface

- **Where:** `SDL3WindowForm`'s constructor (`sdl3/environ/form.cpp`): on Android, iOS and the consoles the window is full screen and the drawing surface is fixed at the size it asks for, 1920x1080 (`mFixedSurfaceWidth`/`Height`), scaled to the screen. Nothing reads the game's own size, and the window's inner size stays 1920x1080 whatever the game sets.
- **What it costs:** a game made at another size (1280x720, or a 4:3 1920x1440 primary layer) is drawn shrunk or in part on phones: a commercial game moved to KAGEX's engines drew at three quarters, at the top of the phone. kagex's framework only warns at start (`Initialize.tjs`), and `doc/kagex.txt` ("Games on Phones and in the Browser") says to make phone builds at 1920x1080.
- **Fix:** take the surface's size from an option (`-surfacewidth`/`-surfaceheight` in `config.cf`, which kagex-release writes from the game's `scWidth`/`scHeight`), or from the primary layer's size when the game makes it.

## 49. Asking an empty sound buffer for its times kills the engine

- **Where:** `WaveSoundBuffer.totalTime` and `position` (and so `samplePosition`'s conversions) on a buffer with nothing open (`status` "unload"): the time in ms comes from a sample count divided by the format's sample rate, which is 0 until a file is opened, and the integer division raises SIGFPE (exit code -8 here, no message, no log line).
- **What it costs:** any script that shows a buffer's time without checking its status first: 0.24.0's music room panel (`KAGNowPlaying`, `MusicPlayer.tjs`) took the engine down the moment it opened, since KAG's BGM object keeps an unloaded second buffer. The framework reads the times only while a buffer plays or is paused.
- **Fix:** return 0 for both while no file is open (the sample rate is 0).

## 50. The sigcheck plugin looks members up on the window from its own thread

- **Where:** `src/plugins/sigcheck/main.cpp`: `WindowSigCheck::postMessage`, called from the checking thread for every per cent of every file (`SigChecker::progress`) and at the end (`SigChecker::start`), reads `objthis->PropGet(0, TJS_W("HWND"), ...)` on the window the check was started on. A TJS member lookup changes the object: `tTJSCustomObject::Find` moves a member it finds deep in a hash chain to the chain's head, and `PropGet` rebuilds the whole table first when a rehash is pending (`RebuildHashMagic`). The checking thread also calls `TVPCreateStream` and `TVPGetPlacedPath`.
- **What it costs:** with the check on the game window, whose members the game looks up all the time (timers, events), members of the window went missing: 0.26.0's first tool-check lost `fore` and `conductor` a second into a signed build, and the error handler's dialog then held the test run until it timed out. A test here that looked the window's methods up every millisecond during 300 checks lost 85 of them at once, or hung the engine (a chain turned into a loop). Since 0.26.1 `SignatureCheck.tjs` runs the checks on a dictionary of four members that nothing else touches (`KAGSignatureChecker`: `HWND` and `registerMessageReceiver` copied from the window, the handlers bound to the global object), which the same test ran 300 checks against without a loss; any other script that calls `checkSignature` on a window has the race.
- **Fix:** read `HWND` once on the main thread (in `checkSignature`) and keep the handle in the `SigChecker`, so the thread touches no TJS object; ideally open the streams there too, or hand the thread only a native path.

## 51. The SDL engine shows only the system's arrow

- **Where:** a layer's `cursor` and the window's cursors do nothing on the SDL engine: `TVPGetCursor` returns 0, "not supported yet" (krkrz_dev `generic/visual/WindowImpl.cpp`), and `TTVPWindowForm::SetMouseCursor` is empty (`generic/environ/WindowForm.h`), so neither a `cr*` constant nor a `.cur` file reaches SDL. Only showing and hiding work (`SetCursorVisible`: `SDL_ShowCursor`/`SDL_HideCursor`).
- **What it costs:** the pointer is the system's arrow everywhere, even the hand over buttons that KAG asks for (`cursorPointed = crHandPoint`) and the I-beam over a text field, and a game's own cursor files (`[cursor default=...]`) never show. Since 0.27.0 the framework draws a game's own pointers on a layer that follows the mouse, with the system's hidden over the game (`GameCursor.tjs`, `cursors.csv`); a game without a table still gets the arrow everywhere.
- **Fix:** map the `cr*` constants to `SDL_CreateSystemCursor` (`SDL_SYSTEM_CURSOR_POINTER` for `crHandPoint`, `SDL_SYSTEM_CURSOR_TEXT` for `crIBeam`, and so on) and set the cursor of the layer under the mouse with `SDL_SetCursor`; load `.cur` files, and pictures, with `SDL_CreateColorCursor`.

## 52. Scripts can't change the options the engine reads at start, nor start the game again

- **Where:** the engine reads a player's options from `<exe>.cfu` in the save folder (desktops; `generic/base/SysInitImpl.cpp`) through `TVPReadLines` (`common/base/StorageIntf.cpp`), which takes the file's bytes as one C string, while a script can only write text as UTF-16 with a BOM (`tTVPTextWriteStream`), so a `.cfu` a script wrote reads as nothing after its first byte. The `-userconf` screen writes the file, but only when the game is started with that option, and nothing starts the game again: the SDL engine binds no `System.shellExecute` (`app.cpp` has the code), and there's no restart call.
- **What it costs:** the Advanced settings (`Advanced.tjs`, 0.27.0) change only what the engine lets a running game change (`System.graphicCacheLimit`, `System.drawThreadNum`, `System.padEnabled`); the options it reads once as it starts (`-memusage`, `-renderer`, `-joypad`, `-gclim`, `-wsfreq` and the rest of optiondesc's `user` options) need the player to start the game with `-userconf`, which phones and the browser don't have, and no setting can say "restart now" and come back to the same place.
- **Fix:** let scripts write the user options (a `System.setUserOption(name, value)` that writes `.cfu` in the `-userconf` screen's format, or a `TVPReadLines` that reads a UTF-16 file with a BOM), on every platform with a writable save folder, and a `System.restart()` that starts the game again (desktops: the executable with its arguments; elsewhere the platform's own way).

## 53. On Android a plugin opened at run time frees into the wrong allocator

- **Where:** `libkrkrz.so` defines and exports its own `operator new` and `operator delete`, and `libc++_shared.so`, loaded with it, binds to them for what it allocates (a `std::string`'s buffer); a plugin opened later with `dlopen` resolves its own `delete` to the C++ library's plain one, so memory the C++ library allocated with the engine's `new` comes back to the system's `free`.
- **What it costs:** the first `std::string` such a plugin frees stops the game ("Scudo ERROR: corrupted chunk header", `SIGABRT`). Since 0.27.0 kagex-release puts a game's own Android plugins in the APK (`plugins/android/<ABI>/`), where the engine opens them at run time, so each has to take the engine's `new` and `delete` itself (`tools/release/README.md`, "Your own plugins"); plugins linked into the engine aren't touched.
- **Fix:** don't export the replaced `new` and `delete` on Android (or don't replace them there), or have the plugin loader hand them to every plugin it opens.
