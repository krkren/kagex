# kagex

An English translation of KAGEX, Wamsoft's extension of the Kirikiri KAG3 visual novel framework (affine layers, layer ordering, automatic actions and the "World" environment system), ported to the SDL3 version of [Kirikiri Z](https://github.com/wamsoft/krkrz_dev) and updated to 1920x1080.

## Branches

- **`main`**: the SDL3 version. It's more modern and in active development, supports multiple platforms (Windows, Linux, macOS, Android, iOS and the web) and modern codecs, but has a less mature ecosystem.
- **`legacy`**: the Windows-only version. It has more resources, but supports Windows only and doesn't support modern codecs. For reference, the best video codec it supports out of the box is WMV3, which came out in 2003.

## Running the sample

In a browser: **[krkren.github.io/kagex](https://krkren.github.io/kagex/)** runs the newest release.

Or download a package from [Releases](https://github.com/krkren/kagex/releases):

- **Windows** (`kagex_sdl3_windows_*.zip`): unzip and run `krkrz.exe`. The engine needs OpenGL ES: a graphics driver that supports it, or ANGLE's `libEGL.dll` and `libGLESv2.dll` next to `krkrz.exe`.
- **Linux** (`kagex_sdl3_linux_*.zip`): unzip and run `./krkrz`. Saves go to `~/.local/share/krkren/kagex/` (set by `krkrz.cf` next to the engine) unless you pass `-datapath=savedata/`. Up to 0.0.4 they went to `~/.local/share/wamsoft/krkrz/`; move them over to keep them.
- **Linux, Steam-ready** (`kagex_sdl3_linux_steam.tar.gz`): the same game built in Valve's Steam Linux Runtime 3.0 (sniper), so it runs on older distributions too and can be shipped on Steam as it is. Extract it and run `krkrz/krkrz`; it comes with a desktop entry (`io.github.krkren.kagex.desktop`) and icon.
- **macOS** (`kagex_sdl3_macos.zip`, Apple silicon): unzip and open `KAGEX.app`. It's signed ad hoc, without an Apple Developer ID, so macOS blocks it the first time: open it from the context menu (Open), or allow it under System Settings > Privacy & Security, or run `xattr -dr com.apple.quarantine KAGEX.app`. Saves go to `~/Library/Application Support/krkren/kagex/`.
- **Android** (`kagex_sdl3_android.apk`, Android 10 or later, arm64 and x86_64): install it on the device, allowing installs from unknown sources, or with `adb install kagex_sdl3_android.apk`. It's a release build signed with a debug key rather than a Play Store key, so a build of the app signed with another key can't update it in place: uninstall it first.
- **iOS Simulator** (`kagex_sdl3_ios_simulator.zip`): a debug build for Xcode's iOS Simulator on a Mac with Apple silicon. Unzip it and run `xcrun simctl install booted krkrz.app` with a Simulator running; it shows up as KAGEX. A build for iPhones and iPads needs an Apple Developer account to sign it, which this project doesn't have.
- **Web** (`kagex_sdl3_web.zip`): the site above. Run `python3 serve.py` in it and open `http://localhost:8100/` to play it locally. It also runs from any static web host, such as GitHub Pages; for 0.2.0's zip, run `.github/platforms/web-static-host.py` on the folder first. On a phone: Android browsers switch to full screen from Config (Screen Mode > Full Screen, then tap once more); iPhone browsers can't, so add the site to the Home Screen (Share > Add to Home Screen) and open it from there, which shows the game without Safari's bars. Android's Add to Home screen opens it full screen too.

On the desktop the game starts full screen the first time; after that it remembers whether you left it in a window (F5 switches). The `_release` and `_debug` zips hold the same game files with a release or a debug build of the engine. The game font (Noto Sans JP) comes with it, so no fonts need installing. The web and iOS builds draw text with the engine's own renderer instead of krkr_richtext, which doesn't build for them yet, so lines aren't kerned there.

The demo menu's Effekseer Effects plays [Effekseer](https://effekseer.github.io/) particle effects (petals, sparkles, fireworks, a magic circle, a shockwave) with the krkreffekseer plugin and OpenGL ES, on Windows, Linux, macOS, Android and the web. The iOS build doesn't have the plugin yet, so the demo says so there. A game plays them on World or KAG layers (`efk` in `doc/world.txt` and `doc/kagex.txt`).

The World Extension: Transition demo ends with the twelve transitions of the extNagano plugin: book, flutter, blurfade, zoomfade, scanline, rgbfade, spin, multiripple, imagewipe, 3duniversal (shards flying from the centre), honeyturn and morphing (a swirl). A game uses them like extrans's, with `[trans method=...]` or the World's `trans=` (`doc/kagex.txt`, "trans (Extension)"); a transition whose plugin is missing runs as a crossfade.

The KAGEX Extended Layer demo ends with an SVG vector image beside a PNG of the same picture, both zoomed and turned: the layerExVector plugin draws the SVG again at each size and angle, so it stays sharp while the PNG blurs. A game shows `.svg` images like any other, on KAG or World layers (`doc/kagex.txt`, "image (Extension)"); SVG text isn't drawn, so convert it to outlines. Then it shows the emblem as two layers of a CLIP STUDIO PAINT file, each loaded with `clip://emblem.clip/root/badge.bmp` and the like (the clipfile plugin) and turned on its own: a game can keep its art in `.clip` files (or `.psd` files, with `psd://`) without exporting each layer. kagex-release splits such files into a picture per layer when it builds a release, so the layers load on every platform, plugin or not.

The World Extension: Animated Character demo shows Pip, a character put together from layers each time it's shown: two outfits, three arm poses and six faces. Its eyes blink by themselves, and its mouth moves with its voice, opening as wide as the voice is loud as it plays (the engine's `WaveSoundBuffer.getSoundLevel`, on every platform). One line, in a synthesized voice, also shows a mouth for each vowel it says, from the lip track `tools/lipsync`'s kagex-lipsync made for it from the voice and its line: a game picks the voices that get one. A game lists such characters in `charinit.csv`, each pose's layers in psdlayer.tjs's text format with a picture per layer, or as the PSD or CLIP STUDIO PAINT file they're drawn in (which kagex-release splits into that format for a release), and its outfits and faces in an `_info.txt` (`doc/world.txt`, "Characters Drawn from Layers").

The demo then shows a Live2D character: Hiyori, Live2D Inc.'s sample model (the one Neuro-sama first streamed as), with her idle motions, faces that fade into each other, a motion played once, blinking and lip-sync, through the krkrlive2d plugin (`doc/world.txt`, "Live2D Characters"). The plugin needs Live2D's Cubism SDK, whose licence keeps it out of kagex's own builds, and Live2D's licence for its sample models lets no one but Live2D hand out their files, so the packages here say so in her place: a game builds the plugin with its own copy of the SDK (`tools/live2d/build.py --sdk <the SDK's zip>`), and `tools/assets/make_hiyori.py` fetches Hiyori for a local build. This content uses sample data owned and copyrighted by Live2D Inc. The sample data are utilized in accordance with terms and conditions set by Live2D Inc. This content itself is created at the author's sole discretion.

The sample is in English and Japanese. It starts in your system's language (Japanese on a Japanese system, English otherwise), and F9, the controller's L2 or Config's Language row switches between them while you play: the line on screen, the choices and the screen you're on are drawn again in the other language, and the message history keeps each line as it was shown. As in Wamsoft's multi-language games, the other languages are built into the compiled scenarios: each script's translation (`data/lang/<code>/scenario/`) is compiled into its `.scn` file with it, and the game shows the language you chose. A game lists its languages in `Config.tjs` and puts each one's translated scripts, interface strings and images in `data/lang/<code>/` (`doc/kagex.txt`, "Languages").

With a controller: the D-pad or left stick moves between buttons, A confirms and advances, B cancels or hides the message window, X shows the message history, Y switches auto mode, R1 skips to the next choice or unread text and holding R2 skips. START opens the config screen, BACK the save screen, L1 the load screen, L2 switches the language and R3 (pressing the right stick) opens the menu bar's first menu in a window.

In a window the game has a menu bar above it, as Kirikiri games had on Windows (the SDL engine has no menu bar of its own, so the framework draws one; full screen has none): the system commands, the display settings, the message commands and Help, which has the controls list, a screen of what every key, mouse button and controller button does (Config has a button for it too), read from the game's own key bindings and named for the controller in use. F12 saves a screenshot as a PNG in the save folder, written in the background so the game doesn't stop. On Windows, macOS and Linux a screen reader (Narrator, VoiceOver, Orca) reads each line out with its speaker's name and can read and press the choices, the prompts, the menu bar and the controls list. English lines break between words where krkr_richtext's line breaker puts the breaks for the whole line, which evens out ragged lines (`lineBreakStrategy` in `Config.tjs`); Japanese lines break by its rules for Japanese (no closing bracket or small kana at the start of a line, no Latin word split), and each line's characters are shaped and drawn together (kerning, ligatures, accents and emoji made of several characters). The World Extension: Character demo plays positional sound: a chime at the far left and the far right of the stage, and footsteps that follow Ai as she walks (`doc/world.txt`, "SE Object Functions").

## Releasing a game

`tools/kagex-release` packages a game for Windows, Linux, Linux for Steam, macOS, the web, Android and iOS. It's in the Windows and Linux packages (`tools/kagex-release.exe`, `tools/kagex-release`), and each system's tool is also a download of its own (`kagex-release-windows.zip`, `-linux.tar.gz`, `-macos.zip`). Run it next to (or in `tools/` below) the folder with your game's `data/`: it opens a window with the settings, saves them to `release.json`, shows what this computer can build, and builds each platform's package into `release/`. It can convert the game's WAV and FLAC sounds to Opus or Ogg Vorbis and its PNG, BMP and TLG images to TLG6, TLG5, PNG or JPEG on the way (lossy files are never converted again), and it compiles the TJS scripts to bytecode, so a package carries no readable source (errors in compiled scripts then show no line numbers). `kagex-release --cli build` does the same without the window, for CI.

Windows, Linux, Steam and the web build on any of the three systems; macOS and iOS need a Mac (iOS also Xcode, and your certificate and provisioning profile for devices); Android needs a JDK 17 and the Android SDK, no NDK. The engines come from the KAGEX release of the tool's version and are downloaded once. [`tools/release/README.md`](tools/release/README.md) describes every setting and what each package holds.

The macOS tool isn't notarized: after unzipping, run `xattr -d com.apple.quarantine kagex-release` (or allow it under System Settings > Privacy & Security).

`kagex-lipsync`, built with kagex-release and kept beside it with its `lipsync/` folder, makes the vowel data for the voices you pick, so characters drawn from layers shape their mouths to the vowels those voices say. It reads each voice's line from your scripts (through the game's own scenario compiler) and lines its sounds up with the voice (PocketSphinx, and OpenJTalk for Japanese, kanji included), writing a `.lip` file beside the voice that the game reads while you develop and in a release. Every other voice moves the mouth by its loudness, with nothing to prepare. [`tools/lipsync/README.md`](tools/lipsync/README.md) has the details and how well it does.

## Patches and DLC

At start the framework loads `patch.zip`, `patch2.zip` and so on, from next to the engine and then from the save folder, after the `patch.xp3`, `patch2.xp3`... archives it already read from next to the engine. A later one wins over the earlier ones and over the game's own files. Every folder in a zip is searched, so its files can be loose or in `data/`'s folders (`scenario/`, `bgimage/`...). On the web, Android and iOS the save folder is the only place new files can go. A game mounts DLC, or anything it downloads, with `KAGMountPatchZip(storage)` at any time (`template/system/Initialize.tjs`). Only what's read before the patches can't be patched: `Initialize.tjs` and `Storages.tjs`. It needs the minizip plugin, which every build has. kagex-release makes the zip: give it an earlier build's file list (Output > *Patch from*) and it writes `patch.zip` with the files that changed since ([`tools/release/README.md`](tools/release/README.md)).

## Layout

- `data/`: the sample game. It loads the framework from `../template/system`, or from `data/system` where a package puts a copy there.
- `template/`: the KAGEX framework (`template/system`) and empty folders for a new game, with `template/main/` holding empty versions of the game-side hooks (`Override.tjs`, `AfterInit.tjs`, `Storages.tjs`). To ship a game, copy `template/system` and `template/startup.tjs` into `data/`, and `krkrz.cf` next to the engine with your own `orgname`/`appname`: without it, every game on the stock engine saves to the same `~/.local/share/wamsoft/krkrz/` folder on Linux.
- `linux-config.json`, `web-config.json`, `app-config.json`, `ios-config.json`: the settings for Wamsoft's platform kits ([krkrz_linux](https://github.com/wamsoft/krkrz_linux), [krkrz_web](https://github.com/wamsoft/krkrz_web), [krkrz_android](https://github.com/wamsoft/krkrz_android), [krkrz_ios](https://github.com/wamsoft/krkrz_ios)), which build the Linux (Steam), web, Android and iOS packages from krkrz_dev without changing it. `.github/workflows/platforms.yml` shows the steps, and `platform/` holds the icons and the Android app name.
- `data/lang/ja/`: the sample in Japanese: `scenario/` (the demos' scripts with their text in Japanese, which the compiler builds into each script's `.scn`), `lang.json` (the interface strings the screens draw, keyed by the English) and the screens' images with Japanese words on them, which take the place of `data/image`'s while the game is in Japanese.
- `doc/`: the KAGEX reference: `kagex.txt` (new and changed tags, and languages), `action.txt` (actions), `world*.txt` (the World extension), `scn.txt` (compiled scenarios).
- `TODO.md`: planned features.
- `tools/assets/`: the scripts that make the sample's images and effects (`make_ui.py` for the screens (in each language, with `subset_fonts.py` for the Japanese labels' fonts), `upscale.py` for the characters and backgrounds, `make_effects.py` for the Effekseer effects in `data/effect`, written with `efkformat.py`, `make_rules.py` for the transitions' rule images in `data/rule`, `make_vector.py` for the layer demo's SVG emblem and its PNG twin, `make_clip.py` for the same emblem as a CLIP STUDIO PAINT file, `make_pip.py` for the Animated Character demo's Pip, its layers and voice lines, `make_hiyori.py` to fetch its Live2D character, Hiyori, and make her voice line, `make_sounds.py` for the Character demo's positional sound effects, `psdwrite.py` to write a layer structure as a PSD), with the original art they start from.
- `tools/release/`: kagex-release (above): its source, `scripts/` that make the engine packages it uses from the release builds, and its smoke test. `.github/workflows/release-tool.yml` builds it for all three systems.
- `tools/lipsync/`: kagex-lipsync (above), built with kagex-release, and its test.
- `tools/live2d/`: `build.py`, which builds the krkrlive2d plugin for Live2D characters with your own copy of Live2D's Cubism SDK (README there).
- `tools/smoketest.py`: a headless smoke test. With the engine next to `data/`, `python3 tools/smoketest.py` plays through the sample and starts the template, and fails on a script error. GitHub Actions runs it on pull requests with the engine from the newest release. `--target android|ios-sim|web` runs the sample's part in the platform builds: on an emulator, the iOS Simulator or headless Chromium.

The engine isn't part of this repository. It's built from [wamsoft/krkrz_dev](https://github.com/wamsoft/krkrz_dev); `CLAUDE.md` has the build steps and the outputs to copy next to `data/`.

## Not available on the SDL3 build

These KAGEX features depend on Windows plugins the SDL3 engine doesn't include. The scripts load without them; using one either falls back to something simpler or stops with an error:

- The native menu bar (`menu.dll`, `windowEx.dll`). The framework draws the same menu as a menu bar above the game in a window (F10 opens it from the keyboard), and the sample puts its player commands on keys (F1-F8), buttons and the controller too; in KAG's debug mode (on unless the engine gets `-debugwin=no`), Shift+F12 shows the debug window and Shift+F11 switches the debug level.
- The fire and Flash effects (`gfxEffect.dll`, `flashPlayer.dll`). Effekseer effects (`efk`) can take the fire effect's place.
- GDI+ outlined text (`layerExDraw.dll`); krkr_richtext draws outlines and shadows instead.
- Native Windows dialogs (`win32dialog.dll`), used by the stand-picture viewer tool.
- `.emf`/`.wmf` vector images (`layerExDraw.dll`). SVG images take their place (layerExVector, which every build has).
- Live2D characters (`krkrlive2d`), which a game builds with Live2D's Cubism SDK for itself (`tools/live2d/build.py`; Linux tested, macOS and Windows not yet, Android, iOS and the web not built): the packages don't have the plugin, and a Live2D character draws nothing without it (`doc/world.txt`, "Live2D Characters").
